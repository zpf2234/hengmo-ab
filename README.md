# 衡模·AB

面向全国大学生数学建模竞赛 A/B 题的建模、求解、验证、可视化与论文审查工作流。

衡模取“衡量模型，也衡量证据”之意。这个项目不追求把一道赛题包装成一次黑箱式生成，而是把选题、建模、计算、验证、图表、成文和复核拆成可以检查、可以回退、也可以由参赛者亲自判断的过程。

目前稳定范围聚焦 **CUMCM A/B 题**：A 题侧重机理、几何、物理过程与高精度数值闭合；B 题侧重统计推断、评价决策、组合优化、生产过程与不确定性分析。C/D/E 题尚未完成同等强度的回归验证，因此不会在这里泛化承诺。

## 我为什么做这个项目

我一直觉得，数学建模比赛真正难的地方，不是知道多少算法，也不是在三天里写出多少页，而是能不能持续回答下面几个问题：

- 这个模型为什么适合当前问题，而不只是“看起来高级”？
- 结果是否满足题意、量纲、边界和现实约束？
- 换一种离散方式、参数范围或基线方法，结论还能不能站得住？
- 图表、公式和文字是否共同证明了同一个结论？
- 评委能否在有限时间内看懂我们做了什么、得到什么，以及为什么可信？

我见过不少建模工具把重点放在“从题目直接得到一篇论文”，但比赛中的很多失分并不来自少写了一个模型，而是来自题意没有闭环、候选模型没有比较、数值结果缺少验证、图表与结论脱节，或者全文结构直到最后才临时拼起来。

所以我更希望做一套稳一点的工作流：该由程序完成的计算和检查尽量自动化，该由参赛者判断的路线、结果和篇幅则明确停下来确认。它不替人做决定，而是尽量让每一个重要决定都有依据。

## 与常见建模 Skills 有什么不同

### 1. 默认半自动，而不是一路生成到底

完整流程设置了两次人工确认：

1. 先完成候选模型比较、正式求解、关键结果、独立验证和风险说明；参赛者确认方法与结果后，才进入论文阶段。
2. 再输出全文目录、大纲和篇幅规划；参赛者确认结构与各问轻重后，才开始生成和编译总稿。

如果结果或方法发生实质变化，流程会退回对应确认点，而不是用后面的文字掩盖前面的不确定性。

### 2. 会先做目录与篇幅规划

项目不是套用固定十章模板，而是根据各问之间的共享关系、推导难度、验证责任和图表需求选择论文结构。进入初稿前会给出：

- 全文目录与章节职责；
- 每一问需要回答的核心结论；
- 共享章节与逐问章节的大致页数区间；
- 图、表、公式和验证证据的预定落点；
- 按官方口径计算的正文页数预算。

篇幅规划用于控制轻重，不是为了把正文机械填满。最终只检查是否超过当年官方上限，内容不足必须补证据，页数较短不会自动灌水。

### 3. A/B 题分别建模，不用一套算法目录硬套

A 题优先检查守恒关系、受力、几何约束、连续过程、临界状态、数值离散和误差闭合；B 题优先检查数据口径、抽样与估计、预测泄漏、评价指标、决策变量、可行域、策略稳健性和不确定性传播。

项目维护了面向 A/B 题的模型与算法路由，但不会因为题号或算法“更先进”就自动选用复杂方法。透明基线能够完整解决问题时，就保留透明基线；只有它在明确指标上失败，才升级模型。

### 4. 先比较模型，再确定正文主解

关键问题会同时保留透明基线、主候选和异构挑战路线，先通过题意、量纲、物理、约束、可识别性与可复现性做硬淘汰，再比较：

- 独立验证结果；
- 收敛性或误差界；
- 稳健性与敏感性；
- 最优性或可行性证据；
- 计算代价与比赛时间风险。

模型竞技过程保留在内部证据中，论文只呈现最终采用的路线和真正影响选择的理由，避免把试错记录写成流水账。

### 5. 论文中的每个关键结论都要能追溯

项目要求建立“题目要求—结论—指标—图表—生成脚本—验证方式”的证据链。论文中的数值、图表和结论必须来自已经落盘的求解结果，审查阶段不能临时发明新结果。

这使得结果修改后能够定位受影响的图、表和段落，也能减少摘要、正文、附件之间口径不一致的问题。

### 6. 图表按论证职责生成，而不是按数量配图

数据图、几何机理图、问题关系图和算法流程图分别走不同路线。每幅图都要回答“它证明什么”，并检查数据来源、连接关系、排版尺寸、可编辑源文件和正文解读。

流程图不会因为步骤多就强制出现；短文、公式或表格已经能说清时就不画。需要画时，节点、分支、阈值和回退必须与实际公式及代码一致。

### 7. 独立审查不替求解擦屁股

求解与审查分离。审查会检查题意覆盖、结果精度、公式与代码一致性、图表引用、正文篇幅、附件可运行性、语言模板化和匿名性，但不会替求解阶段补造结论。

最多进行有限轮次的定向回退；如果仍有风险，会明确列出，而不是给出没有依据的“高分保证”。

## 工作流

```text
题目与附件体检
      ↓
A/B 题型判断与候选题最小试算
      ↓
基线—主候选—异构挑战模型比较
      ↓
正式求解、关键结果与独立验证
      ↓
第一次确认：方法、结果、验证与风险
      ↓
全文目录、大纲与篇幅规划
      ↓
第二次确认：章节结构与各问轻重
      ↓
单一 LaTeX 总稿、图表、附件与编译
      ↓
独立审查、定向修复与最终冻结
```

## 核心模块

| 模块 | 作用 |
| --- | --- |
| `cumcm` | A/B 题完整流程总控与确认节点 |
| `cumcm-contest-operations` | 72 小时赛程、检查点与降级路线 |
| `cumcm-problem-selection` | 候选题附件体检、最小试算与早期止损 |
| `cumcm-model-tournament` | 基线、主候选和异构挑战的同口径比较 |
| `cumcm-solve` | 建模、编码求解、证据落盘与复现 |
| `cumcm-results-validation` | 逐问答案、独立验证、稳健性与适用边界 |
| `cumcm-notation` | 符号语义、单位和全文公式可读性审查 |
| `cumcm-figures` | 数据图规划、生成、注册与质量审查 |
| `cumcm-diagrams` | 几何图、关系图与流程图的矢量化输出 |
| `cumcm-paper` | 目录、篇幅规划、单一总稿与编译交付 |
| `cumcm-deai` | 去除模板腔、统一参赛者视角和行文节奏 |
| `cumcm-review` | 格式、证据、结果、图表和附件的独立复核 |

## 开始使用

克隆仓库：

```bash
git clone https://github.com/zpf2234/hengmo-ab.git
cd hengmo-ab
python -m pip install -r requirements.txt
```

在支持项目级 Skills 的工作环境中打开仓库，将赛题与附件放入工作目录，然后初始化标准结构：

```bash
python .agents/skills/cumcm/scripts/init_project.py --root .
```

初始化后的主要目录为：

```text
题目/     原始赛题与说明
数据/     清洗后的数据与口径记录
求解/     代码、结构化结果与证据矩阵
论文/     单一 LaTeX 总稿和编译 PDF
附件/     可复现代码与最终支撑材料
审查/     检查报告、确认节点与风险记录
```

修改规则、脚本或绘图模块后，可运行完整预检：

```bash
python .agents/skills/cumcm/scripts/run_skill_preflight.py --root . --no-write
```

绘图模块的安装与使用见 [`figure_mcp/README.md`](figure_mcp/README.md)。不同电脑上的 Python、XeLaTeX、字体和 Visio 路径可能不同，需要按本机环境调整。

## 适用边界

- 当前重点验证 A/B 题，不宣称对 C/D/E 题具有同等稳定性。
- 项目提供的是建模与论文质量控制工作流，不承诺任何奖项。
- 正式比赛必须遵守当年竞赛规则、学术规范和工具使用声明要求。
- 历年赛题、优秀论文、个人参赛材料与本地测试语料不包含在公开仓库中。

## 如果这个项目对你有帮助

衡模·AB 不是我把若干提示和模板临时拼在一起的仓库。这里的很多规则，都来自我对数学建模的一点朴素理解：模型不必最复杂，但必须回答问题；结果不必最漂亮，但必须经得起复算；论文不该替错误的计算辩护，而应该让正确的推理更容易被看见。

我还在继续补 A/B 题的模型覆盖、验证方法和论文审查细节。如果你认可这种“先把问题做对，再把论文写好”的思路，恳请给仓库点一个 **Star**。它对你也许只是一次点击，但对我来说，是判断这套方法是否值得长期维护、继续公开完善的重要反馈。

如果你在真实赛题中发现规则不合理、脚本失效或某类问题覆盖不足，也欢迎提交 Issue。比起一句“很好用”，具体的反例和失败案例更能帮助这个项目往前走。
