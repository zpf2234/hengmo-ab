# CUMCM 问题分析

先完整读取 [../cumcm-paper/references/section-chain-contract.md](../cumcm-paper/references/section-chain-contract.md)、
[../cumcm-paper/references/front-section-content-standard.md](../cumcm-paper/references/front-section-content-standard.md) 与
[../cumcm/references/model-selection-and-answer-quality.md](../cumcm/references/model-selection-and-answer-quality.md)。
论证叙事同时遵守 [../cumcm/references/argumentation-patterns.md](../cumcm/references/argumentation-patterns.md)：
每段只承担一个职责，连接词承载因果而非装饰，跨问衔接写在后问开头。
使用 [../cumcm-paper/assets/latex-template/论文.tex](../cumcm-paper/assets/latex-template/论文.tex)，
只更新 `论文/论文.tex` 的 `sec:analysis` 区域，不创建独立章节 TeX。需要章末关系图或
流程图时调用 `cumcm-diagrams`，完整遵守其 TikZ / Visio 规范。

## 输入

- 已通过门禁的问题重述；
- 数据结构、物理机理、约束关系和歧义处理结论；
- 实际采用的模型路线、求解步骤和必要的模型选择证据；
- 各问的输入、输出、共享变量及验证安排。

缺少真实求解路线时不得凭常识编写“拟采用”的过程，应退回求解阶段补齐。

## 标题与叙事

可按分问设置二级标题，也可按共享关系组织并标明各问对应：

```text
二、问题分析
2.1 问题一的分析
2.2 问题二的分析
……
```

- LaTeX 中写 `\section{问题分析}` 与 `\subsection{问题一的分析}`；模板类自动生成“二、”和“2.1”等编号，不手写编号。
- 按分问或共享关系组织，内部段落由实际矛盾与转化难度决定，不机械拆出“特征判断”
  “分析思路”“求解过程”“输出衔接”等三级标题，也不把它们写成固定四段。
- 各问连续排版，不强制换页。
- 问题之间确有共享输入、前后承接、并行汇合或反馈时，可在各问分析之后放置一幅“各问题关系与总体求解流程图”；该图通常不另设空洞标题。

## 从本题内容起句

问题编号只负责定位，不能充当段落内容。进入一问时，从最能决定路线的本题事实起句：

- **对象或机理**：指出谁受谁作用、哪个状态随什么变化；
- **矛盾或约束**：指出两个目标为何不能同时直接满足、哪条边界限制可行域；
- **数据异常或信息缺口**：指出缺失、不等距、共线、噪声、样本不平衡等现象怎样改变处理方式；
- **关键数学转化**：直接说明需要把连续过程、空间关系、观测量或组合决策化为什么可计算对象。

每问至少突出一个真实转化，并把必要路线接在转化之后。例如，不等距观测会使普通差分的误差口径
失真，正文应先指出这一现象，再说明如何构造可比的变化率；容量与等待时间共同约束调度时，应先写
两者的冲突，再引出决策变量和可行性判定。路线是对象结构的结果，不以“为了求解问题 X，我们采用
模型 Y”倒置因果。若后问确实继承前问，开头直接点明继承的变量、单位或状态关系，不写“更加复杂”
“层层递进”。

### 反模板纪律

1. 不让各问都以“针对问题 X”“为了求解”“首先分析”开头；问题编号之后必须立刻出现本题对象、
   条件、矛盾或异常。
2. 不让各问都按“首先—然后—最后”收成三步。真实计算若有严格时序，可以使用顺序词，但动作必须
   带具体输入和输出，且不能跨问重复同一骨架。
3. 不把四项职责各写一段，也不为每问安排相同段数、相近字数和同一句收尾。核心问、支撑问、
   过渡问自然形成不同轻重。
4. 不写“打开 MATLAB/Python 导入数据”“点击求解按钮”等操作细节，也不用“先进、强大、精准”
   评价普通计算动作。

## 每问的职责池

同时执行 [逐问题意理解与建模入口](../cumcm/references/per-question-understanding.md)，消费
求解计划中的题意理解记录，说明待判断的现实关系、关键困难及其数学转化理由。第二章承担总体
分析，第五章仍须在各问核心式之前就地落实对象与关系；本章完成不能替代该处解释。

下列内容用于成稿后的缺项检查，不是写作顺序，也不是四段模板。只按当前一问实际需要组合：

- 决定路线的对象特征、约束、异常或主要矛盾；
- 从原问题到数学对象的关键转化，以及这条转化为何可用；
- 为理解路线所必需的计算链，相邻动作实际传递的量；
- 本问待求输出，或后问真实继承的对象。各问独立时不写衔接句。

机理、几何或控制问题通常需要交代对象与坐标、主导作用或几何约束、状态量/决策量、控制关系、
数学对象、待求输出和主要误差来源，但顺序服从实际推理，能合并的职责合并。不得从题面特征直接
跳到算法名称，也不得在未说明物理来源时给经验公式。分析章通常以文字关系为主；确需出现公式时，
只保留决定转化的一条简洁关系，先说明来源，式后立即解释它约束了哪个量，不在此处堆叠新符号。

“求解过程”写计算逻辑和步骤之间的因果关系，不在本章展开完整公式推导、代码实现、参数表或数值结果。公式推导和具体计算放入模型建立与求解章节，最终数值和验证证据放入结果章节。

## 篇幅与模型路线

“克制”指删除无证据的候选清单、教科书原理和内部试错，不是把分析压到固定字数。问题分析的
篇幅由真实转化负担决定：关键耦合、歧义判定或约束冲突可以用数段讲清；只继承一个量或替换一个
参数的过渡问可用短段结束。**150 字不是目标，也不是硬上限**，各问不得为了整齐而等长。

模型选择只写真实比较且确实改变最终路线的证据。两条路线可用自然段交代结构差异与决定性依据；
三条以上只有在多个比较维度都影响选择时才用表格。比较不重要时直接写采用的必要关系，不为展示
“思考过程”制造候选模型。

## 图示按信息增益触发

用户目标为国一、国奖或一等奖时，完整读取
[../cumcm/references/national-first-precision-and-visual-gates.md](../cumcm/references/national-first-precision-and-visual-gates.md)。
判断/循环/回退、状态转移或多层依赖并不自动触发流程图。只有这些关系难以用短文、公式或一张
结果图清楚表达，且图能让评委更快识别分支条件、反馈位置或对象传递时，才在分析章加入图示。
步骤数量、目标奖项和“复杂”标签都不是配图配额；文字已经清楚时不画，也无需写形式化豁免。
一旦使用，图中节点、阈值和箭头必须与公式、求解记录及实际脚本一致，并通过 `cumcm-diagrams`
的连接、布局和最终尺寸审查。

## 章末关系流程图

仅在文字难以清楚表达以下任一关系时加入：

- 前一问输出成为后一问输入；
- 多问共享同一数据、变量、机理或子模型；
- 多条分问路线最终汇合到统一决策；
- 后问对前问存在真实反馈或修正。

图中节点写具体对象、输入、关键处理或输出，如“问题一：参数识别”“几何边界”“问题三：方案优化”，
不用“进行分析”“建立模型”“得到结论”等空动作。箭头只表达真实的数据传递、时序、因果或反馈；
没有条件判断时不用菱形。问题关系以模块编排为主时优先 Visio 风格，符号、公式或可重复规则布局较多时优先 TikZ。

图必须保持白底、黑灰线、基础形状、克制配色和矢量输出，保留 `.vsdx`、`.drawio`、`.tex/.tikz`
等可编辑源。若各问只是并列且一段话即可说明，不画图。

## 严格禁写

- 再次重述题面或复制问题重述中的段落；
- 计算结果、最终答案、结果优劣和结论性数值；
- “意义重大、方法合理、效果显著、适用性强、具有推广价值”等开放性评价；
- 模型优缺点、改进建议、应用前景和与当前分析无关的延伸讨论；
- “为了便于理解”“使文章结构更清晰”“为后文奠定基础”等写作元叙事；
- “首先对问题进行分析”“通过上述分析可知”等无信息过渡句；
- 跨问重复“为了求解……采用……”“首先……然后……最后……”或同一四步骨架；
- 文件名、工作表名、代码、脚本、软件操作、审查门禁和内部试错过程；
- 不能回到真实求解记录的候选模型、求解步骤或验证安排。

## 门禁

写入 `审查/section-chain/gates/analysis.json`，至少检查：

- `heading_context_clear`：一级标题独立、各问分析可定位；二级结构按内容选择，历史 `fixed_heading_structure` 记录不构成固定标题要求；
- `separate_from_restatement`：没有重复题面；
- `analysis_logic_complete`：每问的特征、思路和转化关系清楚；
- `question_understanding_grounded`：逐问定位任务含义、决定性特征及转化理由，并能追溯到题面、附件与求解计划；
- `question_openings_content_led`：各问从对象、矛盾、约束、异常或关键转化起句；
- `no_fixed_four_step_template`：未把职责池复制为四段，也无跨问同构的三步连接词骨架；
- `question_weight_by_difficulty`：篇幅与段落数随真实难度变化，不执行固定字数或等长配额；
- `route_necessity_explained`：至少一个关键转化说明了路线为何必要，不以“为了……采用……”倒置因果；
- `solution_process_complete`：每问的真实求解链完整且步骤衔接明确；
- `question_dependencies_faithful`：只写真实存在的跨问关系；
- `no_result_leakage`：没有提前给出结果或结论性数值；
- `no_open_evaluation`：没有开放性评价、优缺点、改进或推广；
- `no_irrelevant_text`：没有空泛过渡、写作说明和无关内容；
- `no_production_trace`：没有文件、代码、软件过程或内部试错；
- `diagram_need_based_on_information_gain`：图示由关系表达的信息增益触发，不按阶段数或奖项目标强制；
- `formula_exposition_readable`：分析章若保留公式，来源、最少符号与任务作用均可直接读懂。

使用章末图时，另要求 `diagram_registry_pass` 和 `diagram_style_audit_pass`；未使用图时记录
问题关系可由文字充分表达。全部通过后由 `cumcm-paper` 继续执行
[../cumcm-assumptions/STAGE.md](../cumcm-assumptions/STAGE.md)。
