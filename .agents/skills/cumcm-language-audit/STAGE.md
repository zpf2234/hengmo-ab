# CUMCM 语言审计

先接收 `cumcm-deai` 的语料声纹审计结果，再完整执行本文件的三层检查与逐章节规范；
本阶段不得调用或依赖项目外的润色、降重、去 AI 技能。再读
[../cumcm-paper/references/section-chain-contract.md](../cumcm-paper/references/section-chain-contract.md)。
目标是具体、自然、可辩护，不是迎合检测器或机械替换同义词。

与 `cumcm-deai` 分工：本阶段用自动规则定位生产痕迹、工程项目腔和宣布式句子；
参赛者视角的句法、段落推进与篇幅轻重由 `cumcm-deai` 在本阶段之前完成。禁词只作兜底，
不能代替整句和整段重写。

## 审计范围

扫描摘要、问题重述、问题分析、假设、符号、逐问正文、结果验证和评价推广。
参考文献、附录代码及按官方要求单列的工具声明不参与“正文主体生产痕迹”禁词判断，但仍检查
匿名性、格式和声明真实性；页数审计中，工具声明与参考文献仍按官方定义计入正文。

## 三层检查

### 1. 生产痕迹

删除 AI、人工智能、GPT、Claude、提示词、prompt、AI 生成、审查流程、附件名、文件名、路径、代码、脚本、
CSV、JSON、运行命令、支撑材料或"完整程序见附录"等信息。正文只保留问题对象和数学证据。
同时删除“审计、门禁、冻结模型/路线/口径、冒烟实验、工作流、证据包、证据矩阵、claim_id”等
内部生产语言，以及“口径不一、统一口径、口径校准、去 AI 化、查重、AIGC”等定稿过程痕迹。
若“口径”指管径、炮口直径等真实物理量，或“冻结”是题目对象真实发生的物理过程，则按专业含义保留；官方 AI 工具使用声明
仍按规定单列，不参与正文主体禁词判断。

### 2. 元叙事与无效解释

删除"本文的回答""本问回答""计算口径""满足问题要求""前者回答……后者回答……"、
"首次出现处定义""见下文定义""便于读者理解""体现了模型有效性"等关于写法、阅读或评分的说明。
若句子删除后事实链不受损，直接删除；若承载事实，改写为条件、关系、结果、误差或边界。

### 3. 模板化语言

- 允许参赛队员视角自然、较多地使用“我们”；不统计其次数，不机械替换成“本文”；
- 删除无逻辑作用的"此外、值得注意的是、综上所述"；
- 把"显著、准确、稳定、优越、应用广泛"换成可观察指标或适用范围；
- 避免段落同构、强凑三点、同义反复和逐段小结；
- 保留必要的因果连接，但让句长和段落长度随论证自然变化。

### 4. 工程项目腔与宣布式句子

- “本节将、下文将、接下来我们将”通常只是宣布写作安排。删除后从对象、条件、公式或数据起句；
- “搭建框架、形成闭环、全链路、端到端、模块化、部署、集成、交付、验收、落盘、版本迭代”若指
  写作或协作过程，改写为具体的数学动作和结果；若是题目对象的真实专业术语，保留并说明定义；
- “我们”可以多用，但后面必须是本队实际做过的动作，如取值、分类、推导、计算、比较、发现和检验，
  不能接“从多维度进行全面深入分析”一类姿态表达；
- 每段只完成一个局部判断。公式后说明结构、特殊情形、参数代入或结果影响，图表后写变化、原因和
  答案影响，不用“展示—说明有效—奠定基础”的机器叙事；
- 发现项目管理式抽象名词时不做逐词替换，返回该段的真实对象和数学动作重写整句。
- 反向样本表明，删除少量夸张词或换成“极简学术风”仍可能保留同构叙事。若每问都按“模型—
  结果—敏感性—验证—本问回答”机械展开，按实质难度重组段落，不做表面换词；
- 独立验证、停止条件、边界和误差必须保留，但不得包装成“验证矩阵、证据五层、交付层、全流程
  解算体系”。文件写入、模板检查、工作表和必填单元格属于内部交付记录，不进入正文。

## AI 典型句式诊断与改写

以下列出 CUMCM 论文中最常见的 AI 生成痕迹，按章节给出诊断模式与改写方向：

### 开头废话模式

```text
❌ "本文针对……问题，通过建立……模型，利用……方法，对……进行了深入分析。"
✅ 直接从研究对象进入："波浪能装置由浮子、振子和弹簧阻尼系统组成，在入射波作用下……"
```

### 逐问同构模式

```text
❌ 每问都用"针对问题X，本文首先……然后……最后……得到了……"
✅ 各问按实际逻辑组织，句式随论证内容自然变化：
   问题一以受力分析为起点 → 问题二从已知运动规律出发 → 问题三直接陈述优化目标
```

### 三段式评价模式

```text
❌ "本模型具有以下优点：第一，……第二，……第三，……"
✅ 不强凑三条。有几条证据支持的优点写几条，直接用事实陈述：
   "守恒量复核偏差不超过 0.1%，说明离散方案在当前步长下可信。"
```

### 过渡词堆砌模式

```text
❌ "此外，值得注意的是，综上所述，进一步地，在此基础上"
✅ 直接写下一个事实或结论，用因果关系本身连接：
   "将式(3)代入边界条件，得 $c_1 = 0.23$。" （不需要"进一步地"）
```

### 空泛结尾模式

```text
❌ "综上所述，本文所建立的模型具有较强的适用性和推广价值，为相关研究提供了有益参考。"
✅ 删除整句。若需要收束，写具体的适用条件：
   "上述结论在入射波频率 0.5–2.0 rad/s 范围内成立；超出该范围时非线性效应不可忽略。"
```

### 假设同构模式

```text
❌ "假设1：假设……是合理的。假设2：假设……是合理的。假设3：假设……是合理的。"
✅ 自然变换句式：
   "1. 研究时段内外部环境参数保持不变。"
   "2. 将各连接件视为理想铰接。"
   "3. 忽略空气阻力对水下运动部件的影响。"
```

### 数字墙模式

```text
❌ 摘要中连续加粗 5 个以上数字，形成"数字墙"
✅ 每问只加粗 1 个核心方法和 1 个最终答案，其余数字用常规字重
```

## 逐章节表达规范

### 问题重述

- 不照抄题面原句，也不逐句做机械同义替换
- 背景段不超过 3 句，不写宏观意义
- 不出现"本文将""拟采用""为了解决"等方法预告
- 各分问用不同的句式结构，不用模板句"针对问题X，要求……"

### 问题分析

- 直接说特征和处理方向，不说"首先分析""下面进行分析"
- 不在每问开头重复"针对问题X"——前面标题已说明
- 第五章的问题层标题默认简写为“问题一”“问题二”，需要区分任务时只补一个短任务名；三级标题
  优先用“受力分析”“运动方程”“参数辨识”“数值求解”等 4--10 字的自然表达
- 不用“问题一模型的建立与求解”“问题二求解与分析”等重复上级章名的标题，也不写“口径审计、
  证据闭环、作答映射、适用边界审查”等内部说明式标题
- 用具体的物理/数学关系代替"进行了深入分析"
- 验证安排只说安排什么，不提前写"预期效果良好"

### 模型假设

- 不以"假设"开头造成每条同构；混用"假设""认为""视为""忽略"
- 不用"本文假设以下条件成立"等引导句
- 假设句长短自然，不强制等长

### 符号说明

- 表格后不写"以上符号将在后文中使用"
- 不对符号体系做评价（"符号体系清晰完整"）
- 必要说明只写定义，不写阅读指导

### 模型建立与求解

- 数学推导串联用因果而非列表：用"由式(X)可得""代入边界条件"；智能算法的实际执行流程
  可以使用 `Step1`--`Step4` 或按真实循环增减步骤，不能因此判为模板化语言
- 不在每个公式后写"其中各变量含义同前"——读者自己查符号表
- 参数来源直接在首次使用处交代，不用"下面对参数进行说明"开头
- 不写"利用 MATLAB 编程求解"——正文只说数学过程

### 结果与验证

- 不写"由图/表可知效果很好"——必须写观察到什么数值
- 不写"验证了模型的正确性"——只写具体指标和判定
- 验证结论不用"较好地""基本符合"——写偏差值和阈值
- 不对每组结果做重复小结

### 评价与推广

- 不写"模型简单、准确、实用性强"——必须接证据
- 局限不写"有待进一步完善"——写什么条件下失效
- 推广不写"具有广阔的应用前景"——写保持什么、改变什么
- 不用"总而言之""综上所述"收尾

### 摘要

- 首句不照抄题目全称
- 不用"本文针对……问题，通过建立……模型"起手
- 每问内容不同构——按实际方法和结论的特点自然变化
- 粗体不连续、不整句、不做"数字墙"
- 不在末尾写"本文的研究为……提供了有益参考"
- 不用“严格闭合、严密无偏、强证据判定、物理定论”等质量宣判替代数值和比较对象

## 事实保护

不得为了去 AI 味改动公式、数值、单位、有效数字、引用、符号或 `claim_id`。
任何技术事实改写后都与证据矩阵复核；存在歧义时保留原事实并调整句法。

## 自动扫描

运行：

```bash
python .agents/skills/cumcm-language-audit/scripts/audit_language.py --root .
```

自动扫描只负责定位硬禁表达和高风险模式，不能代替逐段人工复核。修订后重复运行，直到硬错误为零。

## 门禁

写 `gates/language-audit.json`，记录扫描报告、逐章人工复核状态、已删除模式和因技术必要而保留的表达。
只有硬禁表达为零、生产痕迹为零、事实一致且人工复核完成时才 `pass`，然后交回 `cumcm-paper` 编译。
