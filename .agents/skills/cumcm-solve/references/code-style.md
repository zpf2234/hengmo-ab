# 代码、结果与绘图规范

## 可复现入口

每问保留一个主入口，从原始数据生成全部中间结果、最终表格、图片和 `metrics.json`。

```python
from pathlib import Path
import json
import random

import numpy as np
import pandas as pd

SEED = 2026
random.seed(SEED)
np.random.seed(SEED)

BASE_DIR = Path(__file__).resolve().parent
FIG_DIR = BASE_DIR / "图片"
OUT_DIR = BASE_DIR / "结果"
FIG_DIR.mkdir(exist_ok=True)
OUT_DIR.mkdir(exist_ok=True)
```

- 把参数、随机种子、容差、求解器状态和运行时间写入结果文件。
- 不隐藏警告来掩盖数值问题；只抑制已经定位且无影响的第三方噪声。
- 只在关键函数确有接口说明需要时写简短 docstring；普通小函数不机械套“输入—输出—单位—异常”
  模板。行内注释只解释关键公式、边界处理、非显然参数和易错步骤，不逐行翻译代码，不使用
  长分隔线、口号式标题、对话语气或生成式过渡句。
- 变量和函数按当前题目的对象自然命名；代码去 AI 味以删除模板化结构、合并无意义封装和恢复
  清楚的求解顺序为主，不用随机改名、打乱语句或添加无意义注释处理相似性。
- 原始数据只读；清洗数据另存并记录处理规则。
- 文件路径使用相对项目路径，不写个人绝对路径。

在 `求解/运行环境.json` 固化实际重跑成功的环境：

```json
{
  "python_version": "3.11.15",
  "packages": {"numpy": "2.4.3", "pandas": "2.2.3", "matplotlib": "3.11.0"},
  "run_commands": {
    "问题1": "python 求解/问题1/问题1_求解.py"
  },
  "verified": true
}
```

版本必须来自实际解释器，逐问命令必须从项目根目录验证成功。审计器只检查契约完整性；交接和回归阶段仍须按这些命令真实重跑。
`运行环境.json`、`metrics.json` 和证据矩阵均是内部求解与复核文件，不是默认提交附件。最终归拢时
将必要环境与命令转写为简短运行说明，并排除内部 JSON；题目明确要求的 JSON 输出或运行必需配置除外。

## 变量命名

变量按当前题目的对象和作用命名，可以按需要用中文拼音简写：取拼音首字母、前两个字母，或
多个字的拼音首字母组合。如 `sj`（时间）、`sd`（速度）、`jl`（距离）；这些只是说明命名方式，
不能作为其他题目的固定变量表，不要求写成完整拼音词。

- 简写含义在关键变量旁的简短中文注释或符号语义台账中明确；同一作用域避免不同量使用相同简写，
  重名时增加必要的字母或短词区分。
- 同一量保持同一名称；英文、惯用数学字母与拼音可按代码语境选用，库接口参数保留其规定名称。
- 代码变量名与正文数学符号分别命名，通过语义台账对应含义和单位。例如代码 `sj`、`sd` 可对应
  正文的时间 `t`、速度 `v`。代码简写不进入正文公式，代码变量改名不要求正文符号随之改名。
- 命名以理解和复核为准，不设置拼音比例，不通过随机换名处理相似性。改名后同步引用并核对结果。

## 数值与模型检查

- 在运行前做量纲、定义域和数组形状检查。
- 对迭代算法保存收敛历史、终止原因和最优性/可行性指标。
- 对优化模型单独验证所有约束，不以求解器返回 success 代替可行性检查。
- 对预测模型防止训练测试泄漏，按数据结构选择随机、分组或时间切分。
- 对随机仿真重复运行并报告均值、离散程度或置信区间。
- 对连续数值方法做步长、网格或容差收敛检查。
- 保存未经人工修改的原始结果表，再从它生成论文表格和图片。
- 论文中的数值表由结果 CSV/JSON 通过脚本生成，禁止把敏感性、收敛或方案序列手抄进 LaTeX；生成脚本与表格片段一并落盘。
- 写官方 Excel 模板时使用 `openpyxl` 定位单元格，不用 pandas 覆盖原 workbook；写完以
  `data_only=False` 重新打开，核对 sheet 名、形状、公式/数值单元格数量和抽样值。

## 绘图

默认使用 matplotlib；现有项目若已稳定使用其他库，可继续使用。输出优先 PDF/SVG，
需要位图时使用 300 dpi PNG。

先确定要证明的关系，再选择图型：

- 连续变化、收敛和时间过程优先折线图；变量关系与拟合残差优先散点图；少量类别比较优先点图、柱图或表格；区间占用和调度优先时间线/Gantt 图；
- 热力图只用于真实二维矩阵、空间场、相关矩阵或双参数响应面，且两个轴和颜色三者都承担信息；一维序列、少量类别或本可直接读数的表格不得改画成热力图；
- 不因赛题是 A 题或 B 题强制预设图型。机理题和数据题都按变量维度、比较任务和读数方式选择。

本地 50 篇 A/B 题优秀论文的 760 条图号记录只作为漏图检查的经验先验：

- 物理、几何、运动或装置类问题先检查是否需要坐标系、对象关系、关键截面、受力、投影或
  遮挡示意；此类“模型解释图”应直接对应变量、边界和约束；
- 路径、调度、定位、测线或空间分配问题先检查是否需要轨迹、路线、任务分配或空间布设图；
- 数据分析问题按“分布检查—关系识别—拟合/残差诊断—结果比较”逐项判断，不机械生成全套图；
- 动态系统优先给状态随时间的响应；优化算法只在收敛性、稳定性或参数影响需要论证时给
  收敛与敏感性图；
- 三维图仅在二维投影丢失关键空间关系时使用；热力图仍须通过上述二维结构检查。

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

plt.rcParams["font.sans-serif"] = [
    "Microsoft YaHei", "SimHei", "Source Han Sans CN", "DejaVu Sans"
]
plt.rcParams["axes.unicode_minus"] = False
plt.rcParams["figure.dpi"] = 150
plt.rcParams["savefig.dpi"] = 300
plt.rcParams["savefig.bbox"] = "tight"
```

每张图必须：

- 对应一个待证明的结论或必要的数据诊断；
- 坐标轴包含变量名和单位；
- 图例、颜色、线型在灰度打印和色觉差异下仍可区分；
- 展示必要的不确定性、约束线、基线或局部放大；
- 不把论文图题重复画在图内；
- 保存生成图所用的数据表。
- 在 `求解/图表清单.md` 记录“图型选择理由”；若使用热力图，另写二维结构、颜色变量和不用折线/散点/表格的原因。

组合图只在子图共享问题和比较维度时使用。3D 图仅在二维投影确实丢失关键信息时使用。
禁止用装饰图、重复流程图或难以定量读取的效果图填页。

工具按职责选择：

- PowerPoint：几何机理、场景关系和流程图，保留可编辑 `.pptx` 并导出矢量 PDF；
- Python（matplotlib）：工程曲线、三维轨迹、曲面、等值场、统计诊断、批量数值图、验证图
  和自动化；全部数据图的统一路线；
- TikZ 仅用于坐标能精确描述且后续维护成本可控的几何图。

数值点、轨迹和曲面必须由结果文件或脚本生成，不得在 PowerPoint 中手工调整数据位置。
示意图允许人工排版，但关键坐标、比例、方向和标注必须与模型定义一致。

## `metrics.json` 契约

字段可按题型扩展，但必须保留可追溯结构：

```json
{
  "问题": 1,
  "口径": "本问采用的题意解释",
  "主模型": {
    "名称": "模型名称",
    "关键参数": {},
    "求解状态": "optimal/converged/completed"
  },
  "关键结果": [
    {
      "claim_id": "Q1-C1",
      "名称": "最终答案指标",
      "数值": 0.0,
      "单位": "m",
      "有效数字": 4,
      "来源": "结果/结果表.csv"
    }
  ],
  "验证": [
    {
      "类型": "步长收敛/留出验证/可行性检查/情景复算",
      "指标": "相对误差",
      "数值": 0.0,
      "阈值": 0.01,
      "通过": true,
      "来源": "结果/验证.csv"
    }
  ],
  "稳健性": [],
  "最终回答": "含关键数值与单位的一句话答案"
}
```

论文中的数值必须来自此文件或它指向的结果表。不要在 LaTeX 中手工改数。

## 证据矩阵

`求解/证据矩阵.csv` 每行对应一个可独立核查的结论：

```text
claim_id,问题,题目要求,结论,指标路径,图表路径,生成脚本,验证方式
```

一个结论可对应多个图表，但不得出现“有图无结论”或“有结论无来源”。
