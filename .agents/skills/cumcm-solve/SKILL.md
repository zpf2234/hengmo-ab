# CUMCM 求解阶段

先证据，后论文。每个关键数字、图表和结论都必须由本阶段独立算出、保存并可重跑。

## Step 0：输入审计

1. 读取题面、附件说明与提交要求，识别顶层问题数。
2. 全量检查附件的 sheet、字段、单位、缺失、异常、重复、隐藏内容、多级表头和备注。
3. 区分题面事实、合理假设和待判定歧义；禁止把参考论文结论当成题面事实。
4. 若存在 `审查/优秀论文对标.md`，只读取结构统计和验证信号，不读取参考论文段落。
5. 最终答案冻结前不得读取同题优秀论文的模型链、参数或数值答案；完整边界见
   [../cumcm/references/model-selection-and-answer-quality.md](../cumcm/references/model-selection-and-answer-quality.md)。

## Step 1：赛题地图

在 `求解/求解计划.md` 为每问记录：

- 输入、输出、决策变量、目标、约束、单位和评价指标；
- 与前问的依赖及可复用中间量；
- 该问与其他问题是共享机理、递进扩展还是相互独立，用于后续选择论文标题树；
- 问题原型：机理、几何、预测、分类、评价、优化、仿真或决策；
- 会改变答案的歧义及至少两种解释；
- 最终必须落盘的答案、验证和证据；
- 按 [../cumcm/references/grading-profile.md](../cumcm/references/grading-profile.md)
  的评阅要点结构共性，为每问写"评阅视角验收标准"：必备交付清单（模型+算法+结果
  三件套与要求的中间量）、该问题型的高频扣分模式、可争取的明确加分项。注意只读
  该跨年共性文件；同题逐题评阅要点（`cumcm-blind-benchmark/assets/grading-standards/`）
  含答案数值，冻结前禁读。

通过小规模算例、量纲分析、边界条件或逻辑反证选择歧义口径，并记录理由。
同时按 [references/task-contract.md](references/task-contract.md) 写
`求解/任务契约.json`；契约未通过审计前不得开始编码。
按 [../cumcm/references/title-structure.md](../cumcm/references/title-structure.md) 在
`求解/章节结构建议.md` 记录推荐的章节路由、共享模型放置位置和每问结果/验证归属；该文件
只描述依赖关系，论文阶段可随证据密度调整。

```bash
python .agents/skills/cumcm-solve/scripts/audit_task_contract.py --contract 求解/任务契约.json
```

## Step 2：方法决策与多假设试算

先完整读取
[../cumcm/references/ab-model-algorithm-routing.md](../cumcm/references/ab-model-algorithm-routing.md)，
用“研究对象—状态演化—观测—决策—约束—不确定性—交付”七维签名选择一个或多个路由 ID，
再生成基线、主候选、异构挑战和 fallback。A/B 只限定本技能的经验语料范围，题号字母不得进入
选模特征。目录更新后运行：

```bash
python .agents/skills/cumcm-model-tournament/scripts/validate_ab_model_catalog.py
```

按 [../cumcm/references/model-selection-and-answer-quality.md](../cumcm/references/model-selection-and-answer-quality.md)
落实 **A/B 题四大核心**（模型选择、假设合理、结果准确、思路完整）：

1. **多假设与多模型试算**：在求解探索阶段，必须显式设计与测试**多组不同的合理假设**（如刚体 vs 弹性形变、单自由度 vs 多自由度、常数阻尼 vs 非线性阻尼）与**多个异构候选模型**（基线 vs 主候选 vs 异构挑战）。
2. **精选最正确假设与最准确模型**：经过硬淘汰（守恒、量纲、约束）与独立验证（误差、收敛性、界限 gap），最终**仅精选最准确、最合理的假设组合与最强模型**作为正式论文主解。正文假设章仅呈现支撑最终最优模型的必要假设。
3. **正文表达服从选择证据**：候选比较、内部试错、淘汰表和模型竞技图只留在求解证据中。论文
   仅用短文说明最终路线及真正影响答案的决定性理由；不得把内部候选表、模型对比表或选择流程图
   搬入正文，也不把模型选择压成固定句数、固定段落或统一模板。

候选先通过题意、量纲、物理、约束、可识别性和可复现性硬门槛，再依次比较独立验证、稳健性、答案质量与计算代价；不得只按拟合误差或单次目标值选模型。基本规律唯一时仍须用不同离散、估计器或解析特例挑战主实现。

- 机理/几何：优先守恒关系、受力、几何约束、微分方程和数值离散。
- 预测/分类：先建立简单基线，再用交叉验证、时间外推或留出集证明复杂模型的必要性。
- 评价：明确指标语义、方向、量纲、权重依据和排名稳定性。
- 优化/决策：显式写出决策变量、目标函数、约束、可行性和最优性/近优性证据。
- 仿真：说明随机机制、参数来源、重复次数、置信区间和收敛标准。

仅在有比较意义时设置 baseline；机理题可用解析解、极限情形、守恒量或第二种数值方法交叉验证。
保留一个可执行 fallback，避免主模型失败时整题失去答案。

试算前在任务契约预先写明候选路线、关键假设、淘汰条件和答案证据要求。选择冻结后在每问
`metrics.json` 保存候选判定、主模型、选择依据和论文呈现方式；落选路线中至少保留一条作为
独立验证。若模型间差异不超过数值或抽样不确定性，报告模型平均、区间或并列候选，不制造
唯一结论。

计算降阶不得悄悄缩小题面允许的决策空间。若引入“同机同目标、固定候选轨迹、限制邻域”等额外约束，必须在任务契约和论文中标为建模限制，并至少用更宽的弹级/变量级邻域搜索检查其影响。方案排名差必须与多初值、随机种子或离散误差比较；排名间隔不大于求解不确定性时，只能报告近优候选，不能宣称最优。

拒绝下列模式：因赛题字母预设算法；为“高级”而使用黑盒；无样本支持的高参数模型；
无一致性检验的 AHP；无方向与稳定性分析的 TOPSIS；无约束处理和收敛证据的启发式算法。

国一模式对所有会改变最终答案的关键问题调用 `cumcm-model-tournament`，生成
`求解/模型竞技场.json`、`求解/候选淘汰记录.md` 和 `求解/创新贡献表.md`。协议必须在试算前冻结；
同一实现仅换随机种子不算异构挑战，算法名称变化但误差机制相同也不能作为独立复核。

## Step 3：验证设计

编码前为每问指定至少一种主验证和一种补充检查：

| 问题类型 | 主验证示例 | 补充检查示例 |
|---|---|---|
| 机理/几何 | 守恒、解析特例、独立数值算法 | 网格/步长收敛、量纲与边界 |
| 预测/分类 | 严格留出、交叉验证、时间外推 | 残差、校准、消融 |
| 评价 | 排名一致性、外部标准 | 权重扰动、指标删减 |
| 优化 | 可行性、上下界、求解器 gap | 多初值、参数扰动、情景分析 |
| 仿真 | 置信区间、重复实验 | 随机种子、样本量收敛 |

验证指标必须有判定标准，不接受只画图不判断。

若仿真结果用于从多个候选中筛选、淘汰或宣布可行/最优，必须额外冻结候选总数、总错误预算、
同时置信控制、序贯停止规则和最终独立确认集。逐点区间不能直接推出全候选同时成立；缺少同时
控制时结论必须降为抽样下的估计或最佳已知候选。

优化题还须区分“结果稳定”和“接近全局最优”：优先构造松弛界、解析界、对偶界或小规模精确解；
无法给出界时扩大候选池/变量邻域并报告最佳已知或近优方案。逆问题检查合成回收、目标剖面、
多初值和参数相关性；预测、统计、评价和仿真分别执行防泄漏、排名扰动和样本量收敛。

## Step 4：逐问实现

```text
求解/问题X/
├── 问题X_求解.py
├── 图片/
└── 结果/
    ├── metrics.json
    └── 结果表.csv
```

- 每问一个主入口，能从原始数据重跑到最终证据。
- 先保存清洗数据和模型结果，再生成图。
- 固定随机种子，记录环境、关键参数、求解状态和运行时间。
- 写 `求解/运行环境.json`，记录实际验证过的 Python 版本、依赖包版本、逐问运行命令和 `verified: true`；不得只写宽泛的“需要 Python”。
- 对关键参数、假设或场景做灵敏度/稳健性分析。
- 执行参数可识别性、数据泄漏、单位/量纲、极端条件和反例检查；不适用项必须记录题型理由。
- 图片和表格按“要证明的结论”生成；不设置机械数量下限。
- 题目提供 `result*.xlsx` 等输出模板时，保持原 sheet、行列、单位和精度写入有效数值，
  并在脚本末尾重新读取检查空表、错位和缺失。
- 代码与绘图规范见 [references/code-style.md](references/code-style.md)。
- 图形职责、A/B 经验先验和人工学术风格同时遵守
  [../cumcm/references/figure-routing.md](../cumcm/references/figure-routing.md)。
- 数据、预测、试验、评价、抽样或统计决策分问同时完整读取
  [references/statistical-computing-contract.md](references/statistical-computing-contract.md)，
  先冻结缺失/零值/分母语义与无泄漏数据口径，再进入模型。
- 关系图、分题流程、算法迭代、数值计算或状态决策图同时遵守
  [../cumcm/references/flowchart-routing.md](../cumcm/references/flowchart-routing.md)；流程节点、
  分支、判停与回退必须能映射到实际函数、循环或约束检查。只有图能带来信息增益、显著降低
  关系重建成本时才保留，步骤多或目标奖项高都不自动触发配图。
- 几何图、关系图和流程图同时遵守
  [../cumcm/references/diagram-connection-audit.md](../cumcm/references/diagram-connection-audit.md)；
  生成时建立逐连接与逐线语义清单，记录两端锚点、分支文字、禁止穿越对象、方向、箭头要求、
  物理/算法含义和最终渲染结果。
- 为论文摘要输出逐问“任务—模型—算法—结果—验证”五元组，遵守
  [../cumcm/references/abstract-writing.md](../cumcm/references/abstract-writing.md)。
- 为附录准备问题编号、主程序、公共依赖、运行命令、环境版本和预期输出映射，遵守
  [../cumcm/references/appendix-structure.md](../cumcm/references/appendix-structure.md)。
- 为论文架构准备“前置功能—逐问闭环—综合验证—附录索引”映射，遵守
  [../cumcm/references/paper-architecture.md](../cumcm/references/paper-architecture.md)；
  输出可直接形成独立三列符号表的符号、含义和单位字典。
- 证据稳定后输出“研究对象—核心动作—主导机理/方法—对应证据位置”的标题候选表，遵守
  [../cumcm/references/paper-title.md](../cumcm/references/paper-title.md)；不把仅用于单个辅助
  步骤的方法写入总标题。

## Step 5：证据契约

每问的 `metrics.json` 至少包含：

- 问题编号、口径与主模型；
- 关键结果：名称、数值、单位、精度和来源文件；
- 验证：方法、指标、阈值、结果与是否通过；
- 稳健性或敏感性结果；
- 模型选择：候选、角色、判定证据、主模型、选择依据和论文呈现方式；
- 答案充分性：题面闭环、物理/约束可行、独立验证、数值分辨率、替代路线挑战、
  不确定性/最优性与最终 PASS 状态；
- 最终回答，用可直接写入摘要的一两句话表述。

建立 `求解/证据矩阵.csv`，至少含：

```text
claim_id,问题,题目要求,结论,指标路径,图表路径,生成脚本,验证方式,模型选择依据,充分性证据
```

建立 `求解/图表清单.md`，记录图表职责类别、来源数据、生成脚本、关键读数、拟支撑结论、
图型选择理由和可编辑源文件。流程图另记录主要功能、关键分支与回退条件；几何/物理题另
检查是否缺少与模型定义同构的解释图。

除逐问验证外，额外整理至少两类跨问题证据供独立“综合验证与稳健性”章使用，例如统一
步长/样本量收敛、共享约束余量、参数或情景扰动、独立实现复算及误差传播。题型不适配时
更换验证类型，不为凑章伪造实验。

运行：

```bash
python .agents/skills/cumcm-solve/scripts/audit_evidence.py --root .
```

审计通过后，再检查每问是否真正回答题目、主模型是否经异构路线挑战、答案精度是否高于数值
分辨率、验证是否有判定、图表是否承担论证职责；全部通过后整理方法与结果审阅包，但不自动交接
论文阶段。审阅包须清楚呈现各问主方法、关键假设、最终结果、独立验证、稳健性/最优性证据和剩余
风险。交接前按
[../cumcm/references/grading-profile.md](../cumcm/references/grading-profile.md) 第三节
雷区清单逐条自查（算法黑箱、无误差分析、外推失控、重复计数、只报最优值不给方案等），
任一命中即回到对应 Step 修复，不带病交接。

随后停止执行，等待用户明确确认方法与结果达到其认可的国一目标，并明确要求开始使用模板和论文
skills。确认前不得创建论文模板、正式目录或正文；系统自评、证据审计 PASS 或国一门禁评分不能
代替用户确认。确认方式与证据哈希绑定按
[半自动论文工作流](../cumcm/references/semi-automatic-workflow.md) 执行。

国一模式在读取同题答案、优秀论文关键数值或隐藏校验量前按
[盲测阶段](../cumcm-blind-benchmark/STAGE.md) 冻结题面、
附件、任务契约、代码、结果、metrics、证据矩阵和 PDF。冻结清单不存在或后续哈希失效时，不得把
该项目计入前向盲测能力。
