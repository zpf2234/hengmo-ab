# CUMCM 问题重述

先完整读取 [../cumcm-paper/references/section-chain-contract.md](../cumcm-paper/references/section-chain-contract.md) 与
[../cumcm-paper/references/front-section-content-standard.md](../cumcm-paper/references/front-section-content-standard.md)。
使用 [../cumcm-paper/assets/latex-template/论文.tex](../cumcm-paper/assets/latex-template/论文.tex)，
只更新 `论文/论文.tex` 的 `sec:restatement` 区域，不创建独立章节 TeX。只依据题面、附件
所承载的已知信息和官方任务契约重述；不得借用优秀论文的句式或段落骨架。

## 成稿结构

以下为可选的两级结构；内容较少时可省略二级标题并直接成文，保持任务可定位：

```text
一、问题重述
1.1 问题背景
1.2 问题提出
    问题一：……
    问题二：……
    ……
```

- 一级标题写 `\section{问题重述}`；采用二级结构时写“问题背景”“问题提出”，编号由模板自动生成。
- “问题一：”“问题二：”等作为段内加粗标签连续排版，不设为三级标题，不因分问强制换页。
- 通常先交代背景、再陈述问题；不在其前后插入“研究意义”“任务概览”“相关说明”“计算口径”等内容。

## 写作方法

### 1.1 问题背景

用一个紧凑自然段说明研究对象、所处场景和题目为何会产生。通常写 2--4 句；只有装置结构或工作机理是理解任务的必要前提时，才增加一个短段。背景必须明显短于“问题提出”主体。

只保留理解题目所必需的事实，不扩写政策、行业史、文献综述或宏观意义，不使用“意义重大、不可小觑、迫切需要、应用前景广阔”等评价性语言。

### 1.2 问题提出

先用一小段重新说明对象构成、运行状态、给定材料或共同条件；随后用一句自然过渡引出各问。按原题顺序，每问单独成段并写清：

1. 当前对象或情形；
2. 题目已经给出的条件、数据及会改变任务含义的约束；
3. 需要完成的动作；
4. 最终需要给出的量、方案、判断或其他输出。

前一问结果确为后一问的题设条件时，可以客观写“在问题一的条件或结果基础上”，但不得解释这种依赖的建模意义。

### 规范写作纪律

1. **绝对禁止第一句照抄题目全称或比赛名称**。
2. **绝对禁止加入主观修饰词**（如“极其重要”“非常复杂”“完美解决”）。
3. **句式由任务决定**：可按条件、目标或约束推进，不指定某一问必须使用某种句型，也不为制造差异而改写正常重复。

## 严格边界

本章禁止出现：

- 数据特征、问题难点、问题间机理分析或原因解释；
- 候选模型、具体模型、算法、变量设计、公式、假设和求解步骤；
- 计算结果、图表发现、验证、稳健性、优缺点、改进或推广；
- 对题目、方案、模型或预期效果的主观评价；
- “因此采用”“据此建立”“可以有效解决”“为后续建模奠定基础”等越界或元叙事；
- 附件文件名、工作表名、代码、脚本、处理流程和生产痕迹；
- 大段题面原文、机械同义替换以及与重述无关的引文扩展。

题面存在歧义时，本章只保持与原题等价的中性表述；采用何种解释及其影响移交问题分析或模型假设，不在重述中讨论。

## 门禁

与 `求解/任务契约.json` 逐问核对，确保无漏问、改问、增问。写入
`审查/section-chain/gates/restatement.json`，至少检查：

- `heading_context_clear`：一级标题独立，二级标题按内容选用，读者能定位各问任务；历史 `fixed_heading_structure` 记录不作为形式限制；
- `background_brief`：背景简短且没有扩展性铺陈；
- `task_coverage`：覆盖全部分问；
- `input_output_fidelity`：条件、约束和所需输出忠实；
- `semantic_rewrite`：不是原题句式的机械复刻；
- `separate_from_analysis`：没有分析性内容；
- `no_method_or_result`：没有方法、求解、结果或验证；
- `no_evaluation`：没有评价、改进或推广；
- `no_production_trace`：没有文件、代码或写作过程痕迹。
