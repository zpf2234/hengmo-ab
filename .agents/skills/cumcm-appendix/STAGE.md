### 规范写作纪律

1. **绝对禁止泄漏个人/学校/赛号/博主信息**（一票否决红线）。
2. **代码必须使用等宽字体（Consolas / Courier New）**，且每一行代码控制在 75 字符以内，避免超宽被 PDF 边距截断。
3. **正文与附录代码结果 100% 双向一致**，严禁伪造跑不通的代码。

## 内容顺序

1. 支撑材料清单：相对路径、用途、对应问题；
2. 按问题或功能模块组织的完整可运行源程序；
3. 真实运行环境、依赖版本、输入输出约定与复现命令；
4. 正文放不下但核查结论所需的补充推导、表格或诊断；
5. 必要的数据字段说明，不重复题目原始数据。

最终交付时，把规则要求的 `AI工具使用详情.pdf` 放入 `附件/支撑材料.zip` 内，不作为第三个顶层
提交文件；压缩包与
`论文/` 中的单一总稿 `论文.tex`、`论文.pdf` 及必要编译资产共同构成两类最终产出。
工作过程目录不随附件外发。压缩包采用白名单归拢，不允许把 `求解/` 或 `审查/` 整目录直接打包。
内部 `metrics.json`、任务契约、运行环境 JSON、证据矩阵、模型比较、图形注册表与布局 JSON、
检查报告、日志、缓存、临时文件、测试文件、重复产物和废弃代码全部排除；只有题目明确要求的
JSON 答案或程序确实依赖的必要配置可以保留。

## 支撑材料清单模板

附录开头用表格建立索引：

```text
| 序号 | 文件/模块 | 用途 | 对应问题 | 运行方式 |
|------|----------|------|---------|---------|
| 1    | Q1_solve.py | 问题一主求解 | 问题一 | python Q1_solve.py |
| 2    | Q2_optimize.py | 问题二优化 | 问题二 | python Q2_optimize.py |
| 3    | utils.py | 公共工具函数 | 所有 | 被其他脚本导入 |
```

## 代码组织模式

按问题分组，每组遵循以下结构：

**功能说明**（2–3 句）：
- 本程序解决什么问题，对应正文哪个模型/算法
- 主要输入和输出是什么
- 对应正文公式编号（如有）

**完整代码**：
- 不得使用省略号、伪代码占位或"此处省略"
- 无法解析的外部绝对路径替换为相对路径
- 输入输出与论文结果一致，随机过程固定种子

**预期输出**（可选）：
- 给出关键结果的预期数值或文件名
- 便于评委核验代码真实性

## 代码内注释规范

注释保持参赛代码的自然密度。文件开头可用一两行说明用途；复杂函数只在接口不直观时写简短
docstring。普通代码只注释关键公式、边界处理、非显然参数和容易误解的步骤，不逐行解释，不把
每个函数统一写成“问题—输入—输出—对应公式”的固定块。

删除下列常见 AI 痕迹：连续编号式说明、长横线分区、重复说明显然语句、对话式提示、空泛的
“初始化参数”“进行数据处理”“输出最终结果”，以及为了显得完整而增加的无意义封装。代码结构
按真实计算顺序组织，变量和函数名贴合题目对象；不得用随机改名、拆分等价语句或堆注释冒充降重。

## 环境规范

必须声明且经过实际验证：

```text
【开发环境】
- 语言：Python 3.11.5
- 核心依赖：numpy 1.24.3, scipy 1.11.2, matplotlib 3.7.2
- 优化器：gurobipy 10.0.3（需商业许可）或 scipy.optimize
- 操作系统：Windows 11 / Ubuntu 22.04

【运行方式】
- 问题一：python Q1_solve.py（预计运行 < 30 秒）
- 问题二：python Q2_optimize.py（预计运行 < 5 分钟）
- 全部重跑：python run_all.py
```

不得只写宽泛的"需要 Python"或"MATLAB 环境"。

## 正文与附录边界

正文必须自洽地给出模型、关键推导、参数和最终结果。附录承担复现与补充证据，不能替代正文论证。

| 归属正文 | 归属附录 |
|---------|---------|
| 核心公式推导 | 完整代码实现 |
| 模型建立逻辑 | 补充性推导细节 |
| 关键结果和验证 | 大体量结果表 |
| 参数选择依据 | 运行环境和命令 |
| 图表及其解释 | 支撑材料索引 |

正文不反复写"完整程序见附录"、文件名、代码入口或运行命令。
附录内的代码与正文数值必须完全一致，种子固定后可重跑。

## 匿名性检查

逐一删除：
- 姓名、学校、学号、参赛号
- 账号、机器名、个人目录（如 `/home/zhangsan/`）
- 第三方作者痕迹（如 `# Author: xxx`、`# from CSDN`）
- 无关链接和博客地址

## 规模

附录页数由完整代码和复现需求自然形成，不追求 50 篇语料中位数。不得用原始数据、重复代码、终端日志或
大段自动生成表格灌页。

## 门禁

写 `gates/appendix.json`，检查模块完整、命令可运行、环境真实、正文结果可复现、材料索引有效、匿名性通过、
无原始数据灌页。代码与正文数值冲突时退回求解和结果阶段。通过后由 `cumcm-paper` 按
[../cumcm-abstract/STAGE.md](../cumcm-abstract/STAGE.md) 定稿摘要。

封包前另做成员清理：只保留完整源程序、官方要求的结果文件、实际使用的自主数据或必要补充材料、
运行说明，以及适用时的 `AI工具使用详情.pdf`。工作用 JSON、CSV 检查表、日志、缓存、临时图、
测试夹具和旧版本不得进入压缩包；题目明确要求或运行必需者除外。
