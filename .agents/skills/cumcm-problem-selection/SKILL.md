# CUMCM 赛题选择与止损

## 触发与边界

国一/国奖目标在正式求解前必须调用。只负责选题，不提前写论文，也不读取同题优秀论文的答案、模型链和关键数值。若用户已明确指定题目，仍执行单题可行性与止损检查。

## 同口径最小试算

对每个候选题限定相同时间预算，完成：

1. 全量读取题面、附件、输出模板和当年规则；记录数据缺失、单位、歧义和软件依赖。
2. 建立逐问输入—输出—依赖图，识别核心瓶颈和失败传播路径。
3. 对最难且最能决定整题成败的一问做最小试算，不以摘要式方法设想代替运行结果。
4. 至少构造一个基线并验证一个关键量、可行解或误差指标。
5. 判断是否能获得不共享主要误差机制的独立验证。
6. 估计完成核心求解、验证、制图、成文和复核所需时间，记录主路线与降级路线。

## 评分卡

写 `求解/选题评分卡.json`。每题按 0--5 分评价：题意可闭环、数据可用、核心量可识别、验证可得、计算可承受、逐问耦合风险、结果可解释、视觉证据潜力、创新空间、72 小时交付可行性。每个分数必须绑定试算文件或题面证据。

以下为一票否决：核心输出无法定义；关键附件不可恢复；最难问无可执行路线且无降级；核心结论无法验证；计算预算明显超限；必须依赖未授权数据或软件。

## 决策与止损

写 `求解/选题决策.md`，包含入选题、淘汰题、决定性证据、最大风险、停止条件和下一检查点。总分只作排序；存在一票否决的题不得入选。若最高两题差距小于评分不确定性，优先选择验证更强、失败传播更小的一题。

冻结后才进入 `cumcm-solve`。到达预设检查点仍未获得核心可行解、关键量级或独立验证时，执行已记录的切题/降级路线，不用沉没成本维持原选择。

## 门禁

完成条件：每个候选题都有真实最小试算、证据化评分和明确止损点；入选题无一票否决项；`求解/选题评分卡.json` 与 `求解/选题决策.md` 均存在且决定一致。否则状态为 `BLOCK_SELECTION`。
