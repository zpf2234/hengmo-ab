# CUMCM 模型竞技场

## 何时使用

每个会实质改变最终答案的关键问题必须调用。基本机理唯一时，把不同离散、解析特例或独立实现作为挑战者；不得为满足数量伪造方法对比。

## 题型路由

先依据题面和附件，在已有计划中形成问题签名和关键结构初判，再用目录补漏。候选试算前完整读取
[../cumcm/references/ab-model-algorithm-routing.md](../cumcm/references/ab-model-algorithm-routing.md)，并运行：

```bash
python .agents/skills/cumcm-model-tournament/scripts/validate_ab_model_catalog.py
```

先按研究对象、状态演化、观测结构、决策变量、约束、不确定性和交付识别问题签名，再选择一个
主路由和必要的辅助路由。题号字母只能说明语料范围，不能作为路由键。目录提供的是候选边界，
不是算法清单；实际候选必须写出模型方程、参数来源、求解器契约和可执行验证。
调度、分配、路径、选址、资源、连续设计、鲁棒或多目标优化还须完整读取
[references/optimization-solver-contract.md](references/optimization-solver-contract.md)，先强化模型和
构造可行基线，再选择或调优求解器。

## 竞技协议

先独立识别题目结构，再接触历史解法。首次结构判断只依据题面、附件、允许的官方澄清与通用
知识，记录材料接触情况；不得从同题成稿反推“独立”候选。真实当届比赛全程不得为避重访问、
检索或讨论当届解答平台内容、其他队伍方案；自己的方法或答案已经冻结也不解除此限制。

每问候选生成及主候选冻结前读取并执行
[关键数学结构查漏](references/structural-discovery.md)，检查解析关系、临界状态、对称性、
单调性、关键对象和等价简化。记录具体关系与验证责任，不能以算法名称清单结束选模。
用户要求历史题能力检验或同题方法对照时，读取
[独立思路冻结与遗漏评估](references/historical-idea-benchmark.md)，先区分思路测试与完整求解盲测。

试算前写 `求解/模型竞技场.json`，冻结：

- 问题签名、主/辅助路由 ID 及不适用路线；
- 统一题意口径、训练/验证数据和约束；
- 透明基线、主候选、异构挑战、fallback 的角色；
- 关键候选的机制指纹、题面触发线索与待检验的差异；
- 硬淘汰条件和评分指标；
- 数值容差、随机种子、总预算和探索分支的截止/停止条件及回退路线；
- 每个候选的结论等级上限，以及升级所需证据；
- 何时只能报告估计、最佳已知、近优、区间或并列候选。

候选依次通过题意、单位/量纲、定义域、约束、可识别性、数据泄漏和可复现性硬门槛。存活候选再比较独立验证、稳健性、答案质量、复杂度、计算代价和可解释性。优化问题增加可行性、界/gap、小实例精确解或扩大邻域证据；逆问题增加合成回收、目标剖面、多初值和参数相关性；预测问题使用严格留出或时间外推。

候选按以下职责建立；角色可复用，不强制四套模型或四份代码：

1. **透明基线**：暴露量纲、数量级、方向与约束错误；
2. **主候选**：最贴合题面机理、数据结构与决策空间；
3. **异构挑战**：主要误差机制不同，不是同一代码换名称或随机种子；
4. **fallback**：不可识别、不收敛或超时后仍可交付的保守路线。

若问题基本规律唯一，允许不伪造第二套模型，但必须以解析特例、不同离散、不同估计器或独立实现
挑战主结果。候选差异小于数值或抽样不确定性时，保留区间或并列候选。

## 创新探索与最小充分方法原则

候选生成与创新审计时读取 [references/innovation-and-composition.md](references/innovation-and-composition.md)。
支持建模视角、模型结构、求解算法三类创新；允许从题目直接提出可行的新角度，也允许从常规
方法的不足出发改进。不要求三类齐全或每问创新，不把基线先失败作为探索创新的前提。
用户强调减少方法同质化时，把有限探索预算优先投向影响答案质量的核心难点；基础问按最小
充分方法完成。共同物理规律、经典算法与必要的标准推导不是禁用对象；差异须落实到表示、
约束、观测、不确定性或求解机制，不靠换名、换符号或添加无职责模块。

先冻结题面闭环、精度、约束、稳健性、运行时间和可解释性门槛，并声明本次改进要检验的指标。
全部硬门槛通过后，以可验证收益和新增成本选择主方法；收益相当时优先低复杂度路线：

1. 解析关系、直接计算、完备枚举、动态规划、经典统计或确定性优化能够完整解决时，优先选用；
2. 简单方法全部硬门槛通过，且候选在预先声明的精度、速度、稳健性和解释等指标上没有实质差异时，保留简单方法；
3. 新路线可通过修复基线失败，或在基线已达标时取得有实际价值的精度、耗时、可扩展性、稳健性或解释收益而入选；新增复杂度须与收益相称；
4. 机器学习、神经网络、遗传算法、粒子群、差分进化等没有“智能算法加分”。采用者承担额外
   证明责任：数据/搜索空间确有需要、验证增益稳定、参数与停止条件完整、结论强度不过界；
5. 为模型选择而伪造复杂挑战、把同一算法换名称，或以“更先进”替代证据，均直接淘汰。

在 `求解/模型竞技场.json` 保留 `minimum_sufficient_decision`：简单候选是否达到门槛、
新路线修复的失败或达标后的额外收益、证据及不确定性、新增成本、最终为何采用或拒绝。
仅有创新设想可进入试算，未经验证的优势不得写成已成立贡献。

## 结论认证

- “全局最优”只由完备枚举、数学证明、凸/对偶证书或分支定界 gap 支撑；
- 局部求解器和元启发式默认最多支持“最佳已知/近优候选”，多初值稳定不能升级为全局证明；
- 自适应 Monte Carlo 或机会约束若比较多个候选，必须有同时误差控制、可选停时有效规则和
  最终独立确认；只有逐点区间时最多报告估计结果；
- 参数不可识别、边界解释未隔离或搜索空间被未声明缩小时，先淘汰或降低结论，不进入软评分。

## 创新审计

按上述创新参考文件写 `求解/创新贡献表.md`，区分建模视角、模型结构、求解算法及其组合，
记录题目依据、具体改造、对照证据、成本与适用边界。允许贡献体现为同精度下更快，或相同
预算下更准确、更稳定。换算法名称、无职责堆模型、调配色、增加无效指标不算创新。
组合必须说明输入输出、耦合关系、误差传递及各模块必要性；算法贡献不得冒充模型贡献。
论文可呈现证明贡献所必需的对照或消融，完整探索记录留在求解文件。

建模与算法改造均记录机制指纹，区分题目特定适配、可复现实质改进与有限检索范围内的新颖性。
比较当前候选及允许使用的通用机制；历史同题对照仅按独立冻结协议开放，不用赛中平台或其他
队伍方案做碰撞审计。指纹重合不能制造独立创新；正确的常规方法仍可保留为主方法。
明确实际比较范围与未覆盖范围，不能保证与所有队伍或其他 AI 输出不重复。

首次向用户提交方法与结果、请求确认前，在现有 `求解/创新贡献表.md` 顶部给出“方法差异简报”
并向用户展示：常规路线、我们的实质差异、数学依据、对照证据/成本/边界和采用状态。无实质
改进时直说保留基线。具体记录格式见创新参考文件；队员人工核验未实际发生时保持“待队员核验”，
AI 交叉审查不能代替真实队员确认。

## 输出与门禁

在 `求解/候选淘汰记录.md` 逐项记录路由 ID、执行状态、淘汰证据、保留原因和结论等级。
主模型必须经至少一个不同主要误差机制的挑战；候选差异不超过数值/抽样不确定性时不得制造
唯一胜者。

完成条件：目录校验通过；比较协议先于结果冻结；所有声称执行的候选有运行产物；主模型选择
可由证据复核；结论强度不超过证据等级；失败路线仍保留足够的挑战证据。否则
`BLOCK_MODEL_SELECTION`。
