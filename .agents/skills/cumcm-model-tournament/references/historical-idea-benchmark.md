# 历史题独立思路冻结与遗漏评估

用于用户要求的历史题能力检验或优秀论文方法对照。只修改技能时建立协议即可，不自动启动解题、联网、创建模拟项目或改动共享规则。新题没有同题参考时，只执行结构查漏，不虚构官方推荐。

## 1. 先声明测试范围与接触情况

- `idea_only`：只检验候选思想覆盖，冻结方案即可进入对照；不要求代码、数值结果或 PDF，不计为完整求解盲测通过。
- `full_solution`：完整求解盲测，继续遵守 `../../cumcm-blind-benchmark/STAGE.md` 的完整产物冻结与独立评估要求；候选快照不能替代答案冻结。
- 记录已读材料和当前上下文中的同题接触：`no_known_exposure`、`exposed` 或 `unknown`。参考正文、摘要方法、答案、历史项目、题型示例和已读对照报告均可能带来泄漏；更换任务或清空上下文不能抹掉已知接触。
- `no_known_exposure` 只表示可审计会话中未发现接触，不能证明模型训练中从未见题。已接触或无法确认的题标为开发/回顾样本，仍可查漏，不纳入干净的前向覆盖统计。

## 2. 参考开放前保存原始方案

在当前工作目录内的专用评估子目录保存 `独立候选方案.md` 和 `思路冻结清单.json`，不得覆盖已有快照。逐问方案至少含题意口径、关键结构查漏、候选方程或规则、假设、算法职责、验证设计、未解决问题，以及拟采用/排除的理由。

清单记录：测试模式、题目标识、接触状态及依据、冻结时间与时区、题面/附件和方案的路径与实际 SHA-256、已读来源、尚未开放的参考范围、skill 版本标识或已加载规则的哈希。缺少文件或哈希无法核验时，不称为冻结成功。哈希用于检测修改，本身不能证明从未接触参考。

冻结前只用题面、附件和不含同题解法的通用材料；检索索引也需避免读取同题摘要。首次打开参考前复核快照哈希并记录开放时间。思路测试的这一开放点是独立模式的例外，不放宽完整求解盲测。若之后继续求解，后续成果标为参考后开发。

## 3. 对照的是数学作用，不是算法名称

冻结后读取匹配题目的参考模型正文与关键推导，逐条标明文件、页码/章节、实际阅读范围。摘要或目录只能定位线索，不能单独证明关键命题成立。尽可能比较不同路线；只有一篇时明确样本局限，不凑论文数量。

区分官方题面、可核验的官方讲评、获奖论文和其他解答；获奖或官方收录不等于方法被官方唯一推荐。参考之间冲突时列出假设与证明差异，不按票数裁定正确，也不照抄参考结论。

在 `关键思想对照.md` 中逐项记录：分问、参考思想及来源锚点、它解决的障碍、适用条件、冻结方案证据位置、判定、影响、原因与修复建议。判定取：

- 独立覆盖：冻结方案已有实质关系，不能只命中术语。
- 等价替代：路线不同，但能在同口径下完成相同任务；列出映射或证据，未经验证只记“待核实等价”。
- 部分覆盖：想到方向，但缺决定性条件、分支或推导。
- 实质遗漏：缺少影响可行性、精度、证明或计算代价的思想。
- 不适用/参考存疑：参考依赖额外假设、改变题目或缺少证明；说明理由。

算法名不同不算遗漏，算法名相同也不算覆盖。将参考中的替代路线按功能归组，避免重复计数。报告适用关键思想总数、各类数量和逐问关键遗漏，候选阶段只评价覆盖与理论可行性，不打数值准确性分。任何覆盖比例都附分母、样本范围和待核实项，不能据高比例宣布达到国一水平。

## 4. 保留原结果，再提炼通用教训

原快照保持不变；参考后方案另存版本，新增思想标注来源和引入时间。分别报告独立方案的遗漏与参考后修订情况，修订后的高覆盖不能回填成原始能力。

把遗漏原因具体分为题意漏读、结构未识别、条件未证明、分支漏检、数值路线不当或验证不足等。在 `通用推理改进建议.md` 写“触发线索 → 应追问的问题 → 应给证据 → 不适用条件”，不把同题答案、专属参数、固定模型链或算法配方写入通用 skill。

规则修改遵循当次授权；未授权时只留建议。经授权提炼后，用另一道未读参考的留出题或独立构造的小实例检查迁移，并保留不适用/反例，避免把某道题的技巧强制用于所有题。没有新测试时标“规则已更新、迁移效果未验证”。完整求解测试的隐藏参考仍由隔离评估者处理，不用本协议绕过既有隔离。
