# A/B 题创新与模型组合

用于生成候选、试算择优、整理创新贡献和审查贡献证据。A/B 是适用语料范围，具体方向由题目
对象与数学结构决定。创新可以在建模前提出，也可以发生在模型构造和算法求解中；不按题号、
模型数量或算法名称认定创新，不设每问创新配额。

## 1. 两种探索入口

- **题目驱动**：从作用机制、观测方式、几何关系、状态演化或决策要求提出新的建模角度，
  写出可计算关系、参数来源和预期优势，随后用常规路线、特例或独立实现验证。
- **瓶颈驱动**：定位现有模型或求解的误差、约束、复杂度、稳定性瓶颈，提出针对性改造。

基线用于判断增益，不是创新候选的准入许可。无需等待基线失败才探索；在比赛预算内先做
能区分候选的小试算。理论可行且有题目依据的想法可进入候选，但不能提前声明改善已实现。
基线已满足硬门槛时，新方法仍可凭有实际价值的额外收益入选；收益相当时选更简单的路线。
不因方法新颖而降低守恒、约束、数据来源、验证或结论认证要求。

用户要求减少同质化时，先在既有关键结构查漏或求解计划中指出最值得探索的核心难点及理由，
从题面线索推到关系、候选和可推翻它的小试算；不得先读取同题解法再倒填线索。基础问无需
人为制造差异。共享物理规律、经典算法和题面直接要求的约束照常使用，方法常见本身不是缺点。

复用 `求解/模型竞技场.json` 的预算：每个实际探索分支写明待检验收益、最小判别实验、所需
时间/资源、截止或停止信号，以及届时保留的可行基线。预算按剩余赛时和验证成本确定，不给
每问固定创新数或无限扩展候选。超时、关键假设不成立或收益不足时停止该分支，保留失败证据；
无独立验证的中间优势不得挤掉已验证基线。基础答案、最终独立验证和提交时间必须有预留。

## 2. 三层创新及验证责任

| 层次 | 题目特定改造示例 | 应提供的证据 |
|---|---|---|
| 建模视角 | 用能量或临界条件描述物理过程；坐标变换；事件驱动描述；等价状态压缩 | 原描述到新描述的映射、保留的信息、假设与适用条件；特例、守恒、观测或独立路线验证；证明简化未丢失题目所需答案 |
| 模型结构 | 状态相关或时变约束、分段机理、过程耦合、风险进入决策、观测关系改进 | 方程和参数依据；与常规结构的公平比较；约束满足、预测或决策表现、敏感性与失效条件 |
| 求解算法 | 传统算法的结构化加速、自适应离散或步长、专用编码与邻域、可行性修复、精确与启发式分解 | 改动的步骤、伪代码及实现；与原算法和适用基线同预算比较；误差、耗时、可行率、稳定性及必要的模块对照 |

动态约束必须写清“何种量随时间、状态或决策变化、依据何在、何时可知”。例如设备容量随
温度与磨损状态变化，需有相应演化关系及参数依据。把题面明确给定的时变上限写入模型属于
正确建模，不能仅凭“动态”二字认定贡献；不得通过收紧可行域制造更好求解结果而隐去限制。

智能算法和传统算法都可以改进。调度编码保持工序顺序、几何搜索用碰撞结构设计邻域等，须
解释为何减少无效搜索。通用初始化或算子叠加可作候选，但不能凭名称声称适配或增益。
标准方法在本题中的有效适配可称为题目层面的贡献；未经独立文献核查不得声称学术首创。

## 3. 模型组合的成立条件

先区分现实关系的模型、负责计算的算法、检验结果的验证方法，三者并用不自动构成模型融合。
每个组合说明模块职责、输入输出及单位、共享状态或参数、执行顺序；有反馈时说明迭代与
停止条件。核对上游误差如何传入下游、决策时的信息是否可用、是否重复使用信息或计算收益。

例如“不良率估计 → 检测与拆解决策 → 独立情景验证”：估计层交付参数及其不确定性，决策层
使用当时可获得的信息，验证层检验未用于选择策略的情景。不能只把三个方法名称连接起来。

对影响贡献判断的模块，比较移除、简化替代或完整组合，说明它带来何种独立收益和额外成本。
模块可分离时可比较基线、单项改造和完整组合；强耦合无法单独运行时选有意义的替代方案，
记录不可拆原因，不强制无意义的全组合实验。没有收益的模块删除或仅保留为独立验证。

## 4. 公平比较与误差归因

试算前声明主指标、判据、数据划分、预算和停止条件，结果出现后不倒改标准。必须区分：

- 模型预测误差：对独立观测或可信参考的偏差；
- 数值误差：离散、积分、迭代与容差造成的误差；
- 优化解质量：可行性、目标值及相对可信界或精确解的差距。

目标值更好不能直接归因为物理预测更准。算法比较尽量固定模型、可行域、数据、硬件与并行
资源；模型改造比较采用统一外部评价口径，改变风险约束时同时呈现风险与成本，不能只比较
不同口径的目标函数。两层同时改动时分别对照或明确无法分离归因。

按贡献选择同等总耗时、同等目标评估预算或达到同一精度所需时间；记录实际耗时及评估次数，
迭代次数下降不能单独证明加速。初始化、预处理、修复、局部精修和调参成本需说明是否计入，
双方采用一致口径。随机方法用预先指定的多次独立运行，报告分布、失败率和不确定性，不能
只选最好一次；调参数据与最终验证分开。必要时用小实例精确解或界校准，保留全局最优声明
原有证据要求。实测收敛曲线改善不能自动升级为理论收敛率证明。

## 5. 机制指纹、新颖性与比较范围

建模与算法改造均先区分声明等级，不把题目适配直接写成学术首创：

- **题目特定适配**：改造由本题对象、约束或数据结构触发，证明它在本题中有职责和作用；
- **可复现实质改进**：相对明确基线在同一预算下取得稳定的精度、速度、可行率、稳健性或解释收益；
- **有限范围内的文献新颖性**：只有完成相应文献与语料核查后才可谨慎使用，附检索日期、范围
  与限制；有限检索不能证明绝对首创、方法独占或所有参赛队伍都未使用。

关键候选在试算前建立简短“机制指纹”，沿用竞技场和贡献表中的候选 ID。相对明确的常规参照
逐维写清改变了什么、未改变什么，不把空项自动视为差异：

| 维度 | 指纹内容 |
|---|---|
| 模型表示 | 目标与交付、状态/变量、尺度或坐标、核心关系；映射后是否只是等价改写 |
| 约束机制 | 活跃约束、边界/事件、可行域和信息时序；哪些来自题面、哪些是额外假设 |
| 观测关系 | 观测到参数或状态的映射、使用的信息、估计或识别条件 |
| 不确定性 | 随机源/参数区间、误差传递、风险与保守性；无此项时注明题目依据 |
| 求解机制 | 分解、更新/搜索算子、可行性修复、自适应、组合顺序、停止规则和计算预算 |

物理机理相同并不禁止不同表示、观测处理或结构化求解；反之，算法名字不同但指纹相同，不算
异构挑战或独立贡献。换符号、变量排序、随机种子不制造方法差异。指纹重合时合并重复候选、
删除无职责模块或降低创新声明；正确的常规方法仍可被采用，不能为了避重强行淘汰。

比较记录注明已比较来源与机制、来源接触时间、差异及未覆盖范围。来源开放依模式执行：

- **真实当届竞赛**：只比较独立产生的当前候选、允许的通用文献与既有方法知识；不得为避重
  检索、访问或讨论当届解题平台、当届公开方案或其他队伍方案。自己的思路/结果冻结之后仍
  禁止，也不能让其他代理代为获取。官方题面、附件与官方澄清不属于解答平台。
- **历史题能力检验**：同题优秀论文、历史项目与答案在独立方案或完整求解按相应协议冻结后
  才开放；已接触材料如实标记，不回填为独立发现。见 [历史题协议](historical-idea-benchmark.md)。
- **赛后研究**：在任务授权范围内开展文献与公开方案比较，准确标注来源，不冒充赛时独立成果。

未完成外部文献核查时，只能写“针对本题的改造/适配”或“在本试验设置下观察到的改进”。
其他队伍的路线与比例默认未知，不能根据模型名流行程度推算“撞方法概率”，不能声称与其他
GPT 方案不重复。比较旨在发现内部套路复用、无效堆叠和有证据的题目适配，不证明全世界不存在同法。

若把改造写成赛题后续研究或学术成果，至少补做“已有优秀论文/公开方案综述—不足定位—新方案—同口径比较”
四步核查。全国组委会 2026 年后续研究通告把“与已发表的相关论文比较，模型或算法要有创新”作为研究成果
说明的一部分；这支持更严格的比较要求，但不等于竞赛答卷必须声称学术首创。竞赛论文默认使用前两级声明，
第三级只在文献和碰撞范围足够时谨慎使用。

## 6. 贡献记录与成文

沿用 `求解/创新贡献表.md`，每个实际探索的贡献记录：

- 对应问题、层次（可多选）、题目依据与常规参照；
- 具体改造、方程或算法位置，以及预期作用机制；
- 比较协议、运行产物、实测收益与不确定性；
- 新增成本、组合必要性（适用时）及适用边界；
- 状态：待验证、已支持、未支持或不采用，及其理由。

在首次方法与结果确认前，将表中影响主路线的选择压缩为文件顶部的“方法差异简报”，并向用户
展示；复用后文证据锚点，不新增一批重复文件。每项包含以下内容，可用短表或紧凑段落：

- 对应核心问题、常规路线与适用性；我们的路线及改变的机制指纹维度；
- 题面依据、关键数学关系/待证条件，为什么该差异可能影响答案；
- 预先声明的公平比较、实际运行证据、收益及不确定性、额外成本与失效边界；
- 采用/保留基线/不采用/待验证及原因，比较覆盖范围与未知范围。

明确区分“已支持的改进”和“因正确可靠而采用的常规方法”；无改进成立时直接写明，仍可提交
方法结果供确认。队员核验状态初始为“待队员核验”，只有真实队员反馈可记录核验内容和结论；
不得由 AI、自检脚本或另一代理自动填写“人工已核验/用户已确认”。

未获得支持的设想留在内部记录，不包装成贡献。没有创新贡献但正确完整的常规解可以通过，
不得为填表强造改进。正文以对象、数学关系和结果说明贡献，保留证明它所需的对照表或消融图，
不搬入整份候选淘汰清单，不统一套用“改进型多模型融合”标题或每问相同的创新段落。
审查只能核对证据与声明是否一致，不能由方法名、模块数量或语言得分自动认定创新程度。
