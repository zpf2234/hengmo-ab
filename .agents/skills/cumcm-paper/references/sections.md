# 逐章写作规范

## A053 对照形成的版块职责链

以下只模仿功能推进和信息密度，不复用原文句式、同题模型名称、专属符号、数值、图号或代码。
当前项目的章节总顺序仍固定为“问题重述—问题分析—模型假设—符号说明—模型的建立与求解”。

| 版块或问题角色 | 默认推进结构 |
|---|---|
| 摘要 | 统一对象与主线 → 逐问目标 → 模型特有关系/方法 → 求解动作 → 最终定量答案 → 最关键验证或边界；核心问写得更长，过渡问压缩 |
| 问题重述 | 对象与直接背景 → 衡量任务好坏的现实判据 → 共同结构、数据与条件 → 按原题顺序列出各问输入、约束和输出 |
| 问题分析 | 本问任务 → 数学或计算转化 → 决定路线的关系/难点 → 实际求解链 → 本问输出及其向后传递的对象 |
| 模型假设 | 外部环境与扰动 → 研究对象的理想化 → 过程起止、边界或响应时机；只保留后文真正使用的假设 |
| 符号说明 | 全局参数 → 必要索引与状态变量 → 几何/统计/决策量 → 单位；局部量留到对应公式附近定义 |
| 基础状态或机理问 | 对象几何/物理关系 → 基本方程 → 联立或递推关系 → 离散与求解 → 关键状态表图 → 趋势和机制解释 → 精度/灵敏度 |
| 临界、碰撞或可行性问 | 先证明或限定检查范围 → 构造边界/几何对象 → 建立判定准则或指示函数 → 搜索首次临界状态 → 展示整体与局部构型 → 临界前后对比 |
| 单变量或边界优化问 | 讨论极限情形 → 确定决策变量 → 写目标函数 → 逐条给约束来源 → 汇总完整模型 → 粗到细求解 → 相邻边界与反例复核 |
| 复合路径或分段过程问 | 拆成不能混写的子任务 → 推导共享几何/机理 → 消元或降维优化 → 按区域/时段分类状态 → 递推求解 → 用轨迹解释异常或突变 |
| 最大能力或上限问 | 继承前问状态映射 → 写最大化目标与硬约束 → 选择简单搜索或智能算法 Step 链 → 输出上限及活跃约束 → 用枚举、复算或多起点独立核验 |
| 实验推断与方案设计问 | 数据体检与关系探索 → 正式显著性或效应估计 → 建立响应关系 → 在实验范围内优化 → 由不确定性、缺口或最优区设计新增实验 |
| 序贯决策问 | 统一状态、动作、资源和收益 → 已知信息下建立透明基线 → 信息不完备时增加转移或信念 → 多主体时加入相互作用 → 比较策略与基线 |
| 空间测量与布设问 | 修正并固定局部几何定义 → 推导平面或局部覆盖关系 → 升级到连续地形场 → 确定方向与布设 → 复核漏测、重叠和路径代价 |
| 不确定性反馈问 | 估计不确定参数 → 在点估计下形成初始决策 → 用样本更新分布或区间 → 把区间端点/情景送回原决策模型 → 比较策略是否改变 |
| 结果与验证 | 展示答案 → 读出关键数值/构型 → 解释形成原因 → 与临界前后、替代路线或独立方法比较 → 给出适用范围和该问结论 |
| 评价、改进与推广 | 已展示证据支持的优点 → 触发失效的条件及受影响结论 → 针对性改进 → 保留机制并替换输入/约束的推广 |
| 参考文献与附录 | 正文实际引用的方法/数据来源 → 支撑材料清单 → 按问题排列完整代码 → 环境、输入输出和运行方式 → 补充长表、推导与诊断 |

逐问开头可用一个紧凑段落交代整条路线，复杂算法或分支较多时再接流程图；后文按上述结构展开。
路线概述与详细建模承担不同职责，但不得逐句重复。每一问不必同时命中表中所有节点，按题型删去
不适用环节，不能为了模仿A053虚构证明、优化、智能算法或验证。

### 当前论文必须落地的对应结构

上表不是只供分析时参考，而要在标题树、逐问深度清单和单一总稿中实际体现。落地时遵守以下对应关系：

| 我们的章节 | 必须靠拢的功能推进 | 成文形态 |
|---|---|---|
| 摘要 | 统一主线 → 逐问目标与本题关系 → 方法和求解动作 → 定量答案 → 决定性验证或边界 | 各问自然成段，核心问允许更长，不用相同句式和相同字数 |
| 问题重述 | 对象与直接场景 → 现实判据或任务触发条件 → 共同数据/条件 → 各问输入、限制和输出 | “问题背景—问题提出”两节；分问只用段内加粗，不另占小节 |
| 问题分析 | 任务 → 数学转化 → 决定路线的关键关系 → 实际求解链 → 向后传递的状态、参数或方案 | 每问一个二级标题、一个到数个自然段；不提前放完整推导和结果 |
| 模型假设 | 环境边界 → 对象理想化 → 过程边界或响应时机 | 一个连续编号列表，不把理由、检验和题面事实写成假设 |
| 符号说明 | 全局量 → 索引/状态 → 决策与评价量 → 单位 | 一张主符号表；局部量在对应公式前后定义 |
| 各问建模求解 | 本题特有推导 → 完整模型 → 数值求解 → 结果解释 → 独立验证/边界 → 直接作答 | 问题层用简短二级标题，每问按需要设置 0--3 个三级标题，不把七项职责机械拆成七节 |
| 评价改进 | 证据支持的优点 → 明确失效条件 → 对症改进 → 保持机制后的迁移 | 可用连续段落或少量二级标题，不凑固定优缺点条数 |
| 附录 | 支撑材料清单 → 按问题排列的完整程序 → 环境与运行方式 → 补充长表/推导 | 数字附录“附录1、附录2……”连续排列，不用字母附录 |

在第五章成文前，先根据问题依赖中心性、本题特有推导量、求解风险、题面输出重要性和验证负担，
判定每问属于核心问、支撑问或过渡问，再从上表选择最匹配的问题角色链。核心问完整展开关系推导、
约束来源、求解精度、结果机理和验证；支撑问写清其独立贡献；过渡问可以短，但不得省略最终作答。
这些角色只控制内部篇幅路由，不作为论文标题或正文术语出现。

逐问标题不预制为“模型建立—算法求解—结果分析—模型检验”四连标题。问题层默认写“问题一”
“问题二”；三级标题优先使用“受力分析、运动方程、参数辨识、数值求解、误差分析”等短小自然表达。
复杂的职责链留在内部规划和正文中，不压缩成长标题。标题数量由论证转折决定，而不是由模板决定。

上述题型链还执行三项条件门槛：临界、碰撞、边界优化和能力上限问先给出搜索范围成立的依据，
再进行数值搜索；边界优化和能力上限问在最优点报告活跃约束、其余约束余量或乘子，并比较邻域点及
至少一个界外反例；凡后问调用前问结果，开头明确传递的是状态、参数、可行域还是约束，并核对单位、
有效数字和定义口径。三项内容都应自然进入本问推导或验证，不另设“范围证明门禁”“继承审计”等内部标题。

### 不同题材优秀论文补充校准

下表来自本地优秀论文中五类差异较大的样本。只吸收逐问承接方式，不复用其模型组合、变量、句式、
数值和章节标题，也不把样本中较弱的验证方式照搬进当前论文。

| 题材与样本 | 实际可迁移的推进链 | 对本项目的约束 |
|---|---|---|
| 波浪能机理与功率优化（A171） | 瞬态运动方程 → 线性情形解析等效 → 非线性情形数值优化 → 增加转动自由度形成耦合模型 → 网格或遍历复核 | 先把共享物理状态求稳，再按“线性是否仍成立”分流；解析路线能解决时不强加智能算法，新增自由度时明确继承原运动状态和约束 |
| 催化实验统计（B026） | 数据关系与缺失值 → 因素效应检验 → 响应函数拟合 → 约束优化及限定温度分支 → 针对数据缺口和最优区补实验 | 实验题按“探索—推断—预测/优化—实验设计”推进；新增实验必须回答前文尚未辨识的效应或验证最优区，不能只凭高拟合度宣布可靠 |
| 沙漠序贯决策（B175） | 规则量化与状态压缩 → 天气已知的动态规划 → 天气未知的 MDP → 多玩家博弈 → 与单玩家策略对照 | 后问只沿题面新增的信息缺失或主体交互升级；上一问的状态、动作和收益作为基线，不能为每问任意更换状态口径 |
| 多波束空间测量（B477） | 修正覆盖定义 → 局部几何推导 → 均匀平面布线 → 实际地形连续化 → 分区路径规划 → 漏测/重叠复核 | 空间题先保证局部定义在斜坡等构型下仍有效，再从局部关系升级到地形场和全局路径；数据拟合只是几何计算的支撑，必须另查覆盖与路径结果 |
| 多阶段生产决策（B195） | 抽样估计次品率 → 单阶段决策 → 拆解与回流的多阶段递推 → 多零件推广 → 贝叶斯更新次品率 → 重新求解原决策 | 不确定性问不能停在画分布；必须把更新后的参数区间送回前面决策模型，报告策略是否改变及改变边界 |

为防止“逐问并列、互不相干”，`question_architecture` 除角色和职责链外，还要从以下五类中确定本问
相对前问的主要升级轴：`mechanism-regime`（机理情形）、`information-state`（信息完备度）、
`actor-count`（参与者数量）、`spatial-fidelity`（空间真实性）或 `parameter-uncertainty`（参数不确定性）。
首问可记为 `foundation`，确无承接的问记为 `independent` 并说明原因。一问原则上只突出一个主升级轴；
若同时变化多项，先判断能否拆成先后两层，避免一次性把模型复杂化。

后问正文需要时再自然交代上一问留下了什么对象、题面新增了什么条件以及本问增加哪一层机制，
不把这四项写成固定路线段或标题。若题面条件没有改变且原模型仍足够，就沿用简单模型，只改变参数、
约束或求解范围，不得为了“有创新”硬换算法。

## 0. 摘要

摘要是独立阅读即可判断论文做了什么、得到什么以及结果是否可信的一页。
详细统计、结构与放行规则见
[../../cumcm/references/abstract-writing.md](../../cumcm/references/abstract-writing.md)。

每问至少包含：

1. 题目目标或核心困难；
2. 所选方法及必要理由；
3. 来自 `metrics.json` 的关键数值、单位和最终方案；
4. 一项验证、误差、稳健性或可行性证据。

首段给出统一建模思路，各问原则上独立成段；末段只在有跨问题验证或适用边界时设置。
避免公式、引用、背景铺陈、算法教科书介绍和“效果显著”等主观评价。摘要长度以实际
排版不超过一页为准；本地语料 Q1--Q3 为 950--1249 字符，只作软校准。

关键词整行采用黑体，标签与关键词内容均加粗；核心方法、最终答案和决定性验证数值可选择性加粗。删除“本文报告、
不声明、不构成证明”等评审元叙事，禁止出现 AI 提示词、工具名和辅助过程。

写作顺序：先从证据矩阵抽取每问四元组，再组织语言；禁止参考优秀论文句式后同义改写。

## 1. 问题重述

- 固定使用“问题重述—问题背景/问题提出”两级标题结构，其中“问题重述”为一级章，“问题背景”和“问题提出”为二级标题；
- 背景用一个紧凑段落交代对象、场景和任务产生的直接原因，不另写研究意义、文献综述或评价；
- 问题提出先概括共同对象与条件，再用段内加粗的“问题一：”“问题二：”逐问写清输入、约束、任务和输出；
- 分问不设三级标题，不强制换页；
- 先拆解题意再用自己的话重新组织，不沿用题面长句结构做机械同义替换；
- 不写分析、模型、算法、求解、结果、验证、评价、改进或推广，不大段复制题面。

问题重述与问题分析必须分别使用独立一级章；首次核心模型求解前还须完成
独立模型假设和符号说明。默认先假设、后符号；仅在符号定义是准确陈述假设不可缺少的前提时例外。完整架构规则见
[../../cumcm/references/paper-architecture.md](../../cumcm/references/paper-architecture.md)。

## 2. 问题分析

按“问题一的分析、问题二的分析……”逐问设置二级标题。每问依次说明决定处理方向的特征或约束、
原问题的转化思路、实际求解过程及其输入输出衔接；不把这些内容机械拆成三级标题。
求解过程只写关键计算逻辑和步骤关系，完整公式推导、参数表、代码与具体结果留在后续章节。

问题间存在共享输入、前后承接、并行汇合或反馈时，在逐问分析后给出一幅问题关系或总体求解流程图；
各问独立或短文字足够清楚时不画。关系图不得加入最终结果、评价、改进、推广或论文生产过程。
关系图与算法流程图分开判断，详细规则见
[../../cumcm/references/flowchart-routing.md](../../cumcm/references/flowchart-routing.md)。
只有流程确实复杂且正文会引用其关键节点时才画流程图；框数和布局按逻辑决定，不使用固定九框模板，
不把论文生产、文件生成和提交交付画成求解流程。
流程图采用白底、黑灰线、无圆角矩形、标准判断菱形和直箭头，默认不使用颜色编码；
不使用渐变、阴影、发光、装饰图标或卡片式布局。

本节禁止复述题面、提前写结论性数值、展示内部试错，以及使用“方法合理、效果良好、适用性强、
具有推广价值、便于理解”等开放性评价或无关过渡句。

## 3. 模型假设

- 模型假设独立设为一级章，正文仅使用一个连续编号列表，每项只写一条假设句；
- 全局假设不标范围；局部假设仅在需要时自然写明“在求解问题一时……”等适用范围，上下文清楚时可省略，不另设小标题；
- 假设的来源、理由、影响和检验安排只留在内部映射，不写入模型假设正文；句式不必机械统一；
- 假设必须必要、可检验且真实参与模型，不把题面事实、定义、计算设置或常识空话列为假设；
- 可能显著影响答案的内容应作为情景或参数处理，不轻易假设掉；
- 在检验、局限或敏感性章节回应关键假设；
- 默认把模型假设放在符号说明之前；例外必须说明结构理由。

## 4. 符号说明

- 符号说明独立设为第四个一级章，标题后直接放“符号｜含义｜单位”三列表；含义按内容写物理含义或数学含义；
- 全文通用符号集中列出，只服务单问或只出现一次的局部量在相应公式附近定义；
- 单位列不得为空，无单位项统一写“—”，不写“无量纲”；
- 同一物理量使用同一符号，同一符号不承担不同含义；
- 主符号优先简洁，能由上下文区分时不加下标，只在真实对象或编号需要时保留一层必要索引；
- 必要说明控制在一至两句，只陈述共同约定或适用范围，不评价符号体系、表格或模型；
- 删除无信息引导、阅读安排、代码变量、字段名和未使用符号。

## 5. 模型的建立与求解

每问按以下证据链组织，可根据题型合并小节：

### 5.1 口径与目标

明确输入、输出、决策变量、目标、约束、评价指标和与前问的依赖。解释歧义选择。

### 5.2 方法选择

只说明最终采用路线为何适合当前数据、约束和验证要求。不列算法对比表，也不展示候选方案、
选择/淘汰过程或内部试算。若复杂模型的升级确实需要论证，用紧凑段落写出决定性信息与理由；
落选路线可保留为内部独立复算，但不展开进正文。
模型由基本规律唯一确定时，只说明数值实现与挑战路线，不虚构候选模型。

### 5.3 模型建立

- 从定义或基本规律推到最终模型，保留读者复现所需步骤；
- 省略教材级通用推导，详细展开本题特有关系、约束和离散化；
- 每个变量在首次出现处定义，注明定义域和单位；
- 优化模型显式列出决策变量、目标函数和全部约束；
- 统计模型说明样本划分、损失函数、估计方法和防泄漏措施；
- 仿真模型说明随机机制、参数来源、重复次数和终止标准。

公式数量由推导需要决定。严禁为增加“数学感”拆分恒等变形或堆砌无后续用途的公式。
每个展示式优先承担一个主关系；真正的方程组、约束组和分段关系可合写，互不依赖的定义、目标与
结果应拆开。复合变换或长聚合先定义语义中间量，避免嵌套上下标和叠加修饰把推理压进符号。
核心式前说明对象或目的，式后解释结构、约束及后续用途，使读者无需反复回查符号表。
所有独立展示公式必须编号；引出句以冒号结束，公式末尾不留任何标点。
同一语义组内的并列坐标、约束或状态方程使用左大括号配合 `aligned`，整组共用一个编号；
普通推导不为形式统一强加大括号，各行末尾也不添加标点。

### 5.4 具体求解与结果

按真实执行顺序说明输入、变换或离散、初始化、参数求取、迭代更新、约束处理、停止条件和报告精度，
并写清相邻步骤传递的对象。说明求解方法、关键参数和容差。运行环境、命令、文件名和输出路径放入附录，不在正文展开。
结果表突出最终答案，图形展示趋势、空间结构、误差或权衡关系。

每一幅编号图和每一张编号表都要与正文形成合理交互，可用于呈现对象、支撑读数、说明关系、
推进判据或汇总答案。关键读数、形成原因和答案含义仍须在本问整体论证中交代，但不要求逐图逐表
套用固定分析段。

### 5.5 验证与稳健性

选择与题型匹配的证据：

| 类型 | 适合的验证 |
|---|---|
| 机理/几何 | 解析特例、守恒、边界、独立数值法、步长收敛 |
| 预测/分类 | 留出集、交叉验证、时间外推、残差、校准 |
| 评价 | 外部标准、排名一致性、权重扰动、指标删减 |
| 优化 | 约束复核、上下界、gap、多初值、情景分析 |
| 仿真 | 重复实验、置信区间、随机种子、样本量收敛 |

报告指标、阈值、结果与判定。ANOVA、正态性检验、交叉验证等只在统计条件适配时使用。
优化结果另报告可行性、界或近优证据；逆问题另报告可识别性和模型形式不确定性。仅有多初值
稳定、求解器 success 或较高拟合优度，均不足以证明答案最优或正确。

### 5.6 直接结论

结论直接承接结果、验证或不确定度，不设置“本问回答”“本文的回答”等标签。其他
`\paragraph{...}` 标题或列表项加粗短语只要承担引出下文的作用，统一以中文冒号结束。

用一段话直接回答题目，包含最终数值、单位、方案、适用条件和必要的不确定性。
该段应能与证据矩阵中的 claim_id 对应。
最终答案和核心指标采用克制的粗体强调，不加粗普通参数或整段文字。

## 6. 结果检验

各问的复算、对照、参数扰动和边界情形优先放在对应结果后，直接说明检验量、变化范围及结论是否改变。
只有题目确实需要跨问检验，且存在两类以上实质内容时，才设置紧凑的独立“结果检验”章。
不为算术核对、口径统一、证据边界或整条模型链的总结单独设章，这些内容写入审查文件。
若关键中间量被后续问题复用，只在误差确实可能改变最终答案时讨论传递影响。不得为满足章名伪造灵敏度实验。

## 7. 模型评价、改进与推广

- 优点对应真实贡献，例如新口径、简洁推导、验证强度或求解效率；
- 局限对应数据、假设、算法或外推边界，并说明可能影响；
- 改进必须针对局限给出可执行路线；
- 推广先说明哪些结构保持不变、哪些参数和约束需要重估。

不固定优缺点条数，不写“具有广泛应用前景”等空话。

## 标题命名补充

- 固定一级章仍使用“模型的建立与求解”；第五章问题层可直接写“问题一”“问题二”，不重复上级章名；
- 三级标题只展示一个中心，使用“受力分析”“运动方程”“参数辨识”“数值求解”等自然短语；
- 一级使用中文序数，二级使用两段编号，三级使用三段编号，目录不深入第四级；
- 每问按需要设置 0--3 个三级标题；连续内容直接成文，不为凑标题建立子模块；
- 第五章三级标题优先 4--10 个汉字，超过 14 个汉字时检查能否删去重复对象、方法清单、条件说明和程度词；
- 不在标题中写口径、审计、闭环、证据链、门禁、作答映射等内部说明；
- 5--15 篇参考文献、4--6 条假设和语料中的标题数量均只作规模参考，不设硬配额。

## 8. 参考文献

- 只收录实际阅读并在正文引用的真实文献；
- 优先原始方法论文、权威教材、标准和可信数据来源；
- 逐条核对作者、题名、年份、期刊/出版社和链接或 DOI；
- 采用当年要求或统一的 GB/T 7714 格式；
- 文献数量由论证需要决定，禁止保留模板示例或虚构文献。

2026 年先写 AI 工具使用声明，再写参考文献。声明按实际使用情况如实填写，工具不列入参考文献；
实际使用时，详细记录放入支撑材料压缩包中的 `AI工具使用详情.pdf`。声明和参考文献不强制各自
另起一页，保持紧凑连续排版。在声明与参考文献标题前分别保留 `\label{ai-statement:start}`、
`\label{references:start}` 作为顺序锚点。

官方正文页数以 `appendix:start - body:start` 计算，包含正文主体、AI 声明和参考文献，不含摘要与附录。

## 9. 附录

详细组织与复现门槛见
[../../cumcm/references/appendix-structure.md](../../cumcm/references/appendix-structure.md)。

附录必须：

1. 列出支撑材料文件名、格式和用途；
2. 写明实际运行环境、依赖、逐问命令和预期输出；
3. 按问题收录实际使用的完整可运行程序；正文不暴露代码入口、文件路径或运行过程；
4. 包含必要的长表、中间结果或参数文件说明；
5. 不出现身份信息、个人绝对路径、外部署名或省略号占位。

在附录标题处放置 `\label{appendix:start}`，供自动审计定位附录并执行其他合规检查。

从附录首页起不设页数上限。代码篇幅自然形成，不把附录页数作为质量指标。
