# CUMCM 人工学术排版档案

本档案用于本工作区的论文生成与审查。它来自用户逐页批注及本地 50 篇 A/B 题优秀论文的
结构采样，只学习共性，不复刻任何论文的文字、模型、图形或数值。

## 1. 标题与页面

- 使用一套连续的章节编号，标题层级、字号、段前后距全篇一致，不混用多套编号体系。
- 摘要单独占第一页；不设目录；正文保持连续、均匀的论证密度。
- 图、表、公式紧跟首次解释位置，不用放大图表或制造空白凑页。
- 分问章节之间连续排版，不在问题一、问题二的开头或结尾设置固定换页；AI 工具使用声明位于
  参考文献之前，二者不强制各自另起一页；附录从新页开始。

## 2. 摘要与结果强调

- 摘要按各问写明方法、关键结果和验证证据，禁止出现写作策略、审查过程或自我评价。
- 关键词整行采用黑体，标签与关键词内容均加粗；该字重属于首页指定格式，不与摘要正文的方法、结果强调混用。
- 粗体只承担“核心方法”与“最终结论”两种职责；最终结论可包含决定答案的数值、单位和
  不确定性，普通验证数字与中间参数不加粗。
- 摘要逐问统一使用 `abstractquestion` 环境控制段前段后距，不用连续空行或手工 `\vspace` 调版。
- 优先使用 `\keymethod{...}` 和 `\keyresult{...}`；正文最终答案使用 `\keyconclusion{...}`。每问原则上各突出一个方法和一个结论。
- 每句最多突出一组信息；整段粗体、连续多句粗体、孤立数字粗体或把中间参数全部加粗均不合格。
- 各问的最终结论直接承接结果或验证，最终数值采用与摘要一致的粗体形式；不得使用
  “本问回答”“本文的回答”等模板标签。
- 粗体以最终 PDF 的视觉字重为准。宋体无原生粗体时，关键词、核心方法和关键结果改用黑体或
  模板已配置的伪粗体；不得把无视觉变化的 `\textbf` 视为完成。

## 3. 客观技术表达

- 直接写模型结构、计算动作和数值事实，删除“便于、有助于、彰显、提升了表达效果”等
  价值判断。
- 删除“本文报告、不声明、不能据此宣称、不构成……证明”等面向评审或写作过程的元叙事。
- 不把“为何这样写”“如何规避风险”“评审要求整改”等过程放进摘要或正文。
- 正文主体不展示 AI、人工智能、提示词、prompt、AI 辅助脚注、工具名或生成过程。AI 信息集中放在
  参考文献前的独立声明，以及支撑材料压缩包内的 `AI工具使用详情.pdf`；AI 工具不列入参考文献。
- 问题重述与问题分析必须分成两个一级章；模型假设标题只写“模型假设”，不用“计算口径”。
- 删除“口径不一、统一口径、口径校准、去 AI 化、查重、AIGC”等只属于写作或定稿过程的表述；
  “口径”若为真实管径等题目对象，则按专业含义保留。
- 摘要和正文不出现附件文件名、工作表名、代码、程序、脚本、CSV、JSON、文件路径、
  运行命令、支撑材料或“完整程序见附录”。数据以材料、角度、场景或实验条件指代。
- 删除“满足问题一对模型建立和可计算性的要求”等面向任务清单或评审的自证句。
- 删除“前者回答……后者回答……”“不因……预设结论”等论证意图解说，直接写条件、判据
  和由数据得到的结论。
- 不写“首次出现处定义”“见下文定义”或“未在表中列出的量另行定义”等阅读指引；定义在
  符号表或变量实际出现处直接完成。
- 数值不确定性写成客观事实，如“前两名区间重合，差异不显著”，不写“因此本文只报告……”。

## 4. 展示公式

- 行内公式不编号；所有独立展示公式使用 `equation`、`align` 或带编号的同类环境。
- 禁止使用 `\[...\]`、`equation*`、`align*`、`gather*`、`multline*`。
- 引出展示公式的最后一句必须以中文冒号“：”结束。
- 公式右侧按全文顺序显示“（1）”式编号；正文引用统一写“式（1）”。
- 展示公式主体末尾不保留句号、逗号、分号或中文标点；编号后也不附加标点。
- 多行推导用一个带编号环境包裹 `aligned` 或 `split`，不要为每个恒等变形机械拆号。
- 同一语义组中的并列坐标、约束、状态方程或分段条件用
  `\left\{\begin{aligned}...\end{aligned}\right.` 统一组织，并共用一个编号；普通连续推导
  不机械添加大括号。`aligned` 中各行末尾同样不加逗号、句号或分号。
- `\paragraph{...}` 和列表项中的加粗短语若用于引出后续解释，末尾统一使用中文冒号，
  不使用句号。

## 5. 流程图

- 详细路由与门槛见
  [../../cumcm/references/flowchart-routing.md](../../cumcm/references/flowchart-routing.md)。
- 先区分问题关系、分题求解、算法迭代、数值计算和状态决策；只有复杂依赖、三个以上
  不可合并步骤或验证回退时，才用正式流程图替代纯文字罗列。
- 使用人工论文常见样式：白底、黑灰线、无圆角矩形、标准菱形判断、直角或直线箭头。
- 默认不使用颜色编码；禁止渐变、阴影、发光、卡片、装饰图标和大面积彩色底。
- 节点文字使用短动宾结构；流程必须与任务契约、脚本和回退逻辑一致。
- 不把任务契约、结果文件、Excel、支撑材料和结果交付等文件生产过程写入正文流程图。
- 导出 PDF/SVG 矢量图，并保留 `.drawio`、TikZ 或 Python 等可编辑源文件；插入论文前检查字体、箭头、边距和缩放。

## 6. 图表

- 图型由变量维度和待证明结论决定，不由 A/B 题号决定。
- 图数不设上下限，由待证明命题和不可替代证据职责决定；正文可以出现 4、6 幅或更多图。同一命题使用多图时，各图必须承担整体趋势、
  局部边界、空间构型、情景对比或诊断等不同/互补职责，重复职责的图合并或删除。
- 每一幅编号图和每一张编号表都必须由正文编号引用，并与相邻论证形成对象、读数、关系、判据或
  结论上的合理联系；不要求逐项套固定分析段。完全脱离上下文的“见图/表”转人工复核。
- 一维趋势只有在同时标出事件、阈值、边界、区间、基线或不确定性时才使用曲线；只有一条默认
  折线或一组默认柱形且表格更清楚时，不把它作为正式图。
- 优先黑、灰、蓝、红、绿等克制配色；同一变量在全文保持同色。
- 图题、坐标、图例和单位可直接阅读；不使用营销式配色或软件默认的无意义装饰。
- 单图不在绘图区放标题；两幅强耦合图可由总图题用“左/右”说明，三幅及以上或各面板条件不同
  时，在各面板下方居中放 `(a)(b)…` 小标题，再在整组下方放总图题。

## 7. A/B 题制图路由

本地 25 篇 A 题、25 篇 B 题优秀论文共抽取 760 条图号记录。分类只用于检查论证链是否漏图，
不能转化为每篇论文的图数或图型配额。

- A 题常见主链为“几何/物理机理示意—空间状态或轨迹—动态响应—验证图”。存在坐标系、
  受力、投影、遮挡、截面或装置关系时，应优先制作一张与模型定义同构的解释图。
- B 题常见主链为“数据或状态诊断—路线/空间方案—决策流程—拟合或敏感性验证”。调度、
  定位和路径规划类 B 题仍以空间图为主，不以统计图替代。
- 模型解释图先于结果图规划；没有解释变量、约束或关键结论职责的图不进入正文。
- 三个以上对象、变量或问题存在依赖时，先判断关系图、结构图或机理图能否替代长段说明；
  能明显缩短文字并提高定位效率时优先用图，简单列表和精确数值比较仍保留文字或表格。
- 热力图在本地语料中只占少数；仅当真实二维矩阵、空间场或双参数响应存在时采用。
- 高质量三维图在能增强空间理解、双参数响应、轨迹层次或核心结果展示时可以采用；提供可读视角、
  单位和图例，必要时再补投影，不把二维不可替代作为前置条件。

## 8. 制图软件与源文件

- TikZ：关系图、流程图、几何机理和场景示意的默认路线；正文段落、公式、符号和判停条件稳定后
  再按成稿生成，保留 `.tex/.tikz` 与矢量 PDF。
- Python（matplotlib）：工程曲线、三维轨迹、曲面、等值线、动态响应、统计诊断、批量数值图、
  结果复核和自动化；全部数据图的统一路线。
- Visio/draw.io：仅在对象很多、必须依赖图形界面做高强度人工编排时作为回退；登记不用 TikZ 的具体理由。
- 数值图必须由结果 CSV/JSON 或求解脚本生成；结构与机理示意图使用 TikZ，必要时回退 Visio/draw.io，
  不使用 PowerPoint/PPTX 作为正式源文件，也不手工移动数据点或改变数值几何关系。
- 图内公式和数学标签保持透明并放在线条周边；任何对象线、轨迹、轮廓、尺寸线和箭头都不得被文字遮断。
- 白底、黑灰细线为基底，最多使用一种低饱和强调色；避免渐变、阴影、发光、装饰图标、
  大面积彩底和模板化“AI 审美”。
- 几何示意图固定画布和纵横比，标注、箭头、尺寸线锚定对应对象；LaTeX 中仅等比例缩放，
  每次字体、图源或尺寸变化后检查成品是否压线、越界或错位。

## 9. 语料与工具观察

- 本地样本中 Word/WPS 占多数，LaTeX/XeTeX 也能产出优秀论文；工具不是评分项。
- 流程图常见 Office/Visio 式几何框，数值图常见 MATLAB/Python 式折线、轨迹和曲面。
- 仅复用上述排版原则，不追求模仿某个软件的像素外观。
