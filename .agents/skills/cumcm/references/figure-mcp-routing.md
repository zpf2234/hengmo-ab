# CUMCM 图形路由与插入契约

本规则把“是否需要图、使用哪类图、何时插入正文”与具体绘制分离。正式论文图依次经过
`paper-figure-router`、绘图路线、注册表与最终页面审查；不得先画图再为它寻找正文位置。

## 可用绘图路线

| 路线 | 职责 | 正式源文件 |
|---|---|---|
| `paper-tikz`（MCP） | 问题关系、算法流程、坐标、角度、尺寸、边界和公式几何 | `.tex` |
| `paper-visio`（MCP） | TikZ 规则布局仍不清楚且必须人工协作的复杂模块或状态图 | `.vsdx` |
| `python-matplotlib`（求解侧直接生成） | 时间响应、轨迹、曲面、参数扫描、收敛、敏感性和验证图 | `.py` 绘图脚本 |
| `paper-figure-router`（MCP） | 判断插图必要性、绘图路线、图型、正文位置与证据要求 | 路由 JSON |

TikZ、Visio 与 Python 路线均输出 PDF/SVG 矢量成品。数据图默认由求解侧 Python 代码直接生成，并复用
`figure_mcp/python_figure.py` 的统一风格与保存契约（白底、微软雅黑、蓝橙配色、固定物理画布，
禁止 `bbox_inches="tight"` 重排画布），并登记真实 renderer、脚本与结构化数据。Visio 还必须输出同名
`.layout.json`，并在实际论文宽度下完成视觉复核；未完成复核时 `publication_ready=false`，
不得进入正文。

调用 TikZ/Visio 前必须执行对应 MCP 的 `health_check` 并登记结果；Python 数据图直接运行求解侧脚本。配置中出现名称不等于实际可用。若 `paper-figure-router` 不可用，可以按本文件的确定性规则回退，但必须记录 `router_mode: deterministic_fallback`，不得伪称调用过路由 MCP。每图须登记 renderer、tool 或生成脚本、spec、provenance manifest；绘图路线可用不等于生成了合格图形。

PDF/SVG 必须核验为真矢量而非整页位图。Visio 合成 Python/TikZ SVG 时按源 `viewBox` 或原始宽高等比放置，`abs(output_ratio/source_ratio - 1) > 0.002` 直接阻断。Python/TikZ/Visio 图均须保留实际插入尺寸、整页、缩略和灰度渲染；Visio 使用 `record_visual_review` 关闭视觉门禁，复合图必须审查最终复合成品。

## 插图判定

调用 `route_figure` 前写清：章节、唯一待证明命题、对象数量、关系步骤、判断或反馈、几何约束、
数据维度、`figure_role` 以及是否与现有图重复。返回 `should_insert=false` 时保留文字、公式或表格，不调用绘图后端。

当同一命题同时含几何、判断和定量结果时，`figure_role` 是后端消歧硬合同：

- `quantitative_evidence` / `result` / `validation`：有受支持 `data_shape` 时路由到 `python-matplotlib`，保留真实轨迹、策略景观、光谱/拟合与不确定性数据几何；缺结构化数据时 fail-closed，不得用装饰性三维、TikZ 示意或 Visio 卡片冒充结果证据。
- `mechanism`：精确构型、光路、边界、切点和公式关系优先 `paper-tikz`。
- `algorithm`：判断、循环、回退、再生状态和多阶段流程默认优先 `paper-tikz`；只有契约明确
  `requires_manual_layout=true` 且给出充分理由时回退 `paper-visio`。

同一问题可规划 2--3 张不同职责的特色图，但每张只绑定一个不可替代的核心命题；不得借 `figure_role` 把重复面板伪装成不同证据。

- 摘要、问题重述、模型假设、符号说明、模型评价、参考文献和附录默认不插正式论证图，路由对这些章节直接拒绝。
- 问题分析章仅在三个以上分问或对象存在共享输入、输出或递进时插关系图，位置在依赖说明之后。
- 建模求解中，精确坐标或几何判据图放在对象与坐标定义之后、首个控制方程之前。
- 存在判断、循环、回退或状态转移，或有三个以上不可合并步骤时插 TikZ 流程图（与国一流程图门禁同口径，
  任一条件单独成立即可）；两三步的普通线性过程不画。
- 数据结果图放在首次需要它支撑对象、读数、关系或结论的位置附近。
- 验证图只展示误差、收敛、敏感性、不确定性或独立复算，不重复主结果图。
- 模型评价不新增装饰图；已有证据用文字概括适用范围与失效条件。

## 绘制与插入顺序

1. 从证据矩阵抽取唯一 `claim_id` 和待证明命题。
2. 调用 `paper-figure-router.route_figure`；记录是否插图、绘图路线、图型、正文位置和所需输入。
3. 按路由默认调用 `paper-tikz.render_geometry`/`compile_tikz`，满足回退条件时调用
   `paper-visio.render_diagram`，数据图直接运行
   Python/matplotlib 绘图脚本；Python 图将脚本、结构化数据、生成命令和输出哈希一并登记。
   - TikZ 需要局部放大时，优先在结构化 spec 中使用 `detail_inset`：必须提供 source ROI、inset
     位置/尺寸、放大比例和 inset 内原生矢量图元。ROI 与 inset 使用同一对象语义与颜色映射；禁止
     截图裁块、栅格贴片或白底公式图片。放大窗至少解释一个主图不能清楚读取的判据。
   - Visio 流程图固定使用 `visual_preset: cumcm-classic-orthogonal`，并按真实结构指定或自动选择
     `layout_variant`。风格不再逐图确认；允许创新的是本题特有的并行汇合、阶段、分支、反馈和机理对应，
     不得把某题节点、坐标或教科书算法流程硬编码进预设。
   - **GGB 几何源与 `paper-tikz` 清洗中间件（Sanitizer Contract）**：将 GeoGebra (GGB) 或外部图形工具导出的切点、可行域或物理机理路径传入 `paper-tikz` 编译前，必须先执行提纯过滤：① 把坐标精度统一舍入至 **2--3 位有效小数**；② 去除多余的 `\clip rectangle` 裁剪区域及临时色彩（如 `ududff`、`uuuuuu`）；③ 将图元样式与标签分离并映射到 `cumcm` 统一样式表，避免生成臃肿代码或文字重叠碰撞。
4. Visio 正式图使用 `strict_audit=true`，每条边填写 `id`、`kind`、`meaning`、方向和分支文字；
   节点文字写入形状自身，普通框透明填充、直角轮廓，判断框使用标准菱形，颜色不承担流程语义。
5. 在原尺寸、论文宽度、缩略图和灰度视图复核。Visio 用 `record_visual_review`关闭视觉门禁；
   TikZ/Python 数据图按对应审计脚本登记可读性、矢量性和数据追溯。
6. 写入 `审查/diagram-registry.json` 或 `审查/figure-registry.json`，再运行风格审计。
7. 图与正文形成自然交互：相邻文字至少能看出图在当前论证中承担的对象、读数、关系、判据或结论；
   不强制固定的图前、图后说明顺序。

## 流程图视觉约束

- 默认白色画布、透明节点、深灰蓝线与黑色文字；不使用颜色编码、渐变、阴影、图标或大面积填充。
- 主轴方向由语义版型决定；“否”分支放在主轴一侧，反馈以实线沿画布外缘回到真实更新节点。
- 普通步骤使用直角矩形，起止使用胶囊形，判断使用标准菱形，真实输入输出使用平行四边形。
- 每个节点一至两行、单一字号，文字与框为同一对象；不采用“大标题+小字说明”卡片。
- 分支文字靠近对应第一段连线，不压菱形、箭头或节点；所有箭头终止于目标边界。
- 公式、变量、阈值和分支文字全部透明，放在对应线段周边；所有连线、轨迹和箭头连续可见，
  不得为文字留断口或使用白色遮罩。
- 自动布局失败时允许显式提供坐标和路径，但仍须逐连接审计，不得用屏幕拖动修正数值几何。
- `cumcm-classic-orthogonal` 禁止阶段徽标和焦点卡片；仅真实阶段使用原生矢量蓝色虚线框。
  连接审计通过后仍要在论文实际宽度和 25% 缩略图检查主轴、判断、反馈和输出。

## 特色主视觉图的多后端组合

特色图仍先经过插图判定，并先选 `visual-identity-and-archetypes.md` 中的证据原型。需要复合表达时，允许以下可验证组合：

- Python/matplotlib 负责数值几何、曲线、场、等值线和统计分布；
- TikZ 负责精确几何、公式关系、局部放大和尺寸/阈值标注；
- Visio 只负责高层结构编排和可编辑版面，不重绘或手工移动数值点；
- 单一路线能完整表达时优先单一路线，禁止为了“混合多软件”增加无意义流程；
- 复合图必须登记每个面板的 renderer、源文件、viewBox、最终比例和组合顺序，并审查最终复合页；
- 特色图采用共享视觉身份：白底、深灰文字、冷蓝主色、青绿辅助、单一橙红结论色，但同一变量的颜色仍以全文语义一致性优先。

## 失败处理

- 路由判定不需要图：删除候选图，不以美观为由保留。
- 后端生成成功但审计失败：修改结构化 spec 或样式规则后重跑，不在导出文件上手工补丁。
- 图与正文结论不一致：以证据为准，回到结果或模型阶段；不得改动数据点迎合文字。
- 改变字体、画布、连接、标签或插入宽度：重开图形门禁和引用章节门禁。
