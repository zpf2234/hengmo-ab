# A/B 题流程图路由与审查

所有获准流程图还必须执行
[../../cumcm-diagrams/references/fixed-flowchart-style.md](../../cumcm-diagrams/references/fixed-flowchart-style.md)：
视觉固定为 `cumcm-classic-orthogonal`，只按内容选择语义版型，不再逐图讨论视觉风格。

本规则来自本地 25 篇 A 题、25 篇 B 题优秀论文的新版逐图普查。复核后保留 69 幅真正
的流程图、技术路线图或算法迭代图，覆盖 23 篇论文，平均每篇 1.4 幅。统计用于路由，
不构成每篇图数配额；是否画图由待证明命题及相对文字、公式、表格的信息增益决定，未画流程图
不等于论文不优秀。

## 功能分类

| 功能 | 数量 | 典型职责 |
|---|---:|---|
| 主要模块与计算逻辑框图 | 25 | 说明状态量、模块输入输出和共享计算关系 |
| 分问题建模与解题流程 | 24 | 说明某一问从输入、建模到答案的关键步骤 |
| 算法与优化迭代流程 | 17 | 说明搜索、更新、判停和回退 |
| 总体研究与技术路线 | 2 | 说明各问依赖、共享模型和递进关系 |
| 业务调度与控制流程 | 1 | 说明状态转移、调度动作和控制分支 |

该分布说明总体路线图很少，优秀论文更常为具体模块、问题或关键算法画图。A/B 题号只提供
经验先验，最终仍按问题结构选择。

## 先判功能

1. 各问存在共享模型、前后依赖或递进关系时，可画**问题关系图**。节点写问题对象、输入输出
   和复用关系；没有条件判断时不使用菱形，不伪装成算法流程。只保留共享模型与问题递进，
   不附加统一验证栏、总结口号或与关系图职责无关的信息。
2. 某一问包含至少三个不可合并步骤，或存在分支、循环、回退时，普通优秀稿可画**分问题流程图**；
   国一/国奖模式必须画。若一段三句以内的短文字即可完整表达且无上述复杂结构，可记录豁免理由，不为凑图画流程。
3. 仅当算法有题目特定改造、非平凡判停、约束修复或多阶段筛选时，画**算法流程图**。
   标准差分进化、粒子群、模拟退火等教科书流程不得作为装饰复述；应突出本题修改部分。
4. 数值离散、网格推进、边界处理或独立复算决定结果可信度时，画**数值计算流程图**。
   节点应能对应代码函数、循环或判定。
5. 业务状态、调度动作或决策路径本身就是模型对象时，画**状态/决策流程图**。
   状态、动作、条件和收益口径必须与模型变量一致。

一张图只承担一种主要职责。不要在同一图中混合问题关系、算法细节、论文写作、文件生成和
提交交付。尤其禁止用“题面整理—任务契约—结果表—Excel—支撑材料—结果交付”替代数学
模型或算法逻辑。

## 结构规则

- 主方向只选从上到下或从左到右；反馈边沿外侧以实线回绕，避免穿过节点和交叉。
- 处理步骤用矩形，判断用标准菱形，真实输入输出用平行四边形；胶囊形起止框只在确有开始/结束语义时使用。
- 真正的算法或控制流程应设置明确输入/开始与结果输出/结束；问题关系图不强制起止符号。
- 每个判断节点至少有两条出边，所有出边在箭头附近标“是/否”或具体条件。
- 每条箭头必须与真实执行方向一致：主轴指向下一步骤，判断分支指向对应结果，反馈回路指回
  被重新执行的节点。边界接对但方向或语义错误仍按错误流程处理。
- 节点使用短动宾结构，优先写“生成候选轨迹”“计算遮蔽区间”“检查约束余量”，不写长段
  解释、文件路径、工具名称或评审话术。
- 每框只保留一个动作、条件或输入输出，通常一至两行；统一节点字号与字重，不用“大字标题
  + 小字补充”的卡片式写法。阈值依据、变量解释和步骤理由由图前后正文承担。
- 图中变量、阈值、循环上限、候选数和判停条件与脚本一致；正文说明关键分支为何回退。
- 图中字体、字号和箭头族统一；分支标签放在离开判断节点后的第一段连线附近，连接端点吸附节点边界。
- 复杂算法优先拆为“总体关系图 + 关键算法图”，不把五个问题和所有验证压进一条长链。
- 图题说明对象与动作，如“问题五离散模式筛选与连续复核流程”，不用“总体流程图”空泛命名。

## 人工学术风格

- 白色画布、透明节点、深灰蓝细线，不依赖颜色区分步骤；同类节点保持同一字重和尺寸。
- 使用普通矩形、标准菱形、直线或正交箭头；不使用渐变、阴影、发光、图标、卡片和大面积彩底。
- 框体尺寸按最长文字确定，文字水平和垂直居中；主动换行，不让文字贴边、压线或溢出。
- 框体和文字必须是一个形状对象，不得在空框上叠放独立文本框；连接线必须吸附边界锚点。
- 同时执行 [diagram-layout.md](diagram-layout.md)，导出同名 `.layout.json` 并在论文实际
  插入宽度下复核。缺布局报告或依赖 LaTeX 裁边的流程图不得进入正文。
- 同时执行 [diagram-connection-audit.md](diagram-connection-audit.md)，逐条登记主轴箭头、
  判断分支和反馈回路。箭头端点、条件文字和节点间距任一失败时，不得用整图“基本清楚”放行。
- 插入正文后的最小字号原则上不低于 8 pt，关键节点不低于正文小五号的可读水平；缩放后
  逐页渲染检查，不以源文件中的字号代替成品检查。
- 同层节点对齐、间距一致，反馈线贴外边缘；人工调整留白和节奏，但不手工改变数值关系。
- Office/Visio 风格在本地语料中常见，但其中也有控制点残留和连接瑕疵，不作像素模板；图的正确性和可读性优先。

## 构图与节奏

- 先确定一条可在两秒内识别的主轴，再安置判断与反馈。短算法链优先横向，多层程序条件优先纵向，
  关系图使用横向分层；具体按固定版型路由，不要先铺满框再补箭头。
- 主轴通常保留 5--8 个关键节点。支路节点放在主轴一侧，反馈线沿画布外缘回到明确节点，
  形成“主线稳定、局部不对称”的人工构图。
- 起点和输出可用圆角矩形，普通步骤保持直角矩形，判断保持标准菱形。圆角只表达语义，
  不把每个节点都做成卡片。
- 节点宽高由文本和层级共同决定；全图最多使用两档主要宽度。短文字不得塞入横跨页面的
  巨型空框，也不把不同长度的节点机械压成同一比例。
- 相邻主节点间距保持一致；判断节点前后可略增留白，侧向更新节点与主轴之间保留一段清晰
  的水平箭头。回路线不贴框、不贴页面边缘。
- 线宽只设主线与辅助线两级，箭头大小一致。辨识度来自闭合回路、对齐、留白和本题特有的信息结构，
  不来自彩色、阴影、图标、渐变或装饰标题。
- 在缩略图视图下应先看见主轴、判断和回路，再看见文字；若只能看见一排同宽大框或密集
  文字，构图应重做。

## 工具与源文件

- 默认用 TikZ 制作关系图和流程图并保留可编辑源；对象极多、规则布局仍不清楚且团队需要图形界面
  协作时才回退 Visio/draw.io，并登记理由。正式结构图不使用 PowerPoint/PPTX 作为源文件。
- Python 可用于由配置自动生成流程图，但必须人工调整版式并保留脚本；不得用默认网络图主题。
- 终稿使用矢量 PDF/SVG。`求解/图表清单.md` 必须记录图的职责、来源脚本或可编辑源、
  关键分支和论文位置。

## 审查门槛

- 流程图与脚本步骤、条件、循环、判停或回退不一致：P1。
- 用文件生产、支撑材料或交付流水线替代模型/算法逻辑：P1。
- 标准算法教科书流程与本题无改造、正文不引用其节点：P1。
- 判断分支未标条件、多个功能混在一图或关键算法被“问题一至五”空框代替：P1。
- 图表清单无登记、无可编辑源或无法定位对应脚本：P1。
- 箭头交叉、缩放后文字过小、节点拥挤或留白失衡：P2；影响理解时升为 P1。
- 仅因章节名为“求解流程”就强制插图，或重复绘制同一流程：P1。
