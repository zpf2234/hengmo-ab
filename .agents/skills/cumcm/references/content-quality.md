# CUMCM 国一等奖候选内容审查

本规则用于把“内容达到高水平候选稿”落实为逐段检查，不以篇幅、标题数或术语数量代替质量。
审查只使用题面、项目证据和真实来源，不模仿优秀论文的文字与结构。

## 前置顺序

正文进入核心模型前，默认采用：

```text
问题重述 → 问题分析 → 模型假设 → 符号说明 → 核心模型
```

问题重述与问题分析必须分别使用独立一级章。模型假设默认置于符号说明之前，先交代模型
成立的物理边界，再集中定义后文使用的符号。模型假设标题不得附加“计算口径”。
只有当符号定义是准确陈述假设不可缺少的前提时，才允许先写符号说明，并在结构审查中记录理由。

## 摘要语义强调

- 先从证据矩阵提取每问的“方法—结论”主轴，再补必要目标、核心数值和可信度证据。
- 粗体只承担两类语义：`核心方法` 与 `最终结论`。普通参数、中间数值、过程动作、背景词和
  验证细节保持常规字重。
- 优先使用 `\keymethod{...}` 和 `\keyresult{...}`，使生成与审查能够区分强调职责。
- 每问原则上各突出一个方法和一个结论；需要额外强调时必须说明其不可替代性，禁止连续粗体、
  整句粗体和“数字墙”。
- 最终结论可以包含决定答案的数值、单位和不确定性；不得只加粗脱离语义的孤立数字。
- 摘要不得出现 AI、人工智能、提示词、prompt、工具名、生成过程、辅助写作、审查策略或
  “作为语言模型”等文字。AI 合规信息只进入规定的独立声明与支撑材料。

## 最少充分标题

- 标题只在读者需要新的论证入口时出现。连续推导、同一模型的参数估计、结果解释和直接结论
  优先在一个小节内用段内引导语组织。
- 第五章问题层默认使用“问题一”“问题二”作为二级标题；每问按需要设置 0--3 个三级标题。
  推导、求解、验证和回答是正文职责，不把它们批量变成标题清单。
- 需要独立综合验证章时默认 2--4 个二级标题；跨问题证据较少时合并为一节。模型评价、
  改进与推广默认 2--3 个。不得把每一种误差、每张表、每条结论各拆成一个标题。
- 三级标题只在同一二级标题下存在至少两个并列且内容充实的子模块时使用；不为单个公式、
  单个判据或半页以下内容建立三级标题。
- 标题使用短名词或短动宾结构。第五章三级标题优先 4--10 个汉字；超过 14 个汉字时检查能否
  删除方法清单、条件说明、程度词和重复对象。
- 标题总数没有奖励。自动审查把正文二级标题超过 24 个、单个问题章超过 5 个二级标题列为
  合并告警；题目确有复杂结构时可保留，但必须在审查报告说明理由。

## 逐段内容审查

逐段标注主要职责：定义/口径、推导、求解、证据、结论、边界。一个段落若没有明确职责，
或只重复前文，应删除或合并。

每问沿以下链条反向审查：

1. 题面要求是否被准确转成变量、目标、约束和输出；
2. 方法是否由问题结构推出，是否说明不用更简单路线的理由；
   若存在实质候选，正文中的取舍是否与冻结的模型选择证据一致；
3. 推导是否保留本题特有步骤，并给出定义域、单位与边界；
4. 参数、阈值、初值、步长和停止准则是否有来源；
5. 结果是否直接回答原问，精度与单位是否适当；
6. 验证是否独立于主求解，包含指标、阈值、结果和判定；
7. 答案是否通过题面闭环、可行性、数值分辨率、替代路线挑战和不确定性/最优性检查；
8. 假设、模型、实现、图表、正文结论和摘要是否一致。

任一结论若不能定位到结果文件、图表或推导，列为 P0/P1；任一方法若只在标题或摘要出现而
未在公式、实现与验证中兑现，列为 P1。
存在实质模型竞争却没有选择证据，或把“稳定”误写为“全局最优”，列为 P1。

## 国一等奖候选放行

- 内容审查不得只读标题和摘要；必须逐节阅读正文，并抽查公式前后、表图解释和各问直接结论。
- 摘要与正文逐词检查附件文件名、代码、程序、脚本、CSV、JSON、文件路径、生成过程、
  运行命令、支撑材料和机械附录引用；任一命中须删除或改为对象化数据指代。
- 至少随机选择一个问题，从题面要求反向追踪到代码、结果、验证和摘要结论。
- 删除教科书式常识、重复结论、空泛价值判断和为凑页设置的异常留白。
- 删除解释论文如何被阅读或某段“回答什么”的元叙事，包括“前者回答……后者回答……”、
  “不因……预设结论”“首次出现处定义”“见下文定义”；直接保留定义、判据、证据和结论。
- “高水平候选”要求题意与口径、模型适配、数学严谨、验证强度、结果价值和写作原创六项
  均达到评分卡 4 分以上；任何 P0/P1 未关闭时不得使用该结论。

审查后写 `审查/内容审查.json`，至少包含：

```json
{
  "pass": true,
  "sections_reviewed": 9,
  "total_sections": 9,
  "full_text_read": true,
  "abstract_method_result_emphasis": "PASS",
  "assumptions_before_symbols": "PASS",
  "heading_merge_review": "PASS",
  "question_chains": {
    "问题一": {"model": "PASS", "result": "PASS", "validation": "PASS", "answer": "PASS"}
  },
  "p0_findings": [],
  "p1_findings": [],
  "p2_findings": []
}
```

`sections_reviewed` 必须等于 `total_sections`，`full_text_read` 必须为 `true`。该文件不能用
自动脚本凭空生成；它记录人工逐节审查结果。
