# 优秀论文语料对标协议

优秀论文库用于校准质量，不用于复刻内容。开始求解前、论文成稿后各执行一次：

```bash
python .agents/skills/cumcm/scripts/benchmark_corpus.py --root .
python .agents/skills/cumcm/scripts/benchmark_corpus.py --root . --fail-on-similarity
```

默认从 `最终效果/高教杯优秀论文/` 读取 PDF，输出
`审查/优秀论文对标.json` 与 `审查/优秀论文对标.md`。
若该目录包含 `普查总索引与统一口径.md`，同时读取
[full-paper-census.md](full-paper-census.md)，优先使用已复核的全文脉络、分项 CSV 和
OCR/人工抽检边界，不再从旧版“标准模板”报告推导硬规则。
题名缺失或 PDF 无文本层时，先用 [corpus-map.json](corpus-map.json) 的显式映射选取同题语料；
未命中映射时再使用题名相似度。新增赛题或重命名语料后同步更新该映射。

## 使用边界

- 只学习结构特征：问题覆盖方式、论证链长度、图表职责、验证类型、正文与附录的比例。
- 不复制标题、摘要句式、段落、图注、专属模型链、参数、结果数值、代码或图形设计。
- 不因参考论文使用某算法就默认采用该算法；方法必须由题意、数据、约束和验证条件推出。
- 不把页数、图数、表数、公式数当成越多越好的目标。图数由待证明命题和不可替代证据职责决定；
  官方限制优先，语料统计只作区间参考。
- 同题论文只用于发现评委会追问什么，不作为答案来源。独立完成口径、推导、代码和数值验证。

## 邻近样本选择

质量对标优先选 3-5 篇（`--top-k` 只控制质量样本，不控制原创性扫描范围）：

1. 同赛道（A/B）且同类问题；
2. 数据结构或核心约束相近；
3. 方法路线不同，能暴露替代解释；
4. 年份分散，避免把单年排版习惯当成普遍规则。

若题目文件名无法判断 A/B，允许不分赛道并在对标报告中标记。

## 只提取这些特征

- 总页数及附录起始位置的近似值；
- 图、表编号数量；
- 是否出现误差、灵敏度、稳健性、收敛、残差或约束验证；
- 各问题是否都有“模型—求解—结果—验证—回答”；
- 摘要是否覆盖每问、关键数值与最终决策。

PDF 文本层异常时，把图表与验证统计标为不可用；需要时再做 OCR 或人工抽查，不把零计数当成论文真实特征。
候选或任一语料含不可读取、空白/稀疏页、替换字符或提取错误时，明确登记未覆盖范围。
不能因其余页面有大量文字、其余语料可读或人工写了 `pass` 就宣称完整比较。补做 OCR 后须重新扫描；
若只能有限人工抽查，保留“文字覆盖未完成”的残余风险，不能获得本地自动门禁 PASS。

将观察写成当前项目的“质量预算”，例如“至少需要一次独立数值交叉验证”，不要写成
“必须复现参考论文的第 X 图或第 Y 个模型”。

## 原创性门槛

原创性扫描与邻近样本选择独立：对指定语料目录**顶层每一篇 PDF、跨 A/B 赛道**计算摘要 8 字符、
正文 12 字符和全文 12 字符 n-gram containment。正文/全文比较无条件运行，不以摘要分数、
摘要最相似论文、题名相近程度或 `--top-k` 触发。`me/` 等嵌套工作稿目录不自动纳入优秀论文库；
报告逐篇列出实际来源与覆盖状态，不能把这一本地目录称为全网或正式查重库。

正文在可识别的首页关键词行之后开始，在有足够前置正文且非目录页的独立参考文献/附录标题前结束；
边界不确定时保留全文，并报告回退口径。此分段只为减少长附录对正文重合的稀释，**全文仍独立比较**，
不会因识别边界而从审计中删除后面的文字。当前候选的同一路径（含解析后的符号链接路径）排除；
不同路径但字节相同的材料不自动排除，视为需调查的高风险重合。

每个指标的最高值独立取自全部语料，不要求来自同一篇。内部预警带为：

- 摘要 `<0.15` 且正文、全文均 `<0.10`，覆盖检查完成且无连续长段预警：可通过本地文字预警门禁；
- 摘要 `0.15-0.30`，或正文/全文 `0.10-0.20`：人工检查实质复用、规范引用和必要术语；
- 摘要 `>=0.30`，或正文/全文 `>=0.20`：高风险，审查阶段直接 FAIL；
- 总体比例低但定位到连续至少 80 个规范化字符重合：仍进入人工检查，不能靠长正文稀释局部复制。

指标以候选的去标点、小写化字符 n-gram 集合作分母，仅用于本地预警，不是知网重复率、AIGC 比例、
抄袭事实裁定、方法独占保证或正式查重通过承诺。它不识别语义改写、图形/代码复用或其他队伍方案。
处理实质复用时应独立重建论证或正确引用，不能仅换词、改符号、拆句以规避检测。
脚本不上传稿件；如需外部正式检测，应先确认平台、数据处理方式与用户上传授权。

### 覆盖与可定位证据

报告 `schema_version=2`，`candidate_pdf.path/sha256` 与 `originality_gate.candidate_pdf_sha256`
绑定本次读取的候选 PDF 字节。PDF 更新后必须重跑，不接受旧版仅摘要 PASS。
另以 `audit_basis_sha256`（报告顶层和 `originality_gate` 同值）绑定候选字节、算法/阈值版本、
覆盖状态、逐篇语料哈希、分项指标与重合定位；不含运行时间和绝对路径，因此迁移项目不凭空失效。
同一候选遇到语料增删、PDF 更新、OCR 修复或提取证据变化时，旧人工复核失效，必须按新证据复核。
`corpus_source` 同时记录真实语料目录、`discovery=top_level_pdf_files_all_tracks` 和
`members=[{path,sha256}]`。消费者每次重新枚举同范围文件并核验哈希，同时核对其与
`similarity.per_reference` 的来源映射一致；语料新增、删除、改动、目录不可用或快照缺失时，
不能沿用旧报告的 PASS。移动目录后需重新生成带当前真实路径的报告，不能只修改快照绕过审计。

`similarity.coverage` 至少包含 `scope=all_local_corpus_pdfs`、
`discovery=top_level_pdf_files_all_tracks`、`eligible_count`、`compared_count`、
`complete`、`candidate_complete`、`incomplete_references`、`excluded_self`。
不可读 PDF 仍计入 `eligible_count`，不会被静默删除；任一必测文件不完整即 `complete=false`。
参考论文未识别到首页摘要时只把其摘要指标写为 `null`，正文/全文仍比较，不因参考格式不同判定全文提取失败；
另报 `abstract_compared_count` 和逐篇 `abstract_available`。候选摘要缺失仍阻断候选审查，不能替代正式摘要。
这里的“完整”只表示**页面级文本层启发式未发现缺口**，不证明所有扫描图、公式和字词都被提取，
也不等于整篇原创性得到证明；稀疏的纯图页可能保守触发复核。

`similarity.per_reference` 逐篇保留路径、PDF 哈希、抽取引擎、页数/每页有效字符数、稀疏页/错误、
正文边界、三个实测指标和 `overlaps`。重合位置使用双方 PDF 物理页、提取块号及块内规范化字符区间；
块号不是原稿自然段号。每篇最多给出 5 处、每侧最多 160 字符片段，按定位到的连续长度排序，
是人工定位线索而非全部重合的穷举清单。

兼容键 `max_containment` 仍表示全库最高摘要指标，`full_text_containment` 表示全库最高全文指标，
新增 `body_containment` 表示最高正文指标；不可计算时写 `null` 而不是零。三个 `closest_*` 字段可能不同。
消费者使用 `originality_report_issues(report, paper_path)` 验证 v2、当前 PDF 哈希、覆盖和裁定，不自行
把 `WARN_REVIEW`、部分覆盖或历史报告重新解释成 PASS。

### 门禁退出码与放行条件

`benchmark_corpus.py --fail-on-similarity` 是阶段 3 的原创性门禁。它把裁定写进
JSON 的 `originality_gate` 字段（`verdict` / `status` / `reasons` / `enforced`），并按裁定返回退出码：

| 退出码 | 裁定 | 含义 |
| --- | --- | --- |
| 0 | `PASS` | 相似度实测执行且落在可接受带 |
| 0 | `PASS_WITH_MANUAL_REVIEW` | 落在人工检查带，且有独立评审的 `pass` 记录 |
| 2 | `FAIL_HIGH_SIMILARITY` | 达到高风险线，人工记录一律不得放行 |
| 3 | `BLOCK_ORIGINALITY_UNPROVEN` | 原创性未被证明 |

退出码 3 覆盖的「未证明」状态：候选论文缺失/损坏、论文无可提取文本层、抽不到摘要正文、
语料目录缺失或为空、任一候选/参考文件部分提取、人工检查带无有效复核记录或复核绑定已过期。这些状态不能返回 0，
即把「没测」读成「通过」，属本项目禁止的 fail-open。未加 `--fail-on-similarity` 时裁定照样写入报告但不阻断，
以便阶段 0 在论文尚不存在时完成语料校准。

人工复核记录写在 `审查/原创性人工复核.json`（独立文件，因为 `审查/优秀论文对标.json` 每次运行都会被重写）：

```json
{"pass": true, "reviewer": "<独立评审标识>", "reviewer_type": "ai", "scope": "<实际抽查页码/参考来源及处置理由>", "date": "<YYYY-MM-DD>", "candidate_pdf_sha256": "<当前候选 PDF 的 SHA-256>", "audit_basis_sha256": "<本轮审计依据 SHA-256>"}
```

先运行审计取得重合位置与依据哈希（此时阻断或使用非阻断校准模式），评审实际核对后填写记录，再原样重跑。
`reviewer_type` 如实填 `ai` 或 `participant`：独立 AI 可作内部文字复核，但不能冒充参赛队员最终人工核验。
`pass` 为真但缺具名评审、实际范围、日期、当前候选哈希或审计依据哈希，不构成放行依据；
`pass=false`、候选变化或审计依据过期均阻断。
报告以 `manual_review_file={path,sha256}` 绑定真实复核文件。对于 `PASS_WITH_MANUAL_REVIEW`，
消费者必须重新读取这个文件，校验其当前哈希、完整记录内容、`pass`、具名身份类型及候选/依据绑定；
撤回、删除或任何改动后，旧报告内嵌的 `manual_review.pass=true` 不能继续放行。普通实测 PASS
不依赖无关人工记录。文件变更后若要重新放行，应按真实记录与当前来源重跑生产端审计。
该记录只对**覆盖完整的人工检查带**有效，对高风险、未运行或部分提取状态无效。
改动后运行 `selftest_similarity_gate.py --no-write` 与 `selftest_originality_consumers.py --no-write`；
回归至少覆盖摘要不同正文复制、正文来源不是摘要最高者、top-k 外/跨赛道复制、附录稀释、空库/缺稿、
部分提取、坏 PDF、候选自身排除、当前哈希绑定和合法人工复核，不能用这些合成测试证明真实论文原创。
