# A/B 题附录组织与复现门槛

本规则来自本地 25 篇 A 题、25 篇 B 题优秀论文的附录普查。页面补查后，50/50 篇存在
显式附录或以 A/B 等字母直接进入的等价补充材料；附录页数 Q1/中位数/Q3 为
10/16.5/28，平均 23.2 页，A 题平均 21.5 页、B 题 24.8 页。既有自动分类识别出程序代码、
支撑数据、补充图表和少量长推导；类别数量可能受扫描页漏识别影响。页数仅反映语料分布，
附录从首页起不设页数上限，也不以接近均值为目标。

## 组织顺序

1. **支撑材料索引**：列文件/目录、格式、对应问题、用途和正文结论；不把审查内部文件
   当作竞赛论文的主要学术支撑。
2. **运行环境与复现命令**：写语言版本、核心依赖、必要工具箱、随机种子入口、逐问命令
   和预期输出。
3. **按问题或功能收录代码**：公共内核在前，问题一至问题末问主程序依次排列；每节标题
   写对象、任务和语言。
4. **辅助核验**：只收录确实用于正文验证的诊断、复算或模板检查程序。
5. 支撑材料包同样保持整洁：只放规则要求或复现确实需要的文件；大型原始数据、完整迭代日志、
   JSON 检查记录和冗余中间文件留在内部工作目录。题目明确要求提交的 JSON 或运行必需配置除外。

## 正文与附录的边界

- 正文不得出现“完整求解程序见附录 B”、代码入口、文件路径、运行命令或支撑材料名称。
- 附录每个问题模块可设置稳定 `\label{app:q1}` 等标签，用于附录内部组织。
- 代码标题、文件名、问题编号、图表清单和证据矩阵保持一致。
- 附录不能承接正文不可缺少的核心推导；正文必须独立形成模型—结果—验证闭环。

## 代码真实性与排版

- 只收录实际运行版本，不用伪代码、截图、删节号或“此处省略”。
- 源代码必须能从原始数据或官方模板生成正文关键结果；随机种子、容差和步长可定位。
- 使用 8--9 pt 等宽字体、原生可搜索文本、行号和自动换行；不得出现右侧截断。
- 代码注释以参赛者实际调试和复现需要为准：保留关键公式、边界处理、非显然参数和易错步骤的
  短注释，不为每个函数机械套“输入—输出—对应公式”模板，不逐行翻译代码，也不使用长分隔线、
  口号式标题、对话语气或“下面将”等生成式措辞。变量与函数名按当前对象自然命名，不能通过
  随意改名、拆句或堆注释伪装原创。
- 代码不得出现姓名、学校、学号、联系方式、无关赛号、博客署名、AI 生成提示或个人绝对路径。
- 全部代码很长时可以完整收录，因为附录不限页；不得用原始数据和重复日志恶意扩页。

## 工具经验

语料中 MATLAB 出现 36 篇、Python 16 篇、C/C++ 各 9 篇，另有少量 Lingo、SPSS 和
Stata。工具频次不构成优先级；应选择当前项目真实使用且可复现的环境。

## 放行检查

- 有显式附录入口、支撑材料索引、运行环境和逐问复现命令；
- 正文不暴露代码模块、文件路径或运行过程；
- 附录代码文件存在、可搜索、无占位删节、无身份和外部署名泄露；
- 代码运行结果与正文、官方模板和内部冻结结果一致；
- 最终压缩包不含 `metrics.json`、任务契约、证据矩阵、注册表、布局记录、检查报告、日志、
  缓存、临时文件、测试文件和废弃版本；题目明确要求或程序运行必需的文件除外；
- 渲染抽查首个代码页、最长代码页和附录末页，无越界、黑块、过小字号或断裂标题。
