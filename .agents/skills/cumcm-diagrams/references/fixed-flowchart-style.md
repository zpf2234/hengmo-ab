# CUMCM 固定流程图风格与语义版型

## 数学符号零白底规则

- 一切变量、公式、概率、角度、点名、边长、阈值和分支条件均使用透明背景；TikZ 明确写 `fill=none,draw=none`，Visio 文本标签关闭填充。
- 含数学符号的流程节点内部同样不填白，只保留节点边框。不得用白色矩形、白色文本框或页面同色贴片遮住连线。
- 标签与连线冲突时，只允许移动标签、改变连线路径、增加真实留白或使用短引线；禁止以任何背景遮罩制造“看似没有压线”的效果。
- 所有主线、支线、回路线和箭头必须连续可见；标签只能放在对应线段周边，不得在线路上挖空、截断或覆盖线条。
- 审查报告必须同时满足 `white_node_fill=false`、`transparent_node_fill=true`、`math_labels_transparent=true`、
  `line_continuity_unmasked=true` 与 `labels_outside_line_paths=true`。

## 人工构图检查

- 每个节点只承担一个真实动作、状态或判断；正文解释、方法理由和长段参数说明不得机械塞入节点。
- 先确定主链，再安排局部分支和反馈；回路必须回到真正被更新的步骤，不能仅为了版面对称随意接回。
- 节点宽高按语义分组人工统一，换行按短语边界确定；禁止让自动换行把变量、否定词、数值与单位拆开。
- 判断节点写可直接回答“是/否”的条件，分支词靠近离开判断框的第一段线；不使用脱离本题参数的空泛算法模板。
- 正式导出前以参赛者视角逐节点朗读：若节点不像人在讲解实际求解过程，或删去题目变量后可原样套到任意题，则必须重写。

本文件冻结用户确认的论文流程图基线。适用于算法流程图、程序流程图、问题关系图、模型结构图、
状态决策图与分阶段求解图。今后不再逐图询问配色、圆角、线型或总体视觉风格；只确认节点文字、
判断条件、连接方向和最终渲染是否正确。

## 固定视觉基线

- 预设名固定为 `cumcm-classic-orthogonal`，`style_confirmation_required=false`。
- 纯白画布，不保留编辑软件网格；所有普通节点默认透明填充，只保留轮廓。
- 中文正文采用宋体/思源宋体一类稳定衬线字体，数学变量采用论文数学字体或 Cambria Math。
- 文字近黑，节点轮廓与箭头采用深灰蓝；除分阶段虚线框外，不靠颜色区分流程语义。
- 普通步骤用直角矩形，判断用标准菱形，真实输入输出用平行四边形，真实开始/结束用小型胶囊形。
- 连线使用细实线、统一箭头和正交折线；反馈线沿主链外缘回绕，默认仍为实线。
- 只有真实阶段分组才使用蓝色虚线外框与小型阶段标题；虚线不得用于普通反馈或装饰。
- 禁止阴影、渐变、发光、图标、编号徽章、焦点色卡、异常红框、彩色节点、灰色网格和大面积底色。
- 图题与编号交给 LaTeX；图内不重复标题。
- 节点内部默认透明；分支标签、概率、公式、点名和短注释必须透明，不生成白底贴片。标签与线冲突时
  先移到线段周边净空区或调整折线路径，不能靠白块盖线；线条从起点到终点始终连续，不为标签留断口。
- 图内普通文字成品以 9--10.5 pt 为主，最小不得低于 8.5 pt；通栏流程通常取 14.5--16 cm 宽，
  高而窄的流程可取 8--11 cm 宽且不超过 `0.80\textheight`。
- 默认由 TikZ 统一生成字体、节点和箭头；Visio 只在注册表给出充分回退理由时使用，但仍执行同一预设。

## 固定语义版型

`layout_variant` 由内容自动选择，不以题号、算法名称或“看起来高级”为依据。

| 版型 | 适用结构 | 构图规则 |
|---|---|---|
| `horizontal-mainline` | 线性求解、PSO/迭代主链、短算法链 | 左到右主链；判停后结束；反馈从上方或下方回到真实更新节点 |
| `horizontal-feedback` | 有一至两个判断与闭环的算法 | 主链左到右；局部分支在主链一侧；反馈走外缘，不穿框 |
| `vertical-branching` | 时间步进、程序逻辑、多层条件分支 | 上到下主干；左右只承载条件支路；底部汇合后从外侧回到时间更新 |
| `layered-dependency` | 输入—中间量—输出、变量推导、系统关系 | 左到右分层；同层并列；共享输入与汇合输出使用正交汇流 |
| `objective-constraint-fusion` | 目标函数与多个约束共同定义优化模型 | 左侧对象进入中部“目标/约束”并行层，再汇合到优化与求解输出 |
| `phased-groups` | 粗搜—细化、阶段一—阶段二、分时域算法 | 每阶段用蓝色虚线框；框内仍遵循主链和标准形状；跨阶段箭头只连接真实交接量 |
| `hybrid-evolution` | 遗传/群智能中纵向算子栈与横向判停并存 | 变异、评估、复制等局部可纵排，判停与输出横排；回路回到种群更新节点 |
| `mechanism-assisted` | 流程旁必须解释几何、采样或碰撞机理 | 流程为主，旁置一个克制的原生矢量机理小图；两者用真实变量或对象对应，不做装饰拼贴 |

默认选择顺序：真实分阶段优先 `phased-groups`；目标与约束并行优先
`objective-constraint-fusion`；多层程序判断优先 `vertical-branching`；一般模块依赖优先
`layered-dependency`；含闭环的短算法优先 `horizontal-feedback`；其余使用
`horizontal-mainline`。`hybrid-evolution` 与 `mechanism-assisted` 只在确有相应语义时使用。

## 创新边界

允许并鼓励的创新是“解释责任创新”，包括：

- 把本题特有目标、约束、状态、判停和回退组织成新的依赖结构；
- 将粗搜—细化、基线—挑战、状态—决策或机理—算法放在可追溯的同一证据链中；
- 用局部机理小图、阶段框、并行汇合或非对称分支解决本题真正的理解难点；
- 让图中变量名、阈值和节点动作与本题模型严格对应。

不属于创新：换颜色、加图标、加阴影、给节点编号、套某算法教科书模板、无数据地拼接曲线或
为了“高级感”增加无意义分支。固定风格保证整篇论文一致，结构创新保证不同题目不会同质化。

## 直接确认清单

生成后只做下列确认，不再重新讨论风格：

1. 节点、目标、约束、判断条件与正文模型一致；
2. 每条箭头的源、目标、方向、标签和回退位置正确；
3. 版型与真实语义匹配，没有为了套版型制造阶段或分支；
4. 白色论文画布、透明节点、标准形状、正交细实线、无装饰元素；
5. 所有线条连续无缺口，公式和文字均在对应线路周边且不压线；
6. 原尺寸、论文最终宽度与 25% 缩略图均可读；
7. PDF/SVG 为真矢量，TikZ/Visio 源可编辑，连接审计全部通过，复核不是只看 OCR 文字识别。
