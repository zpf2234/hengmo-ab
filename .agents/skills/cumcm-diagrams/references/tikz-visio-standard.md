# TikZ / Visio 风格结构图与数学几何图标准

## 数学符号透明约束

所有数学符号和公式标签一律无填充、无白色背景；即使位于有边框节点内，节点也只保留轮廓。
线段、曲线、轨迹、轮廓、尺寸线和箭头必须连续绘制，不能因文字而截断或留出遮罩缺口；标签移到线路周边，
与线保持净距，必要时用短引线锚定。该约束优先于旧模板中的白色节点填充和在线标签设置。

本标准用于问题关系图、算法流程图、状态图、机理图和数学几何图。最终视觉只允许两类：
`tikz` 或 `visio`。两类都必须是白底、矢量、克制、可编辑、可追溯；“Visio 风格”不是默认
Office 彩色主题，而是精确对齐、基础形状、正交连接和清楚留白。

## 路由

优先 TikZ：

- 坐标、长度、角度、圆弧、投影、切线、视线束与公式需要严格对应；
- 节点和连接可由规则布局，需与 LaTeX 数学字体完全一致；
- 图后续会随符号、公式或变量名称一起修改。

Visio 回退条件：

- 模块关系、业务状态、算法主轴、控制分支或多层系统框图经 TikZ 规则布局后仍需高强度人工调整；
- 图形对象多但数学坐标比例不是结论；
- 需要团队成员在图形界面中继续编辑。

因此关系图、流程图、几何图和公式结构默认先用 TikZ；选择 Visio 时在注册表写明上述哪一项成立，
不得仅因 Visio 操作熟悉或优秀论文常见 Office 风格而回退。

复杂图可由 TikZ 生成精确几何内核，再在 Visio 中仅编排外围模块；最终必须保留两份源并说明
哪个源决定数学位置。不得在 Visio 中手工改变数值轨迹、角度、交点或曲线。

## 共同视觉语言

- 画布白色；主文字 `#202124`，主线 `#3F454B`，辅助线 `#7A828A`。
- 唯一强调色默认冷蓝 `#355C7D`；危险、违反约束或唯一异常可用暗红 `#B44C43`。
- 全图颜色不超过 4 种，线宽只设主线与辅助线两级。
- 流程图中文用宋体/思源宋体等稳定衬线字体；数学变量使用 LaTeX 数学字体或 Cambria Math，不能混用多个数学字体。
  数据图与几何图可按其专属规范使用黑体，但同一图内不得混搭。
- 最终 PDF 中正文节点 8.5--9.5 pt，关键节点 9--10 pt，轴名和点名不低于 8 pt。
- 禁止阴影、发光、渐变、拟物图标、圆角卡片系统、大面积彩底、灰色网格背景和装饰标题条。
- 图内不重复论文图题；图题和编号由 LaTeX 管理。
- 多图组合的面板小标题位于各面板下方；不得把标题写进流程画布或数据区域。

## TikZ 实现

使用 [../assets/tikz/cumcm-diagram-styles.tex](../assets/tikz/cumcm-diagram-styles.tex) 或等价的显式样式表。

- 使用 `positioning`、`calc`、`arrows.meta`、`shapes.geometric`、`angles` 和 `quotes` 等稳定库。
- 流程箭头统一 `Stealth`，不得混用三角、Latex、Circle 等多个箭头族。
- 同类分支标签统一放在离开判断节点后的第一段连线附近；字体、字号和箭头尺寸全图一致。
- 节点通过相对定位、矩阵或计算坐标布置，不用大量无语义的绝对微调。
- 文字换行由 `text width` 控制；不得用 `\resizebox` 把过密图整体缩到不可读。
- 数学几何对象从命名坐标构造，角弧、尺寸线、切点和投影点引用相同坐标，不重复手填近似位置。
- 精细度按“对象—构造—判据—注释”四层绘制：主对象、辅助构造、临界判据、标签分别使用固定线宽和
  z-order；局部接触、切点、投影或角度密集时必须增加解析局部放大，不把全部标注挤在主图。
- 公式和符号必须是同一 TikZ/LaTeX 画布中的原生文本节点，默认 `fill=none,draw=none`；严禁把公式截图、
  白底 PNG、白色矩形文本框或外部粘贴对象覆盖到图上。公式不得遮断主轮廓、轨迹或连接线；位置冲突时
  移到几何空白区并用短引线锚定，或拆成独立公式带，但公式带也保持透明背景。
- 每幅核心几何图至少检查：切点/垂足解析误差、角弧端点、尺寸投影线、标签锚点、对象间最小间距、
  主图与局部放大的一致性。仅画“几条线+几个字”不能作为高精细机理图放行。
- 局部放大统一使用 MCP 的 `detail_inset` 结构：source ROI 与 inset 由同一 spec 和同一命名对象生成，
  以两条克制引线建立对应关系；inset 内重算并放大对象，不允许把主图局部截图后拉伸。至少呈现一个
  主图难以直接读出的几何判据（切向/法向、垂足、接触间隙、角弧或边界），否则不应设置放大窗。
- **GGB 几何源码转换与净化（GGB-TikZ Sanitizer Contract）**：若图元坐标自 GeoGebra (GGB) 导出或由其他绘图软件生成，必须使用 `sanitize_ggb_tikz.py` 或同等规则进行提纯过滤，不得原封不动直接嵌入：
  1. **坐标精度修剪**：所有超过 3 位小数的浮点坐标强制舍入或截断至 **2--3 位有效小数**，减小文件体积与 LaTeX 编译耗时；
  2. **色彩与冗余裁剪净化**：自动剥离 GGB 专有颜色宏（如 `ududff`、`xdxdff`、`uuuuuu`）及无用边界裁剪框 `\clip ... rectangle ...`，统一替换为论文规范样式；
  3. **层级与标绘解耦**：分离几何点标志与标签文本作用域（剥离非必要的 `\begin{scriptsize}`），避免由于默认作用域叠加导致标注文字重叠碰撞。
- 使用 `standalone` 或固定 `tikzpicture` 边界导出；不得依靠 LaTeX `trim/clip` 修正留白。
- 编译日志无 overfull、缺字和字体替代警告；保留 `.tex/.tikz` 与矢量 PDF。

## Visio 实现

- 页面尺寸按论文实际宽度建立，关闭主题渐变和自动配色，启用网格、吸附与连接点。
- 普通步骤使用直角矩形；判断使用标准菱形；起止仅在真实开始/结束语义下使用小圆角矩形。
- 普通框建议高 9--14 mm，宽 26--42 mm；同层节点最多两档宽度。数值只是起始模板，文字与层级优先。
- 所有普通形状关闭填充、只保留轮廓；流程图分组仅使用蓝色虚线外框，不使用色块填充或焦点卡片。
- 轮廓 0.65--0.85 pt，主连接 0.75--0.95 pt，辅助连接 0.45--0.65 pt；箭头大小一致。
- 连接线使用动态连接线并吸附边界连接点；主轴直线/正交，反馈沿画布外缘正交回绕。
- 框内文字必须属于形状自身，水平和垂直居中，四边留 2.5--4 pt 内边距，最多两行。
- 关闭 AutoSize 后重新锁定 `Left/Top/Width/Height`；中文写入或字体替换后再次锁定。
- 保存 `.vsdx`；若使用 draw.io 制作 Visio 风格图，同时保留 `.drawio` 并导出 SVG/PDF，注册表中仍标记 `visio` 风格。

## 流程图

### 结构

- 一图只表示问题关系、分问流程、算法迭代、数值计算或状态决策中的一种。
- 先确定一条两秒内可识别的主轴，主轴通常 5--8 个关键节点；超过时拆图或合并低层步骤。
- 每框只写对象、动作、条件或输入输出中的一个；通常一至两行，不写解释段落和最终数值汇总。
- 判断菱形写可判定条件，每条出边就近标“是/否”或实际条件；反馈必须回到真实更新节点。
- 问题关系图没有条件判断时不用菱形，也不强制开始/结束符号。
- 标准算法没有题目特定修改时不画教科书流程；只画本题的约束修复、筛选、判停或异构复核。

### 构图

- 版型按 [fixed-flowchart-style.md](fixed-flowchart-style.md) 自动路由：短算法链、依赖关系和目标—约束汇合
  优先横向，多层程序条件优先纵向；支路放主轴一侧，避免无意义地左右同时开枝。
- 判断节点前后增加留白；条件文字、箭头尖端和框线保持至少 2.5 pt 成品距离。
- 回路线不贴框、不贴画布边缘、不穿节点；交叉不可避免时重新排版，不使用线桥掩盖复杂度。
- 缩略图先看见主轴、判断和回路，再看见文字；若只能看见密集框或大片说明，必须重构。
- 清楚和辨识度来自信息架构而不是装饰：先冻结一句十秒结论，再用必要主节点形成单一视觉主轴；
  全部普通节点透明填充，判断和否分支不另设异常色。仅真实阶段允许蓝色虚线分组框，禁止阶段徽标、
  渐变、阴影、图标堆叠、彩色卡片和无意义大标题。
- 主轴节点使用动宾短语或“对象→状态”，每框不超过 10--12 个汉字/两行；输入输出或阈值放在连线
  周边的透明小标签中，不用白底贴纸，也不让文字覆盖或截断连线。非主轴分支退后一级线宽和明度，反馈沿外缘形成完整闭环。
- 正式流程图必须同时通过 100% 原尺寸、论文最终宽度和 25% 缩略图三视图；缩略图中主轴、唯一判断、
  回路和最终输出仍不能一眼识别时，判定构图失败，即使连接审计为 PASS 也不得入正文。
- 跨题型固定使用 `visual_preset: cumcm-classic-orthogonal`，并显式记录 `layout_variant`。
  预设冻结白底、标准形状、字体、线宽和正交连接；A 类数值迭代、B 类决策优化和通用证据闭环
  通过各自真实变量、目标—约束结构、条件、阶段与回退实现结构创新，不通过换皮实现差异。

## 数学几何图

### 对象分层

1. 对象层：点、线、圆、曲线、实体轮廓和区域；
2. 构造层：投影、辅助线、法向、切线、延长线和坐标轴；
3. 判据层：角度、距离、半径、视线束、边界和可行域；
4. 标签层：点名、量名和短对象名。

主对象用 0.75--0.95 pt 实线，辅助构造用 0.45--0.6 pt 灰色虚线，关键判据用 0.9--1.1 pt 或唯一强调色。
线型全文保持同一语义。

### 数学一致性

- 图中每个点、角、长度和区域都与正文符号或模型对象对应；不存在只为装饰的字母。
- 角弧端点落在两条真实射线，尺寸线端点落在被量测对象，投影虚线垂直或平行关系由坐标构造。
- 有向轨迹、速度和算法推进显示箭头；轮廓、半径、尺寸和标注引线不误加方向箭头。
- 比例会影响结论时按坐标等比例绘制；示意性非等比例图在图题或正文说明，不制造虚假相等关系。
- 二维投影能解释判据时不用伪三维；必须三维时增加正交投影、截面或局部放大。

### 标签

- 点名距点标记 2--4 pt；角标放在弧外侧；对象名放轮廓外并以短引线锚定。
- 标签不旋转跟随斜线，不压轨迹、圆周、箭头和另一标签。
- 点名、角度、概率、公式、分支和普通标签保持透明背景；外置标签必须有真实对象锚点。标签与线冲突时
  移到线的周边净空区、改线或使用短引线，不使用白底遮罩；任何对象线和辅助线均不得为文字中断。
- 一幅图最多突出一个主要几何判据；场景、局部构造和结果曲线拥挤时拆为两图。

## 文件与审计

每幅图在 `审查/diagram-registry.json` 登记：职责、正文成稿锚点、TikZ 优先选择记录、风格族、源文件、矢量输出、正文宽度、最小成品字号、
关键连接和对应 `claim_id`。同名 `.layout.json` 必须包含 `style_audit`、逐连接、逐线语义和整图审计。

进入正文前运行：

```bash
python .agents/skills/cumcm-diagrams/scripts/audit_diagram_style.py --root .
```

TikZ/Visio 风格、源文件、矢量输出、成品字号或任何连接审计失败时，整图不得进入论文。OCR 只能辅助
识别文字，不能替代端点锚定、箭头方向、分支标签位置和最终页面的矢量复核。
