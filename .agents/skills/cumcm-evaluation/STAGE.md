## 50 篇普查校准

40/50 篇有评价标题，28/50 有改进或推广标题，独立结论章仅 5/50。
坐标切分的 37 篇评价段中：优点 73.0%、局限 81.1%、改进 56.8%、推广 56.8%、
证据信号 83.8%。近似字符量 Q1/中位/Q3 为 306/425/735。

关键发现：局限出现率（81.1%）高于优点（73.0%），说明优秀论文重视失效边界而非自夸；
证据信号（83.8%）是最高命中项，说明优缺点必须连接到已展示的证据而非空泛判断。

## 组织原则

按实际职责决定章节存废，不机械设置固定配额：

- 有两项以上证据化优点与局限时，设置简洁评价节；
- 改进能直接解决已识别局限时再写，不列泛泛未来工作；
- 推广必须说明哪些变量、约束或机制保持，哪些需要重估；
- 各问已充分收束时，不另设重复摘要的结论章。
- 评价阶段不得接管前面缺失的结果解释或验证；若某问尚未说明可信度、敏感性或失效边界，先退回该问补齐。
- 每项改进与一项已写明的局限一一对应；每项推广同时说明保持不变的机制和必须重估的参数、假设或约束。

## 独立结论章决策树

```text
各问结尾是否已给出直接回答且评价章完成收束？
  ├── 是 → 不设独立结论章（50 篇中 45/50 选择此路径）
  └── 否 → 是否存在跨问综合发现且未在验证章覆盖？
            ├── 是 → 设简洁结论节（≤ 半页），只写综合发现
            └── 否 → 合并至评价章末尾一段
```

## 优秀论文规范表达范本与防 AI 味指南（基于 50 篇语料）

在 50 篇优秀论文中，评价章节局限出现率（81.1%）高于优点（73.0%），说明优秀论文极度看重“诚实的失效边界”。严禁写成万能赞美词与假大空推广。

### 规范写作纪律

1. **缺点比优点更具体**：缺点必须指明“触发条件 + 受影响的变量 + 估计误差量级”。
2. **拒绝万能套话**：严禁出现“具有广阔的应用前景”、“为相关研究奠定了基础”、“有待进一步完善”。
3. **取消独立无物结论章**：除非有跨问重大综合新发现，否则不单设重复摘要的“结论”一章（50 篇中 45 篇未设独立结论章）。

## 优点写作：证据链模式

每项优点必须形成三环链条，不得只写"模型简单、准确、实用性强"：

**结构/方法 → 已展示证据 → 带来的可靠性**

示例模式：
- "本文采用[守恒关系/微分方程/整数规划]建立模型，在[验证X]中[误差不超过Y%/收敛至Z]，
  因此在[适用条件]下结果可信。"
- "通过[独立数值方法/交叉验证]验证，主模型与替代路线的偏差为[具体数值]，
  表明[结论]不依赖于[特定算法/离散精度]。"

**禁止模式**：
- "模型具有较强的适应性"——不说明适应什么条件
- "算法效率较高"——不给出时间或迭代次数
- "结果令人满意"——不给出满意的判据

## 局限写作：失效条件模式

每项局限必须形成三环链条，不得只写"模型存在一定局限性"：

**触发条件 → 受影响结论 → 当前证据范围**

示例模式：
- "当[参数超出X范围/数据量低于Y/非线性程度超过Z]时，
  [某假设]不再成立，[受影响的结论]的误差可能达到[量级估计]。
  当前证据仅覆盖[题目给定范围/实验条件]。"
- "本模型假设[条件]，在[什么情形]下该假设不成立，
  将导致[哪个输出]偏离真实值；敏感性分析显示该偏离在[范围]内可控。"

**禁止模式**：
- "模型有待进一步完善"——不说明哪里需要完善
- "未考虑所有因素"——不说明哪些因素和影响多大
- "假设可能与实际有偏差"——不指出哪个假设和何种偏差

## 改进写作：可操作链条

每项改进必须对准一项已识别局限，不得列泛泛未来工作清单：

**薄弱环节 → 新增信息或方法 → 预期可验证变化**

示例模式：
- "针对[局限X]，若获取[更细粒度数据/更长时间序列/真实参数]，
  可将[某近似]替换为[更精确处理]，预期[可量化改善]。"
- "当前[搜索范围/离散精度]受到[计算时间/数据量]限制，
  使用[并行计算/自适应网格]可将[范围/精度]提升至[水平]。"

**禁止模式**：
- "可以考虑引入机器学习方法"——不说明解决什么问题
- "可以进一步提高精度"——不说明如何提高和提高到什么程度
- "未来可以扩展到更复杂情形"——不指出具体情形和所需改变

## 推广写作：条件映射

推广不是"本模型适用于更广泛场景"的空话，必须明确回答两个问题：

1. **保持不变的机制**：哪些变量、约束、方程或数据结构在新场景中仍然适用？
2. **需要重估的部件**：哪些参数需要重新标定？哪些假设需要修改？哪些约束需要增减？

示例模式：
- "本模型的[核心微分方程/目标函数结构]适用于[类似系统]，
  但[阻尼系数/边界条件]需根据[新场景特征]重新标定；
  若[某假设]不再成立，需引入[替代处理]。"

## 禁写

- "模型简单、准确、实用性强"等无证据套话；
- 与摘要相同的逐问结论复述；
- "具有广阔应用前景""有待进一步研究"等空泛收尾；
- 未实现方法的长清单或把理想条件包装成优势；
- 写作、附件、代码、AI 或审查过程。

## 门禁

写 `gates/evaluation.json`。若独立章节被省略，记录合并位置和"无新增职责"的判断；若保留，检查：
- 每项优点有"结构/方法→证据→可靠性"三环；
- 每项局限有"触发条件→受影响结论→证据范围"三环；
- 每项改进对应一项已识别局限；
- 推广有"保持机制→重估部件"映射；
- 不存在无证据的空泛评价。
