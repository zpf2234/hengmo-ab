# CUMCM 去 AI 味（语料正样本对照）

与项目内 [语言审计阶段](../cumcm-language-audit/STAGE.md) 分工：后者扫"不能出现什么"（生产痕迹、硬禁表达、
元叙事）；本技能做"应该像什么"——把论文稿
每一部分与优秀论文同部分原文对照，学习人写表达的节奏与密度，定位并改写 AI 味段落。
执行顺序：正文各部分成稿后先过本技能，再交语言审计阶段做硬禁扫描。
全文首次交付前必须完成本技能，不能等初稿已交付才补检查。语义审查如由 AI 执行，应如实记录
审查者类型，不把它写成参赛队已人工核验；本技能的自然表达判定不提供 AIGC 比例或方法独占承诺。

正式竞赛项目同时读取 [CUMCM 2026 知识库快照](../cumcm/references/current-knowledge-2026-09.md) 和
[官方规则摘要](../cumcm-paper/references/official-rules.md)。去 AI 味不能把事实审计替换成风格改写：
若竞赛期间使用过 AI，正文参考文献前必须放官方“AI工具使用声明”，支撑材料按规定提供
`AI工具使用详情.pdf`，并逐项人工核验 AI 参与内容。项目使用 Codex 或其他 AI 完成求解、代码、图表或写作时，
不得填写“未使用 AI”；官方页面没有规定 AI 工具一律不得列入参考文献，实际引用仍按普通资料引用规则处理。

始终先读 [references/authentic-expression-standard.md](references/authentic-expression-standard.md)。需要逐段改写时再读
[references/a053-narrative-grammar.md](references/a053-narrative-grammar.md)、
[references/corpus-voice-profile.md](references/corpus-voice-profile.md)、
[references/engineering-narrative-counterexamples.md](references/engineering-narrative-counterexamples.md) 与
[../cumcm/references/corpus-alignment.md](../cumcm/references/corpus-alignment.md)；
一手语料读取遵守后者的隔离边界（求解与盲测期禁读同题材料）与长句重合复核规则（连续 15 字
一致优先核对来源与必要性，不机械改动标准术语）。语料目录缺失时跳过一手对照，只执行声纹量化审计与画像自查，
并在门禁记录 `corpus_alignment: "skipped_no_corpus"`。

## 表达真实性底线

- 去 AI 味只改变句法、衔接、段落组织和无信息修饰，不改变任何事实层内容；
- 不把正常的精确数值改得“不规则”，不隐藏有效统计结果，不删去有独立职责的验证；
- 不为显得像学生而编造试错、犹豫、时间不足、赶工或排版瑕疵；真实试错通常留在内部记录，
  只有它解释最终方法选择或适用边界时才进入正文；
- 不设置“我们”占比、每问页数比、方法数、图表数或瑕疵数量等伪自然配额；结构轻重由实际论证负担决定；
- 自动脚本只能定位待复核表达，不能给出 AI 概率、作者身份或学术不端结论。
- 建模视角、模型结构、算法改进和必要的模型组合均可如实呈现；按
  [创新与组合规则](../cumcm-model-tournament/references/innovation-and-composition.md)
  区分贡献与无职责堆叠。不得因方法名多、采用智能算法或存在对照表而自动删改；保留支持
  贡献的数学关系、消融和性能证据，具体说明改了什么、为何有效，避免只写“改进、融合”。

## 逐部分对照流程

对摘要、问题重述、问题分析、模型假设、建模求解、结果验证、评价推广逐部分执行：

1. 以 A053 的参赛者口吻和叙事闭合为主锚，再按题材从 B078、B047、B035、A212、B477、
   B050 中选 2 篇跨题材支撑样本；同对象或同模型论文只能在独立建模冻结后读取，且不得作为
   词句来源；
2. 从 `corpus-alignment.md` 路由表定位对应章节原文（摘要另读
   `摘要普查/all_paper_abstracts.md`），通读主锚和支撑样本的同一部分；
3. 现场回答五个问题并记入工作笔记：段首由谁作主语、句内动作怎样排序、公式前后怎样承接、
   一段形成什么局部闭合、该问为什么应当写长或写短；
4. 拿论文稿逐段对照 [references/a053-narrative-grammar.md](references/a053-narrative-grammar.md)
   的正样本约束、[references/corpus-voice-profile.md](references/corpus-voice-profile.md) 的语料画像与
   [references/engineering-narrative-counterexamples.md](references/engineering-narrative-counterexamples.md)
   的反向样本，标记宣布式起句、主语单一、动作名词堆叠、公式后空转、等长段落、验证配额化和
   工程项目叙事；不能只换词或换版式而保留原段落骨架；
5. 改写命中段落：从对象、条件、公式或本队有证据的真实动作重新起句，恢复局部论证链，不改事实
   （见下方事实保护）；
6. 改写前将原稿冻结为基线，改写后运行真实性表达审计；事实改变回退核对；保留值的重复次数减少进入有记录的去重复核；
7. 运行声纹量化审计和语言审计复查，定位统计异常后逐段完成人工叙事复核，不为阈值刻意调整句长或连接词。

人工复核必须区分“建模证据链”与“审计说明链”。正文参照 A053 直接展开题面对象、数学关系、公式/算法、
数值结果和必要的局部检验；对原稿、重构、口径、闭合、门禁、证据边界和模型链的说明留在审查文件。
局限或适用条件只在它确实改变结论时保留，且同一事项不在摘要、分析、问尾、验证和汇总表中重复。

### 问题分析专项复核

问题分析最容易把内容职责误写成生成模板。逐问先找出一个真正决定路线的事实——本题对象的
作用关系、目标与约束的冲突、几何边界、数据异常或信息缺口——并从它起句；再写这一事实怎样
转化为可计算对象以及为何需要当前路线。不得把“特征判断—分析思路—求解过程—输出衔接”复制
成固定四段，不跨问复用“为了求解……采用……”或“首先—然后—最后”骨架。

核心问、支撑问和过渡问的长短由真实转化负担决定，不设 150 字上限，也不把“思考克制”解释为
固定一段。图示同样不是复杂度配额：只有分支、反馈或对象传递难以用短文、公式和表格清楚表达，
且图确有信息增益时才使用；使用后必须与公式、指标及实际求解过程一致。

## 声纹量化审计

```bash
python .agents/skills/cumcm-deai/scripts/audit_corpus_voice.py --root .
```

指标与阈值锚定 50 篇摘要语料实测分布（详见画像文件"量化基线"节）：

- 段首同构对（6 字相同前缀的段落对）：语料 47/50 篇为 0，≥4 对优先人工复核，≥1 对人工复核；
- 句长变异系数：语料最低 0.302，<0.25 优先人工复核（句数不足 8 句不判），<0.30 人工复核；
- 模板连接词密度：语料中位 3.7/千字、P90 11.4、最高 18.0，>18 优先人工复核，>11.5 人工复核。
  优秀论文本来就用"首先/其次/最后"，治理对象是密度失控，不是词本身；
- 摘要数值密度：语料 P10 为 5.3/千字，摘要低于 5.5 记人工复核（对应摘要雷点
  "零数字摘要"）；
- 句内逗号链 P90 >12 记人工复核（"一逗到底"）。
- 问题分析专项：跨问重复“为了……采用……”、两问以上复制“首先—然后/其次—最后”或直接出现
  四职责标签记人工复核；问题编号归一化后的同构开头、三问以上近乎等长记人工复核。专项判定只抓
  跨问模板，不禁止技术上确有必要的一次顺序说明。

审计输出 `审查/section-chain/corpus-voice-audit.json` 与同名 `.md`。判定阈值使用固化
基线快照，不随语料文件变动漂移；语料存在时另行重算基线写入报告供人工参考
（`baseline_source: corpus`），缺失时报告标注 `builtin`。无可扫描正文时按失败处理。

## 真实性表达审计

逐段改写前保留一份未改写基线，例如 `审查/deai-baseline/论文.tex`，然后运行：

```bash
python .agents/skills/cumcm-deai/scripts/audit_authentic_expression.py \
  论文/论文.tex \
  --baseline 审查/deai-baseline/论文.tex \
  --output 审查/section-chain/authentic-expression-audit.json
```

脚本比较数值、公式和引用；数值改动、事实全部消失或公式变化判完整性失败，保留值的重复次数减少转人工核对，不能自动放行；同时把内部工程词、未经证据
支持的过程叙述、同问方法堆叠、重复段首和异常均匀的逐问篇幅列为人工复核信号。复核信号不等于
AI 证据：逐条确认其是否服务于当前论证，必要时改写表达，不得为了让报告变绿而改动事实或伪造经历。

## 事实保护

数字相同不等于事实相同。逐项核对来源、数值归属、假设、适用条件和结论强度；重点检查经验
阈值变仪器参数、一次回收变无偏证明、局部结果变全局认证。程序只定位部分术语和变化，
未命中也不能免除语义复核。去重记录被删位置、保留位置与未损失的结论；确属事实纠错时
退回验证并记录修订依据，不伪装成纯语言改写。

不得为了去 AI 味改动公式、数值、单位、有效数字、引用、符号或 `claim_id`；改写后先通过
真实性表达审计，再与证据矩阵复核。允许改的只有：句法结构、连接方式、段落节奏、冗余修饰和空泛评价。
优秀论文原句不得进入论文稿；改写以"信息密度与节奏对齐"为目标，不是句式模仿。

符号与模型名称的去同质化必须在 `cumcm-notation` 和模型冻结阶段完成：依据当前题目的对象、
作用机制、索引和单位建立语义符号台账。不得在本技能的语言润色阶段随机替换变量，也不得为了
与其他论文不同而改动标准符号。模型名称优先使用“研究对象 + 主导关系/任务动作”，不添加
“智能、改进、融合、混合”等未被模型结构和验证兑现的修饰词。

## 门禁

写 `gates/deai.json`：逐部分记录主锚与支撑样本（篇目 id 与部分名）、命中的句法或叙事
信号、反向样本检查、改写段落数、基线文件与哈希、真实性表达审计、声纹审计结果及人工复核结论。
只有数值/公式等完整性无未解决失败、来源/条件/结论强度的语义复核完成、表达与声纹复核项均有
处置记录、逐部分对照完成（或语料缺失降级已记录）、证据矩阵复核通过时才 `pass`。若完整性
状态为 `REVIEW`，必须在 `deduplication_review` 记录被删与保留位置、对应结论、审核理由和本次
基线/改稿哈希；语义核对记为 `semantic_fact_review`，不得把脚本退出码 0 当成人工确认。
首次交付前仍须通过全语料全文相似度审计（`benchmark_corpus.py --root . --fail-on-similarity`），
确认对照没有引入文本复用。按
[逐问深度与初稿协议](../cumcm-paper/references/question-depth-and-pagination.md) 绑定当前源稿、PDF、
基线和自动报告，记录真实语义审查者及类型；报告哈希或来源变化后须重审，不能将旧报告重新标成通过。
