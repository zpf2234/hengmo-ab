# A053 式句法与叙事结构约束

本文件约束的是“句子怎样展开、段落怎样推进”，不是复刻某篇论文的词句。正样本以
A053 为主锚，并用跨题材优秀论文校正：B078（决策与动态规划）、B047（力学机理与状态递推）、
B035（几何证明与启发式搜索）、A212（传热机理与数值搜索）、B477（空间几何与路径设计）、
B050（实验数据与回归分析）。A053 决定参赛者口吻与论证节奏，其他论文只补足不同题材的
自然推进方式。

任何原句都不得进入新稿。若当前赛题与某个正样本对象、数据或模型高度相近，只能在独立建模、
变量定义和求解结果冻结后读取该 PDF；冻结前只使用本文件已经抽象出的叙事规则。

## 1. 句子的三种自然起点

正文交替使用三类主语，不让“本文”或“我们”垄断段首。

1. **对象或条件起句**：用真实对象、边界或情形进入论证，如“当水深增大时”“若两轨迹相交”
   “鼓面发生偏转后”。这类句子适合分类讨论、边界处理和机理解释。
2. **数学关系起句**：用“由式”“代入”“联立”“比较”“积分区间”“图中交点”等承接前文，
   句子必须完成一次可检查的数学动作。
3. **参赛者起句**：自然使用“我们取、我们把、我们比较、我们发现、我们分别计算”。“我们”
   后面紧跟本队实际做过的动作，不接“将从多个维度展开深入分析”一类预告。

“本文/本研究/本工作”只在确需指代整篇论文时偶尔出现；“本节将、下文将、接下来我们将”通常
删去。删去后直接写对象、条件或动作。

## 2. 句内动作顺序

一句话只承担一到两个紧邻动作。长句可以存在，但内部关系必须可还原为下列顺序之一：

- 条件或现象 → 数学处理 → 局部结论；
- 对象定义 → 关系式 → 参数含义；
- 数据特征 → 候选函数或模型 → 选择依据；
- 计算结果 → 关键数值 → 对题目答案的影响；
- 近似或误差来源 → 受影响结论 → 适用范围。

避免把“分析、建模、求解、验证、推广”五个动作压进同一句，也不把一句可说清的内容拆成三句
同长度短句。句长随推导难度自然变化。

## 3. 公式、图表和正文的衔接

- 公式前交代它从哪个条件、几何关系或守恒关系得到；不写“下面给出公式”。
- 公式后两句内至少完成一项实质动作：解释结构、指出特殊情形、代入参数、核对量纲、给出数值
  或说明它怎样决定下一步。
- 图表不以“图中展示了”“可视化结果表明”开头。先写可见的变化、拐点、区间或相对位置，再解释
  原因，最后说明它改变了哪个判断。
- 数值不集中到段尾统一报账；它应出现在支持判断的位置，并与单位、比较对象或阈值同时出现。

## 4. 段落的推进骨架

每段围绕一个局部判断展开。可按题材选用下列骨架，不强制每个环节都占一句。
这些骨架服务于建模与求解全文，不得原样搬进前置“问题分析”章；分析章只抽取决定路线的对象、
矛盾、约束、异常和关键转化，顺序随题目结构变化。

### 机理与动力学

研究对象与受力状态 → 必要近似 → 守恒或运动关系 → 状态方程 → 参数求法 → 数值结果 →
物理解释或假设回查。

### 几何与边界

位置关系或可行域 → 分类依据 → 几何构造 → 方程或判定式 → 临界情形 → 搜索或计算 →
前后状态比较。

### 数据与统计

原始数据现象 → 异常或样本限制 → 候选关系 → 参数估计与检验 → 比较淘汰 → 结果解释 →
预测边界。

### 决策与优化

极限情形或局部性质 → 决策变量 → 目标与约束来源 → 基线或小规模试算 → 搜索过程 →
停止条件与边界修复 → 最终方案 → 独立复核。

### 智能、随机或进化算法

先解释为什么解析法、枚举或简单搜索不足，再用 `Step1`--`StepN` 写本题的实际执行过程。
步骤依次覆盖变量编码与初始化、目标或适应度计算、算法特有更新、不可行解修复、停止条件和结果
输出。步骤名必须出现本题变量或状态，不写可移植到任意题目的教科书式算法介绍。简单算法能够
完整解决时，不使用智能算法，也不强凑 Step 格式。

## 5. 整问的叙事闭合

每一问都形成“题目要求 → 本队判断 → 数学处理 → 结果 → 题面回答”的闭合，但篇幅由实质难度
决定。核心问展开模型特有推导、参数来源、求解精度、停止条件、边界处理、结果解释和独立验证；
支撑问保留其必要关系与结果；过渡问只写承担前后连接的内容。不得把各问修成等长、等段数、
同一开头和同一结尾。

一问的结尾不写“完成了该问题的求解”。直接给最终数值、方案、成立条件或失效边界，并与题面
要求逐项对应。

### A053 式证据链不是审计链

正文的推进链是“题面对象或现象 → 数学关系 → 公式或算法 → 数值/构型结果 → 必要的局部检验”。
方法选择的理由只保留会改变方程、参数或结论的部分，不反复解释“为什么这样写”。

“原稿、重构、统一口径、计数闭合、证据边界、整条模型链、门禁、复现包”等语句属于审查或生产过程，
写入审查文件而不进入参赛正文。“不能解释为、不能升格为、不声称、不补造”等防御性句式若确实影响结论，
只在对应结果或模型局限中出现一次，不在摘要、问题分析、每问结尾、验证章和汇总表重复。

结果检验优先放在对应问题后，直接报告复算、对照、扰动或边界情形。除非题目本身需要跨问检验，
不为“总结模型链”单独设置长篇“综合验证与稳健性”。

## 6. GPT/Claude 工程叙事的消解

工程感首先是叙事问题，其次才是词语问题。出现下列表达时，不做机械同义替换，而是回到具体
对象和数学动作重写整句。

| 机器协作或项目管理式写法 | 改写方向 |
|---|---|
| “搭建整体框架/形成闭环/构建工作流” | 直接写先确定什么关系，再求哪个量 |
| “完成数据处理模块并接入求解模块” | 写清采用何种筛选、变换或方程，得到什么输入量 |
| “统一口径、冻结方案、通过门禁” | 写清变量定义、选定理由、误差阈值或判定条件 |
| “端到端、全链路、多维度、体系化” | 删除范围夸饰，列出实际变量、约束或检验 |
| “对结果进行全面深入分析” | 写图表中的具体变化、原因和答案影响 |
| “为后续工作奠定基础/提供支撑” | 直接指出哪一个量将代入下一问的哪一关系 |
| “实现模型的部署、集成、交付、验收” | 若非题目中的真实工程对象，改成计算、比较、求解或验证 |

“接口、模块、状态、生成、迭代”等词在控制、计算机或随机模拟题中可能是专业对象，不能一律删除。
判断标准是：它是否对应题面中的实体、算法中的明确定义或可检查的数学动作；若只是在描述写作、
协作或生产过程，则删除。

## 7. 逐段人工复核

每段成稿后依次问：

1. 删除第一句后，是否发现它只是在宣布接下来要做什么？若是，删掉并从对象或条件起句。
2. 本段每个“我们”后是否紧跟真实动作？若只是姿态表达，改为对象、公式或数据作主语。
3. 公式或图表后是否出现了新的判断，而不是“说明模型有效”？
4. 本段最后一句是否回答了局部问题，还是落在“提供参考、具有意义、奠定基础”上？
5. 这段的长短是否由内容决定，还是为了与相邻段落整齐？后者应拆并重组。

复核通过只说明叙事自然；公式、数值、单位、引用和模型结论仍须按证据矩阵逐项锁定。
