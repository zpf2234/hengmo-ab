[../cumcm/references/model-selection-and-answer-quality.md](../cumcm/references/model-selection-and-answer-quality.md) 与

[../cumcm-paper/references/question-depth-and-pagination.md](../cumcm-paper/references/question-depth-and-pagination.md)。
使用 [../cumcm-paper/assets/latex-template/论文.tex](../cumcm-paper/assets/latex-template/论文.tex)，
只更新 `论文/论文.tex` 的 `sec:model-solution` 及逐问区域，不创建独立章节 TeX。
只消费 `cumcm-solve` 已冻结的模型、参数和真实求解记录。

## 50 篇语料给出的结构依据

本地普查显示：23/50 篇采用分问题一级章，21/50 篇采用总章统领后按问题二级展开；模型建立与
求解分别在 46/50、49/50 篇中可明确定位，29/50 篇对每一问都显式设置模型与求解标题。这些结果
说明模型和求解必须可定位，但不要求每问机械复制同一套标题。

本项目按用户指定固定使用：

```text
五、模型的建立与求解
```

第五部分内部再依据问题关系组织：

- 各问相对独立：二级标题默认只写“问题一”“问题二”；任务名称确能帮助定位时，写成
  “问题一：临界角求解”这类短标题，不重复上级章中的“模型建立与求解”。
- 多问共享坐标系、状态方程或基础关系：先设“基本关系”“统一坐标系”“状态方程”等简短共享标题，
  再按问题展开新增条件与求解。
- 单问内容较短：在问题标题下连续成文，不强制设置三级标题。
- 单问确有两个以上需要分别展示的实质部分：使用“受力分析”“运动方程”“参数辨识”“数值求解”
  这类短小、题内可识别的标题。标题只命名正文已经存在的内容，不把参数来源、精度、验证、边界等
  审查职责全部塞进标题。

按 [逐问题意理解与建模入口](../cumcm/references/per-question-understanding.md)，每问标题后必须
先写一段开头概述，再进入下级小节、公式或算法：交代本问任务、决定性条件或关系及实际求解主线，
让评委先理解后续展开。后面的定义、推导与求解须兑现概述；不能把概述移入首个实质小节。
概述不统一句式、句数或字数，不另设“题目理解”标题，不复制第二章分析；简单继承问也保留短段，
说明新增任务与继承量。标题用于展示和定位，正文负责解释。审计、门禁、口径、证据链、
闭环、工作流、误差预算和交付说明只写入正文相应论证或内部文件，不得包装成小标题。

### 小标题命名纪律

- 优先使用本学科自然采用的短名词或短动宾短语，一般 4--10 个汉字；超过 14 个汉字先压缩。
- 一个标题只点出一个中心，不使用“对象 + 方法 + 条件 + 结果 + 验证”的满载结构。
- 不追求各问标题对称，不为每问复制同样数量、同样语法的小标题。
- “问题一：对象与核心动作”“核心关系与模型建立”“参数来源与数值求解”“结果验证与适用边界”
  只能作为反例，不能进入成稿。
- 允许“受力分析”“目标函数”“约束条件”“求解结果”“误差分析”等朴素标题；只要正文内容明确，
  不必为了显得独特而扩写成长标题。
- 标题定稿时通读目录：只看标题即可辨认主要内容即可，不要求目录承担完整论证、审计或作答说明。

模型成文不能在“得到数值”处停止。每问的模型和求解段必须向 `cumcm-results-validation` 明确交接：
题目要求的输出量、产生该输出的公式或算法位置、参数与精度来源、主要误差机制以及可用的独立复算对象。
结果解释、验证、边界与直接结论随后仍写在同一问题区域内，不另起空泛全文结果章。

### 规范写作纪律与表达克制

1. **精选最正确的模型与假设**：在求解竞技后，正文建模部分**直奔主题呈现最终精选的最正确模型**。对试算中废弃的其他候选模型或失真假设，不作大篇幅推导。
2. **正文呈现最终取舍与贡献证据**：删除无证据候选和内部试错，说明最终路线及决定性理由。
   完整候选清单和淘汰过程留在内部证据；按
   [创新与组合规则](../cumcm-model-tournament/references/innovation-and-composition.md)，
   保留证明建模视角、模型结构或算法改进所需的对照、消融及误差/耗时结果，不机械禁止比较表。
3. **公式前冒号引出，公式末尾不加标点**（保持标准 LaTeX 编写习惯）。
4. **推导用因果链衔接**：使用“将式(3)代入式(4)得…”、“对上式求关于 $c$ 的一阶导数，令其等于 0：”、“两端取 Fourier 变换可得…”，严禁使用“通过简单的计算”、“显而易见”等轻浮词汇。
5. **彻底清除软件与代码痕迹**：严禁出现 `df.fit()`、`x0=[0,0]`、`gurobi_solver()`、`csv文件`、`第15行代码` 等编程信息。正文只讲数学模型与算法机理。

## 详细模型建立

全文口吻遵守 [论证叙事规范](../cumcm/references/argumentation-patterns.md) 与 A053 主锚，
向评委解释本题判断如何落实为关系与计算。逐问执行
[建模完整性](../cumcm/references/per-question-understanding.md#建模完整性)，从题面每项输出
逆推必需关系和条件，再核对实际计算与最终输出；共享或短写不豁免必要职责。

按题型写清读者复核所需内容：

1. 界定研究对象、变量、状态、目标和约束；
2. 从物理机理、统计结构、几何关系或决策逻辑推出模型；
3. 给出必要的定义域、边界条件、初始条件和参数来源；
4. 展开本题特有的关键推导，省略教材式通用算法介绍；
5. 说明模型假设在何处进入公式或约束；
6. 只有真实候选会改变答案时，才写有证据的模型取舍。

每组核心控制方程必须承担六项责任：①物理定律或数学关系来源；②变量定义域与单位；③初始/边界条件；④近似及适用条件；⑤方程如何产生题目要求的输出；⑥离散或估计误差如何受控。任一责任缺失时不得放行。数值求解还必须区分模型误差、参数误差和数值误差，并说明步长、网格、容差或停止条件对最终有效位的影响；求解器返回 `success` 或单条收敛曲线不能代替精度预算。

优化题明确决策变量、目标函数和全部约束；统计题明确样本、响应、误差结构、估计量与识别条件；
机理题明确守恒、受力、几何和边界；逆问题明确前向模型、观测关系、可识别性和正则约束；
决策与仿真题明确状态、动作、转移、收益或随机机制。

## 具体求解过程

把问题分析中的高层路线在本章落实为可复核的数学与数值步骤。按真实执行顺序说明：

- 输入量如何进入模型，必要的变换、离散或初始化如何完成；
- 参数、状态或决策变量按什么关系求取；
- 算法每一步更新什么量，相邻步骤传递什么对象；
- 搜索范围、约束处理、步长、容差、随机重复或多初值策略；
- 对临界、碰撞、边界优化和能力上限问题，先给出搜索范围覆盖目标点的数学或数据依据，再写具体搜索；
- 判停条件、收敛标准和最终报告精度；
- 前问输出如何作为后问输入或共享参数，并核对继承对象的单位、有效数字和定义口径。

标准算法只说明本题实际使用的部分和题目特定改造，不抄教科书流程。正文说明数学过程，不展示
代码、运行命令、软件界面、文件路径或调试记录。

## 公式与行文

同时遵守 [../cumcm/references/mathematical-writing.md](../cumcm/references/mathematical-writing.md)
和 [../cumcm/references/argumentation-patterns.md](../cumcm/references/argumentation-patterns.md)。

按 [成熟公式与本题推导](../cumcm/references/mathematical-writing.md#成熟公式与本题推导)，成熟
关系沿用惯用写法，说明本题用途与适用条件；本题新增关系从依据分步推出，定义、近似、拟合和
定理推论如实区分，复杂式拆成可理解的中间关系，兼顾完整推导与局部阅读。

- 变量先说含义再给符号，最后定义域和单位；不在公式后才解释。
- 每组公式前用一句话说明"为了什么目的，需要建立什么关系"。
- 一个展示式优先只承担一个主关系；真正的方程组、约束组或分段关系可以合写，但引出语必须说明
  组内关系。互不依赖的定义、目标和结果不得为了显得紧凑塞进同一公式。
- 当核心式同时包含复合变换、长聚合与优化或输出定义时，先定义具有本题语义的中间量，再写主式；
  不用嵌套下标、叠加帽号或花体字母压缩本可分开的概念。
- 按 [简洁符号与下标](../cumcm/references/mathematical-writing.md#简洁符号与下标) 不用复杂下标
  公式；必要索引保持一层短写，时间优先写为自变量，多重角色通过局部说明或中间量表达，简化后
  核对对象对应、定义域和模型关系未变，不能只补解释保留复杂下标。
- 本题特有的关键推导必须展开；标准代入和化简省略但说明依据。不逐行抄教科书也不跳跃过大。
- 边界条件和初始条件与主方程紧邻放置，不藏在段落中间。
- 独立展示公式全部编号，引出句以中文冒号结束，公式末尾不加标点。
- 同一语义组的并列坐标、状态方程或约束可使用左大括号与 `aligned`，普通推导不强行套用。
- 参数注明题面来源、估计方式、标定依据或取值范围；来源不明的参数值不得出现。
- 多参数模型使用参数表（符号—含义—数值—单位—来源），按
  [../cumcm/references/table-design.md](../cumcm/references/table-design.md) 设计。
- 每个核心公式后立即解释主项的结构、方向或约束，以及它怎样产生本问输出或进入下一步；不能只写
  “式中符号见表”。正文应能局部读懂，符号表只作查阅，不作解码器。
- 每个结论性断言在 ±2 段内有数值、图表或公式支持。
- 文字只说明对象、关系和过程，不写"方法先进、效果显著、便于理解"等评价。

逐问公式与结果稳定后，调用 `cumcm-notation` 的全文公式可读性审计。审计没有符号数量配额；检测到的
阅读风险必须通过简化、拆式或补充前后说明消失，确需保留时在处置台账中给出具体理由和正文证据。

## 与其他章节的边界

- 问题分析只保留高层思路和路线，具体推导与求解步骤全部在第五部分展开。
- 本阶段完成模型与求解正文后，由 `cumcm-results-validation` 在相应问题位置补入结果、验证和直接结论；无需另起一个空泛总章。
- 模型优缺点、改进和推广不写入第五部分。

## 严格禁写

- 只有算法名称而没有目标、约束、参数、更新和停止条件；
- 未运行候选、内部失败日志和无法回到求解证据的步骤；
- 代码、脚本、CSV/JSON、文件名、工作表名、运行命令和附录入口；
- “为了满足可计算性”“本文的回答”“计算口径”等元叙事；
- 未经证据支持的“全局最优、唯一解、高精度、鲁棒性强”；
- 为凑篇幅重复算法原理、题面或问题分析内容；
- 为每个公式单设标题或机械复制三级标题。

## 门禁

写入 `审查/section-chain/gates/model-writing.json`，逐问检查：

- `fifth_section_structure`：模型建立与求解位于第五部分，分问或共享模型结构清楚；
- `concise_display_headings`：问题标题与小标题简洁、可展示，不重复上级章名，不含审计或生产措辞，
  未把多个正文职责压成一个长标题；
- `variables_objective_constraints_complete`：对象、变量、目标和约束齐全；
- `question_model_entry_explained`：逐问定位标题后、首个下级小节与公式之前的概述段；任务、关键关系和求解主线清楚，后续推导兑现主线，与第二章一致且无整段重复；
- `semantic_notation_consumed`：变量来自当前题目的符号语义台账，未复用技能示例或同题成稿；
- `assumptions_used`：相关假设在模型中实际调用；
- `derivation_continuous`：关键关系和推导连续；
- `question_model_completeness`：逐问定位任务所需对象、关系、条件/分支、参数/可解性、求解与输出恢复、验证作答；缺项回求解，已有证据但正文跳步回成文；
- `parameters_traceable`：参数来源或估计方式明确；
- `solution_process_reproducible`：具体求解步骤、停止条件和精度可复核；
- `question_handoff_clear`：跨问输入输出衔接准确；
- `search_scope_justified`：适用题型的候选范围有几何、单调性、上下界、必要条件或全域粗扫依据；
- `inherited_objects_consistent`：前问输出的来源、单位、精度和口径在后问使用前已复核；
- `one_formula_one_primary_relation`：公式按定义、机理、目标或约束职责组织，合写关系具有真实组语义；
- `semantic_intermediates_used`：复合关系已用可读中间量拆解，没有以符号嵌套代替推理；
- `formula_exposition_closed`：核心式前有对象或目的，式后有结构解释与后续用途，局部阅读无需反复查表；
- `formula_origin_and_readability`：成熟公式来源与适用条件准确，本题新增关系有推导或验证依据；关系性质未混淆，关键步骤与项的用途在局部上下文可读；
- `formula_readability_audit_pass`：全文公式风险已简化或有可核验保留理由，未处置项为零；
- `no_open_evaluation_or_irrelevant_text`：没有开放性评价和无关内容；
- `no_production_trace`：没有代码、文件和调试过程痕迹。
